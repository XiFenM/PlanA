## 1. 近期主目标：AI Framework Eng. `87545`

- **地点**：上海
- **层级信号**：官方描述为 early-career software engineer，没有写明必须具备 5 年以上经验
- **官方页面**：[AMD Careers — 87545](https://careers.amd.com/careers-home/jobs/87545?lang=en-us)

### 工作重点

- 为 LLM 与多模态模型构建高性能软件组件，覆盖多 GPU 执行。
- 优化 PyTorch、vLLM、SGLang，并将改进带回上游。
- 围绕 Attention、跨模态融合、KV Cache、量化和投机解码做模型感知实现。
- 使用 profiling 判断计算、内存和通信瓶颈，关注吞吐、延迟和扩展性。
- 与 GPU 库、编译器和开源维护者协作。

### 门槛与加分项

- 必需侧强调 Python、Linux、LLM/多模态理论、生产代码意识，以及在多 GPU/多节点环境中定位计算、内存和通信瓶颈的端到端性能工程。
- C++ 或异步编程、HIP/CUDA/ASM、CK/CUTLASS/Triton、LLVM/ROCm、公开开源贡献均是显著加分项。

### 对当前准备的意义

这是与现有“国产非 CUDA 加速器 + vLLM/PyTorch + 多模态 + 跨层排障”经历重合度最高的官方样本。短期不应因为尚无 ROCm 实操而停止投递，但投递前必须：

1. 收紧简历中未经证据支持的“深入理解/掌握”表述。
2. 能脱稿讲清 vLLM 当前请求主链和一个多模态优化案例。
3. 给出一个可复算的性能案例，而不只给提升百分比。
4. 明确现有自研芯片经验如何迁移到 ROCm，以及哪些仍待验证。

## 2. 进阶目标：AI Framework Eng. `78999`

- **地点**：上海
- **经验信号**：3 年以上技术软件开发经验
- **官方页面**：[AMD Careers — 78999](https://careers.amd.com/careers-home/jobs/78999?lang=en-us)

### 工作重点

- 在 AMD GPU 上优化 PyTorch、TensorFlow、模型、GPU Kernel 和完整深度学习流水线。
- 覆盖训练与推理、单机多卡与多机系统。
- 与 GPU 库和开源维护者协作，使用编译技术改进性能。
- 与开源维护者协作并推动代码进入上游，属于核心工作职责。

### 门槛与加分项

- Linux 环境中的 C++ 是核心能力信号。
- GPU Kernel 开发与调优、训练/推理框架优化和多 GPU/多节点工作属于核心职责。
- 3 年以上技术软件开发经验，以及 Linux C++ 能力，是明确资格信号。
- HIP、CUDA、ASM、CK、CUTLASS、Triton、LLVM、ROCm 和异构集群位于优先经验部分，不应把每一项都解释为统一硬筛选条件；上游集成则是上述核心职责之一。

### 对当前准备的意义

工作年限与现有经历基本相邻，但证据结构还不完整。优先补齐：

- C++ 系统基础和现场编码；
- 一个独立负责的 custom op/Kernel 或 Kernel 集成证据；
- Roofline 与 profiler counter 的定量归因；
- ROCm/HIP/RCCL 迁移矩阵和最小运行证据；
- 一个公开可评审的上游工件。

- **地点**：上海
- **经验与学历信号**：官方写明 5 年以上专业经验，并列 Master/PhD；当前约 3 年多经历存在明确年限筛选风险
- **官方页面**：[AMD Careers — 89398](https://careers.amd.com/talent-network/jobs/89398?lang=en-us)

该岗位把分布式推理中的 PD 分离、Large-EP 与强化学习列为端到端重点，同时要求 vLLM/SGLang、Python/C++、HPC、LLVM/ROCm 和上游协作。它比 `87545` 更贴近本地 MORI 复合 JD，也更依赖大规模分布式和硬件栈证据。

建议把它作为专项拉伸岗位：MoE EP、PD/KV、通信量推导和 C++ 补强可以缩小技术差距，但八周计划不能消除 5 年以上经验的筛选风险。

## 4. 拉伸标杆：Senior AI Performance Engineer `88008`

- **地点**：Helsinki / Stockholm
- **经验信号**：5 年以上 GPU computing、AI systems 或 HPC
- **官方页面**：[AMD Careers — 88008](https://careers.amd.com/careers-home/jobs/88008)

### 能力上限

- 深入掌握 vLLM V1、scheduler、PagedAttention/KV manager、Chunked Prefill 和 ROCm backend。
- 从用户请求追到 Kernel，使用 occupancy、register、LDS、cache、memory coalescing 和 wavefront 等一阶指标定位瓶颈。
- 集成 Triton、Gluon、CK、PyDSL、ASM、AITER 等 Kernel。
- 优化 TP/PP/EP/DP、多机通信、RCCL/RDMA 与通信计算重叠。
- 在客户场景中交付可测提升，并形成可复用方法和上游贡献。

当前可迁移强项是跨层排障和客户交付；明显缺口是 ROCm、Kernel 一阶分析、当前 vLLM 架构、C++、大规模分布式和上游所有权。该岗位适合作为中长期能力标杆；是否达到以这些验收门槛为准，不按日历时间承诺。

## 9. AMD 岗位共同结论

不同职级反复出现的共同要求是：

1. 框架主链和模型架构必须落实到代码与状态，而不是术语熟悉。
2. 性能结论必须由 workload、profile、理论模型和正确性回归共同支持。
3. Python 是入口，C++、Kernel、runtime 和编译器决定更高职级上限。
4. 多 GPU 不能只会调用 collective，要能说明拓扑、切分、通信量与重叠。
5. 自研加速器经验可以迁移，但 ROCm/HIP/RCCL 的直接证据必须单列。
6. 上游协作是稳定要求，内部 CI 和跟随上游升级不能完全替代公开贡献。
