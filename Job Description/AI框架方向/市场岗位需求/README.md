# AI 框架岗位需求索引

> - 整理日期：2026-08-29
> - 信息来源：企业官方招聘网站；链接与在招状态可能随时变化
> - 用途：为 AMD AI 框架方向的能力诊断、学习规划和投递分层提供可追溯的市场基线

## 1. 使用方式

本目录不再把多个岗位描述拼成一份“万能 JD”，而是保留岗位层级、工作地点和能力重心。每张岗位卡只做结构化转述，完整要求以官方页面为准。

当前准备顺序是：

1. 以 AMD 上海 `87545` 为近期主目标。
2. 以 AMD 上海 `78999` 为进阶目标。
3. 以当前 AMD `88008`、`81040`、`80979` 与本地 MORI 复合 JD 为不同技术支线的拉伸标杆；`89398` 单列为有 5 年以上经验门槛的分布式推理专项拉伸。
4. 训练岗位只用于定义“推理优先、训练兼顾”所需的最低系统素养，不按 Principal 标准准备。
5. NVIDIA、AWS Neuron 和 Google 岗位用于检查 AMD 之外的共同要求，避免计划过度绑定某个内部项目名。

## 2. 岗位分层

| 层级 | 代表岗位 | 当前用途 | 主要门槛 |
|---|---|---|---|
| A：近期主投 | AMD AI Framework Eng. `87545`，上海 | 直接校准简历和近期面试 | Python、LLM/多模态、PyTorch/vLLM/SGLang，以及多 GPU/多节点上的计算、内存、通信瓶颈诊断；C++、Kernel、ROCm、开源是加分项 |
| B：进阶主投 | AMD AI Framework Eng. `78999`，上海 | 完成 P0 与关键 P1 补强后重点投递 | 3 年以上开发、Linux C++、PyTorch/TensorFlow、GPU Kernel、多卡/多机、上游协作 |
| C：专项拉伸 | AMD AI Software Engineer `89398`，上海 | 技术主题相邻，但官方写明 5 年以上经验；八周只能缩小技术差距，不能关闭年限筛选风险 | Large-EP、PD 分离、分布式推理、C++/Python、ROCm/LLVM |
| D：当前拉伸标杆 | AMD `88008`、`81040`、`80979` 与本地 MORI 复合 JD | 分别定义 vLLM 性能、Kernel、端到端性能和网络专项上限 | 岗位族并集：vLLM V1、Kernel 一阶分析、TP/PP/EP/DP、RCCL/RDMA、ROCm、上游所有权；单个岗位只取对应支线 |
| E：训练参照 | AMD `78259`、NVIDIA `JR2005687` | 定义训练系统最低知识面和长期上限 | Autograd、DDP/FSDP/ZeRO、模型并行、混合精度、内存与通信重叠、训练性能回归 |
| F：历史架构参照 | AMD `76255` | 页面已失效，仅保留历史框架/runtime 画像 | 生产级分布式 runtime、vLLM/SGLang/llm-d、KV/调度、RCCL/RDMA |

“主投”只表示准备优先级，不表示一定满足招聘筛选、地域、职级或其他条件。“主要门槛”按每行岗位族概括；尤其 D 层列的是多条专项支线的并集，不表示每个岗位同时要求全部能力。

### 2.1 岗位族视图

投递优先级和技术支线是两个维度，不能把所有岗位排成一条单向职级梯子：

| 岗位族 | 当前样本 | 用途 |
|---|---|---|
| 框架与模型集成 | `87545`、`78999` | 近期主线 |
| 分布式推理与 RL | `89398` | EP/PD 专项拉伸；另有 5 年以上经验筛选风险 |
| vLLM 性能 | `88008` | 当前拉伸性能标杆 |
| GPU Kernel | `81040` | Kernel 专项标杆 |
| 端到端推理性能 | `80979` | Principal 级长期标杆 |
| PyTorch 训练框架 | `78259` | 训练能力上限 |
| 框架/runtime 架构 | `76255` | 历史样本，页面已失效 |

## 3. 跨公司共同能力模型

| 能力簇 | 市场共同要求 | 对当前准备的含义 |
|---|---|---|
| 推理框架主链 | vLLM/SGLang 的请求生命周期、scheduler、model execution、KV Cache、batching | 必须能从 API 请求讲到 backend/kernel，并映射固定版本源码 |
| 模型感知 | Attention、MoE、量化、KV、投机解码、多模态 | 不能只背算法，要能解释 shape、状态、内存和系统代价 |
| 性能工程 | 端到端 profiling、microbenchmark、吞吐/TTFT/TPOT/尾延迟、回归门禁 | 每个优化案例都要有绝对基线、工作负载、正确性契约和单变量归因 |
| 系统与 Kernel | Python 与 C++，GPU Kernel，异步/并发、内存层次、编译与 runtime | 需要一个可运行或可审查的混合栈证据，不能只依赖跨团队协作叙事 |
| 分布式推理 | TP/PP/EP/DP、collective、拓扑、多机 KV、通信计算重叠 | 要能手推 tensor shape、通信字节数和性能下限 |
| 加速器迁移 | CUDA 之外的后端接入、ROCm/HIP/RCCL 或 AWS Neuron | 现有国产芯片经验是强迁移基础，但不能直接等价为 ROCm 实操 |
| 工程质量 | 测试、CI、正确性与性能回归、可维护设计 | 将已有排障方法沉淀为公开 reproducer、test design 或 patch |
| 上游协作 | issue、设计讨论、PR、review、benchmark | 高级开源框架岗位的高频强信号；“跟随上游升级”不等于“上游贡献”，本轮至少形成一个可评审公开工件 |
| 跨团队交付 | 与模型、Kernel、编译器、runtime、客户团队协作 | 保留优势，同时明确个人负责、参与和他人负责的边界 |
| 训练系统素养 | PyTorch 训练主链、DDP/FSDP/ZeRO、模型并行和混合精度 | 本轮做到能推导、能选择、能解释故障，不追求训练 Principal 深度 |

## 4. 对本地复合 JD 的处理

[高级 AI 框架开发工程师原文](../高级AI框架开发工程师.md)包含两段明显不同的职位画像：

- 一段聚焦 MORI、GPU Direct RDMA、MoE EP、PD 分离和分层 KV 存储；
- 一段聚焦通用高级推理、Kernel、编译器、分布式系统和开源领导力。

截至 2026-08-29，没有在 AMD 官方招聘页中确认到与前一段完全一致的单一在招岗位。因此，它继续作为“高难度专项能力标杆”，不作为唯一市场事实，也不用于推断当前岗位一定要求 MORI 的每一个组件。

- 新岗位必须记录公司、岗位名、地点、Job ID、访问日期和官方 URL。
- 官方页面失效后保留岗位卡，但标记“页面已失效/待复核”，不把搜索摘要当作永久事实。
- 不复制完整岗位原文，只保留与能力判断直接相关的摘要。
- 旧目录中的历史 JD 不移动、不删除；本目录作为 2026-08-29 起的分类入口。
