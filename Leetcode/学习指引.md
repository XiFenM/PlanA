# Leetcode 学习指引（20 周全程并行子轨道）

## 0. 入场点

- **为什么学 + 校准**：你 5 年工作经验，算法基础扎实但**近几年没系统刷 LC**——这 20 周不是"重学算法"，是 **手感维持 + 公司分布覆盖 + 系统/并发专项**。面试 vLLM/SGLang/Megatron/NV DevTech/自研芯片组，**算法侧通常只 1-2 道 medium**，但会加**并发/多线程/手撕 CUDA kernel** 额外轮次——题型比例与纯前端/后端岗不同（详见 §5）。
- **终点（W20 末必须能做到）**：
    1. 累计 **250 题**（NeetCode 150 骨架 + 60 公司高频 + 25 系统/并发 + 10 GPU + 5 streaming）
    2. **Medium 题 35 分钟内稳定 AC**（不求最优，但要一次写对）
    3. **手撕能力**：CUDA Top-K 堆、线程安全生产者消费者队列、线段树模板能从 0 默写
    4. **系统设计画像**：Meta E5 infra 风格 + Anthropic take-home 风格 + NV HW-SW co-design 风格都准备过至少 1 套答题框架
    5. **SRS 错题本**：错过/卡顿过的题目都落进 LeetSRS / Anki，按 FSRS 自动重查
- **时间预算**：工作日 45 min + 周末 1.5h ≈ **4h / 周 × 20 周 = 80h**（已含在主计划 32.5h/周 预算里）

## 1. 周节奏

### 每日模板（工作日 45 min）

```
00:00–00:15  1 题复习（SRS 队列顶出的题，或 3 天前写过的同题重写一次）
00:15–00:45  1 题新（按当前周题单选）
```

### 周末 batch（1.5h）

```
45 min  —— 6–8 道当前主题快刷（同主题集中 reinforces pattern）
45 min  —— 1 道难题深挑（周末难题题单 / 公司真题 / 系统专项）
```

### 20 周分布（来自 [主计划](../计划/主计划.md) §4，在此细化）

| 周 | 主题 | 题量 | 来源比重 |
| --- | --- | --- | --- |
| W1–W4 | 数组 / 双指针 / 滑窗 / 哈希 / 二分 | 60 | NC150 全刷 + 热门 10 补 |
| W5–W8 | 链表 / 栈 / 队列 / 堆 / 单调栈 | 50 | NC150 + 补公司 tag 高频 10 |

**"主题周"原则**：当周刷题 80% 集中在当周主题，20% 做 SRS 复习。集中练同一模式能加速模式识别。

## 4. 系统/并发/GPU 专项（common_problems 里的三题）

### 4.1 线段树（W11-W12 插入 10 题）

- **高质量模板**：https://github.com/wisdompeak/LeetCode/tree/master/Segment_Tree （307 / 715 详细拆解）
- **LC 必刷 10 题**：
    - **入门**：307 Range Sum Query Mutable（所有线段树模板从这里开始）
    - **区间修改 + lazy tag**：715 Range Module
    - **My Calendar 三连**：729 / 731 / 732
    - **经典难题**：218 The Skyline Problem（线段树/堆/扫描线）
    - **逆序对**：315 Count of Smaller Numbers After Self（线段树/BIT 都可）
    - **区间查询极值**：493 Reverse Pairs
    - **动态插入 + 区间极值**：2407 Longest Increasing Subsequence II
    - **字符区间**：2213 Longest Substring of One Repeating Character
- **产出**：`Leetcode/segment_tree_template.cpp`（Python 或 C++）—— 支持 point update + range query + lazy propagation 的通用模板，以后 10 分钟内能默写

### 4.2 CUDA Top-K 堆（跨到算子板块任务 4）

- **参考实现来源**（⚠️ 主动校准过）：
    - **FasterTransformer** `topK_kernels.cu` —— 🟥 主要参考，**注意仓库已停更**（last release 2023-01），但 kernel 代码仍是 NV 风格权威实现。https://github.com/NVIDIA/FasterTransformer
    - **TensorRT-LLM** sampling kernel —— 🟥 FasterTransformer 的继任者，新代码都在这儿：https://github.com/NVIDIA/TensorRT-LLM
    - **NVIDIA GTC Top-K slides**（Christina Zhang & Yong Wang）—— 🟨 算法概览
    - **anilshanbhag/gpu-topk** —— 🟩 只做对照（**它是 bitonic/radix，不是 heap**，别当作参考）
- **和算子板块任务 4 的关系**：算子板块 W14 任务 4 已经要求你做 block-level radix + warp-level heap 两种对照实现——在 LC 维度这题体现为 "给定 N 个 float，返回 top-K，写 CUDA kernel"，考察时间复杂度分析 + 共享内存使用
- **面试白板答题框架**（5 分钟能讲完）：
    1. K 小时（≤128）：每 warp 维护 k 大小的 min-heap，warp-level reduction 归并
    2. K 中（≤1024）：block-level radix sort + partial extract
    3. K 大（>1024）：split-and-merge 多 kernel 启动
    4. 和 CUB `DeviceRadixSort` 的对比

### 4.3 CUDA 多线程中线程安全的生产者消费者队列

- **参考实现**：
    - **rigtorp/MPMCQueue**（1.5k⭐, Frostbite 生产级, header-only C++11）—— 🟥 主要参考：https://github.com/rigtorp/MPMCQueue
    - **cameron314/concurrentqueue**（lock-free MPMC）—— 🟨：https://github.com/cameron314/concurrentqueue
    - **K-Adam/SafeQueue**（mutex + condvar）—— 🟩 教学起点：https://github.com/K-Adam/SafeQueue
    - **vLLM scheduler（`vllm/core/scheduler.py`）** —— 🟥 **真实生产代码**，给你 "host 侧如何和 CUDA stream 协调" 的实战范本
- **⚠️ 重要校准**：**没有成熟开源的"纯 CUDA device-side"MPMC queue**。生产栈实际做法是：host 侧 C++ MPMC 队列 + `cudaStreamAddCallback` / CUDA event 做 kernel 完成通知。面试讲这题时不要编"device 侧 queue 实现"——讲 host-device 协调更真实
- **面试白板答题**：
    1. 基础版：std::mutex + std::condition_variable + std::queue，讲清 `notify_one` vs `notify_all` 和假唤醒处理
    2. 无锁版：讲 Lamport 单生产者单消费者 ring buffer + `std::atomic` memory order
    3. MPMC lock-free：讲 Michael-Scott queue 思路 + ABA 问题 + hazard pointer
    4. GPU 扩展：host 队列 + CUDA event + stream callback（vLLM 范本）
- **LC 多线程题（W17-W18 共 7 题）**：
    - **1114** Print in Order：最基础 condvar 练习
    - **1115** Print FooBar Alternately
    - **1116** Print Zero Even Odd
    - **1117** Building H2O
    - **1188** Design Bounded Blocking Queue —— ⭐ **生产者消费者原题**
    - **1195** Fizz Buzz Multithreaded
    - **1242** Web Crawler Multithreaded

## 5. 公司面试画像（Agent 搜到的 2025 真面经数据）

### NVIDIA（2 道 LC medium + CUDA 手撕）

- **算法侧**：array / tree / graph 占比高；medium 水平
- **手撕侧**：memory coalescing / kernel fusion / top-k / softmax
- **近年倾向**：HW-SW co-design 题增多，考察"给定硬件特性，算法该怎么改"
- **准备重点**：算子板块 §H 维持轨道 + 本指引 §4.2

### Meta E5 Infra

- **算法侧**：45min × 2 medium，array / string / linked list / tree / graph + BFS/DFS 为主；**DP 在 screening 阶段不重**
- **系统设计**：分布式缓存 / 限流 / pipeline 类题
- **follow-up 坑**：喜欢在 medium 题上加 streaming 变体（→ 需要 heavy-hitters 直觉，W13-W16 streaming 支线就是给这个）

### Anthropic

- **算法侧**："practical" 风格（build-a-bank 渐进题），不是纯 LC 模板题
- **并发**：**跨多轮出现**，所以 §4.3 + LC 多线程 7 题必练
- **take-home**：90 分钟 CodeSignal 或 60 分钟 live；题库极小（~6 题），难度适中但重代码质量/可读性
- **准备重点**：能干净地写一个"多个 worker + 共享状态 + 错误恢复"的 service

### 字节跳动 AI Infra

- **算法侧**：CodeTop 数据显示"无重复字符最长子串"（3）出现 25 次，medium 经典题为主
- **概念题**：transformer / LoRA / embedding 基础概念
- **准备重点**：NC150 medium + 模型理论板块 §J 速查表

### 小初创（Moonshot / DeepSeek / Character.AI / Cerebras）

- **tag 不准**：LC Premium 过滤对它们失效
- **替代**：1p3a / leetcode.cn 面经 + GitHub issue 里的 contributor 背景查
- **共同特点**：偏看作品集 + 真实项目 PR，LC 题只是及格线

## 6. 错题本 + SRS 工作流

1. **当场处理**：每做错或卡 >5 min 的题，立刻 LeetSRS "Add"
2. **卡片格式（3 行内）**：
    ```
    Pattern: sliding window + monotonic deque
    Trap: 缩左指针时要 while 不是 if
    Trigger: 看到 "最大 k 长度窗口 + 某种极值"
    ```
3. **每日 15 min SRS** 从队列顶取题；错了标"Hard"（加快下次复习），对了标"Good"
4. **周末回顾**：每周末花 15 min 看 SRS 统计，识别反复错的 pattern，那是**你的真正弱点**——在 common_problems 里专门挑相关题做 deep drill

## 7. 跳过清单 / 常见坑

- **竞赛级难题**（Codeforces Div.1 / AtCoder AGC）—— 不在面试范围，跳
- **过度优化**：Medium 题不需要写到最优解，35 min AC 一个可行解就走
- **C++ template 黑魔法**：LC 用你最顺手的语言（Python 推荐）；C++ 留给手撕 CUDA kernel
- **付费 AI 辅助工具**（Cracked、Leetcode Wizard 等）—— 风险大、社区抵制，面试平台也开始反制（interviewing.io 2025 已上 AI 检测）
- **大面积刷 hard**：除非目标公司明确偏好（Google L4+），否则不值得
- **盲信"最近一周"面经**：最好以 "最近 2 月聚合" 的高频分布为准
- **用 LC cn 做英文面试准备**：语言习惯和题目表述差距大，最后 4 周要强迫自己用英文题面
