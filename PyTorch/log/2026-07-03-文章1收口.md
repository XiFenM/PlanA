## 学习过程

- [纠错] 场景：复述 `torch.add` 调用链时，我连续两轮说“`requires_grad=true` 所以 Autograd key 最高”。→ 当前限定：路由与“是否记录反向图”是不同判断；实际 keyset、key 顺序和参与层还受 tensor 属性、GradMode、subclass、functionalization、autocast 等因素影响，`requires_grad` 不能单独推出一条固定路由。原因：后续文章复核表明原句把记录条件、dispatch keyset 和版本相关实现压成了一个开关。（来源：文章1 §3.2、§读后回顾 Q4/Q13）
- [纠错] 场景：回答 `native_functions.yaml` 语法（Q9）。我说“`!` 表示原地、`_` 表示修改输入”，后来又把 `(a!)` 简化成“直接让 version counter +1”。→ 当前限定：`_` 是给使用者看的 in-place 命名约定；`Tensor(a!)` 向 codegen 描述 alias 与 mutation。version counter 的维护还涉及生成 wrapper、`ADInplaceOrView` 和 autograd 逻辑，不能归因于 dispatcher 读取一个 `!` 字符。原因：命名、alias/mutation 元数据和运行时版本维护属于不同层。（来源：文章1 §4.2、§读后回顾 Q9）
- [转折] 回顾 `torch.add` 调用链时，我最初试图记住一条固定七步链；文章复核后，理解改为“代表层次用于建模，精确符号与路径必须回到目标 revision”。稳定结论与版本限制见文章1 §3.2、§读后回顾 Q4。
- [转折] Q13 暴露出我曾把算子路由主要按设备区分；复盘后才把问题扩展为多个彼此独立的路由维度。完整维度与适用边界见文章1 §读后回顾 Q13，本记录不重复维护答案清单。
- [纠错] 场景：总结新增算子流程时，我把它说成“只改 `native_functions.yaml`、`derivatives.yaml`，只手写 kernel 和反向两个洞”。→ 当前限定：in-tree yaml 会参与生成接口、schema、redispatch API 和部分注册代码，但开发者仍可能需要 kernel、meta、functionalization 与 autograd 支持；`derivatives.yaml` 只是内置算子提供反向公式的一种方式。out-of-tree 扩展通常使用 `TORCH_LIBRARY`／`TORCH_LIBRARY_IMPL` 与 `torch.library`，不改内部 yaml。原因：所需支持取决于算子类型和扩展方式，不能固定成两个手填位置。（来源：文章1 §4、面试 Q&A）
- [纠错] 场景：我把“yaml 不写 `dispatch:`”概括成“必然是 CompositeImplicitAutograd，前向照常、反向静默错误”。→ 当前限定：在文中讨论的 in-tree 场景，它可能采用 composite 实现，但必须结合完整 yaml 字段与当前 codegen 规则确认；可导 ATen 组合可以由 autograd 记录，裸指针或外部库实现则需要显式 backend/autograd 语义。失败可能表现为无历史、报错、`None` 梯度或更晚暴露，不能预设“前向照常、反向静默错误”。（来源：文章1 §4.2、面试 Q&A）
- [纠错] 场景：我把新后端的 autograd 总结为“前向注册全了，反向白给”。→ 当前限定：只有导数公式已经存在，且公式依赖的 ATen 算子、dtype、layout 与设备语义都被该后端覆盖时，backward 才能复用已有 backend kernel；外部库或融合单体 kernel 还需要显式 autograd 公式，必要时实现专用 backward。原因：注册一个前向 kernel 不等于覆盖反向公式的全部依赖。（来源：文章1 §3、面试 Q&A）
- [高价值问题] PyTorch 有没有现成的"自定义算子 vs 标准算子"自动对拍机制？——本轮可保留的结论是：当前环境变量触发的 CPU 对拍宏是自建的。原记录关于 `__torch_dispatch__` 可作为"影子执行"式通用对拍挂点的判断尚未核验，已转入遗留；核验前不作为稳定结论或制卡事实。（来源：文章1 §读后回顾 Q8）
- [转折] 对拍经验复盘让我意识到：参考实现本身也可能因布局等语义处理不完整而出错，不能只检查被测实现。具体参考路径选择与限制见文章1〔下游透镜·过往经验〕。
- [转折] 过往硬件经验暴露了“所有算子共用一个容差”的假设问题；本轮把判断改为按证据确定误差标准，并停止把单一平台现象外推为通用事实。完整方法见文章1〔下游透镜·过往经验〕。
