# PyTorch Internals 学习指引（2 周地基 / Track A 核心）

## 0. 入场点

- **为什么学**：这是其他所有板块的共用地基。你每天在工作里通过 PrivateUse1 跟 Dispatcher 打交道，但从没读过它的源码，也没自己实现过 allocator——CV 上写的"精通 PyTorch Dispatcher"目前名不副实。两周后你要能：白板画完 `torch.add(a,b)` 从 Python 到 kernel 的完整 dispatch 路径；讲清 caching allocator 怎么管碎片 / `expandable_segments` 做了什么；能独立跑通一个 PrivateUse1 后端 demo。
- **终点（W2 末必须能做到）**：
    1. 白板画 Tensor / Storage / Stride 的三元结构，解释 `view()` 为什么零拷贝、`.contiguous()` 什么时候是免费的
    2. 白板讲 Dispatcher 的 DispatchKeySet 路由机制：Autograd key、fallback key、boxed vs unboxed 的性能差
    3. 白板讲 caching allocator 的 block split/coalesce、`expandable_segments=True` 改了什么、MemPool API 在干嘛
    4. 在本地/工作机上跑起来一个自写的 PrivateUse1 后端，能 dispatch 一个 `my::add` kernel
    5. 能回答 [common_problems.md](../面试准备/common_problems.md) 里："模型运行时的内存碎片问题如何处理"、"为什么 int8/int4 这种低精度数据类型也可以运行模型产生结果"相关的 dispatch/overflow 讨论、以及你工作里"单流→多流"通信改造涉及的 stream semantics
- **你已经会 vs 你不会**（校准）：你日常**在用** `TORCH_LIBRARY_IMPL` 注册算子、**在用** PrivateUse1，但你**不知道**：DispatchKey 的优先级怎么排、fallback 路径在哪、为什么有时候 `autograd` 会兜底到 `CompositeImplicit`、caching allocator 什么时候会触发 OOM 重试、`torch.compile` 生成的 Triton kernel 怎么回到 dispatcher。这份指引以"机制"为主，不花时间复述你已经熟的 API。
- **时间预算**：2 周 × 32.5h − (Leetcode 4h/周 + 杂项 ~2h/周) ≈ **53h**

## 3. 实践任务

### 任务 1 — Tensor Stride 10 题（W1，3h）

- **要求**：自己写 10 道小题，每题 ≤15 行代码，都要能解释 stride / storage_offset / is_contiguous 的变化。样例：
    1. `x.T` 的 stride 是什么？`x.T.contiguous()` 会复制数据吗？
    2. `x[::2]` 的 storage 是否共享？
    3. `x.view(-1)` 和 `x.reshape(-1)` 在 non-contiguous 下的区别
    4. `torch.as_strided` 做一个"假的 2D view"指向同一段数据，会怎样？
    5. 自己构造一个 stride 让两个逻辑位置指向同一物理位置（经典的 shared-memory trick）
    6. `x.permute(1,0,2).contiguous()` 的拷贝成本 vs `x.transpose(0,1).contiguous()`
    7. Broadcasting 下的 stride=0 现象
    8. `x.unfold(0, 3, 1)` 是怎么只靠改 stride 做滑窗的？
    9. `torch.empty_like(x)` 会保留 stride 还是只保留 shape？
    10. 你自研芯片要求 32 字节对齐，一个 stride=[7,1] 的 float16 tensor 会有什么麻烦？
- **产出**：`PyTorch/stride_puzzles.md`（代码 + 答案）

### 任务 2 — 从 Python 追到 kernel（W2 前半，4h）

- **要求**：选 `torch.add(a, b)` 和 `torch.nn.functional.gelu(x)` 两个算子，写出完整调用链：
    - Python `torch.add` → `THPVariable_add` → Dispatcher → 对应 backend 的 kernel
    - 沿途经过的 DispatchKey 顺序（Autograd → Autocast → Tracer → Backend Select → CUDA/CPU/PrivateUse1）
    - 打印证据：在源码里插 `std::cerr`（或用 `torch._C._dispatch_key_set` 之类的 Python API），抓出实际 key 路径
- **产出**：`PyTorch/dispatch_trace.md`（两个算子各一张调用链图）

### 任务 3 — 自写 PrivateUse1 后端 + 注册 `my::add`（W2 后半，8h）

- **要求**：以 OpenReg（资料 10/11）为参考，在一台 CPU 机器上：
    1. 新建一个 extension，设备名 `my_accelerator`
    2. 实现最小的 `PrivateUse1HooksInterface`（allocator、generator 可以是占位）
    3. 用 `TORCH_LIBRARY_IMPL(aten, PrivateUse1, m)` 注册一个 `aten::add` 的假实现（只要能返回 a+b 就行，底下用 CPU 算）
    4. Python 端：`torch.zeros(4).to("my_accelerator:0")` 不崩，`a + b` 能跑
- **不要求**：真的跑在硬件上、性能、autograd 支持
- **产出**：
    - 一份能 build 能跑的 extension（代码放 `PyTorch/my_accelerator/`）
    - 一段 150 字总结："我司现有后端和这个 demo 相比，真正的区别在哪"（为下一步梳理工作代码做准备）

### 任务 4 — Caching Allocator 实验（W1 末，3h）

- **要求**：在 H100 上用一个会出现碎片的 workload（比如反复 allocate/free 不同大小的 tensor）：
    - 跑三次：默认、`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`、`max_split_size_mb=128`
    - 用 `torch.cuda.memory_summary()` 和 `torch.cuda.memory._dump_snapshot()` 对比
- **产出**：`PyTorch/allocator_experiment.md`，包含 3 张 snapshot 对比 + "这跟 vLLM 推理长时间跑完内存爬升的现象怎么对应"的 300 字分析

### 任务 5 — （加分，可放 Track B）为一个简单 op 写 Structured Kernel

- **要求**：参考 `aten/src/ATen/native/native_functions.yaml` 里任一 structured 算子，给一个自造算子写出 meta（形状推导）和 out 版本

### 2025Q4-2026Q1 新题（跟进最新资料）

- ⭐ **PyTorch 2.9 Stable libtorch ABI 扩容具体改了什么？为什么它对外部后端插件是刚需？**（答：新增 `torch::stable::Tensor` 方法 + `accelerator.h` Device Guard/Stream；C++ 插件包不必跟 PyTorch 小版本重编）
- ⭐ **OpenReg 从 2025-03 "PrivateUse1 参考实现"升级到 2025-11 "Accelerator Simulator" 核心变化是什么？**（答：三段式架构：CPU 模拟器 + CI/CD + matching docs；嵌入到 Accelerator Integration Working Group）
- ⭐ **2025-09 新建的整合版 Accelerator Integration Guide 是什么顺序？它和 `PrivateUse1HooksInterface` 是什么关系？**（答：七章线性教程 Device Mgmt → Hooks → Guard → Autoload → Operator Registration → AMP → Profiler Integration；是 "PyTorch 2.10+ 时代怎么接后端"的教科书）
- ⭐ **TorchTPU 和 OpenReg 是什么关系？它为什么不走 Inductor 而走 XLA？**（答：都是 PrivateUse1 范式；TorchTPU Dynamo 捕图后经 XLA → StableHLO，利用 XLA 已有的 TPU 编译栈）
- **PyTorch 2.10 的 DebugMode 底层基于什么机制？对做 dispatcher 的人有什么用？**（答：TorchDispatchMode；可以做数值调试 + 算子 trace，是 dispatcher 理解的实战练手）
- **Issue #166205 指出 PrivateUse1 两大短板是什么？为什么目前还没 accelerator-agnostic 的 graph capture API？**（答：CUDA Graph 深度 CUDA-coupled + Profiler 集成缺乏抽象层；上游在补）
- **Ezyang 在 2026-03 "Autograd and Mutation" 里讲的 CopySlices / lazy rebase 解决什么问题？这对你做后端有什么直接影响？**（答：view + in-place 导致的反向传播梯度错算；PrivateUse1 后端写 `aten::copy_` 时必须尊重 version counter）
- **RFC-0050 Cross-Repo CI Relay 的 L1-L4 分级意味着什么？L4 能给 backend 团队什么决定权？**（答：L4 backend 的 CI fail 可阻塞上游 PR 合入——等于外部 accelerator 团队获得上游门禁权）
