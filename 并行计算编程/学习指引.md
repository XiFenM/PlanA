# 并行计算编程 / GPU 算子学习指引（3 周主线 / Track A 核心）

## 0. 入场点

- **为什么学**：这是你的第三优先方向（vLLM/SGLang kernel 团队、NVIDIA DevTech、Triton/TRT-LLM、各家自研算子组）。**但这不是"学 CUDA 基础"——你已经每天在非 NV 芯片上手写 kernel、做算子融合、针对特定 shape 做优化**，CUDA 基本功和你的工作直觉都不是瓶颈。这 3 周真正要补的是 4 件事：
    1. **Triton 块级编程**——你家芯片没有 Triton 栈，所以一直没用过；它是当前业界除 CUDA 外最重要的 kernel 语言
    2. **FlashAttention-2/3 的数学与 schedule 细节**——你知道它做什么，但没系统推过 online softmax rescaling 和 Hopper warp-specialization producer-consumer pattern
    3. **Nsight Compute + roofline 驱动的系统化 profiling**——你有直觉但没有系统方法
    4. **MFU / bank conflict / top-k 这些 common_problems 高频题的系统化答案**
- **终点（3 周后必须能做到）**：
    1. **白板手写 FA-2 Triton forward 伪码**，能推 online softmax rescaling 公式 + block 切分策略
    2. 能读 Triton `06-fused-attention.py` 并解释每一块 tile 的用意；能独立写一个 fused MLP 或 RMSNorm Triton kernel
    3. 白板讲 FA-3 相对 FA-2 的 Hopper 专属优化（warp-specialized producer/consumer、GEMM-softmax 的 pingpong、FP8 incoherent processing）
    4. 能用 Nsight Compute 报告判断一个 kernel 是 compute-bound / memory-bound / latency-bound，并给出具体 metric 证据
    5. 能独立计算一个 kernel / 训练任务的 MFU，答出 Roofline 上下界推导
    6. 能回答 [common_problems.md](../面试准备/common_problems.md) 里："flash attention 系列优化"、"写 kernel 算子时的难点"、"MFU 计算"、"bank conflict"、"CUDA 编写 top-k 堆排序"、"算子优化有哪些常用手段"（完整版）
    7. **面试 live coding**：白板/coderpad 现场能写出 SGEMM stage 2-3、reduction stage 3-5、scan 单 block 版、transpose with padding、histogram with SMEM —— CUDA 基本功常年维持在面试可战水平（这一条靠 §H 维持轨道支撑）
- **你已经会 vs 你不会**（校准）：
    - ✅ **已熟**：CUDA threads/warps/shared mem/register/global mem 层次、coalescing、stream semantics、算子融合思路、针对 shape 的 kernel 模板化、pingpong、软件流水线（你回答过）
    - ❌ **需补**：Triton 块级编程范式（不同于 SIMT 思路）、FA-2/3 数学证明细节、Hopper 新指令（TMA / wgmma）、系统化 profiling 方法论、CUTLASS/CuTe 布局代数（Track B 定性了解即可）
- **时间预算**：3 周 × 32.5h − (Leetcode 4h/周 + 杂项 ~2h/周) ≈ **79h**
- **2026-04 审计后提示**：因 Blackwell 生态成型 + DSL 大爆发（FA-4 / Helion / CUTLASS 4 CuTeDSL / DeepGEMM Mega MoE 都是 2025Q4-2026Q1 新增），本指引内容 Mandatory 精读项（🟥）合计时间已**超过 79h 约 15h**。取舍建议：优先保 §A（Triton 主线）+ §B §9b（FA-4）+ §E §22b（CuTeDSL）+ §F §25b（DeepGEMM），把 §D §19b (Blackwell TMEM) / §B §9d (IBM Triton 分析) / §C §16a (batch-invariance) 任一条降级到**Track B** 或**每日 15 分钟扫读**节奏消化

- ⭐ **实现 reduction**：Harris 7 阶段分别做了什么？为什么 sequential addressing 比 interleaved 好？unroll last warp 的前提是什么？
- ⭐ **parallel scan**：Blelloch work-efficient 和 Hillis-Steele 各自的 work/step complexity 是什么？多 block scan 的两/三阶段怎么组织？
- **matrix transpose 为什么是 bank conflict 经典题**？padding 和 swizzle 两种解法的差别？
- **histogram 的 atomic 分层策略**：global atomic / SMEM per-block / warp-private，分别在什么场景占优？
- **warp-level primitives**：`__shfl_sync` / `__ballot_sync` / `__any_sync` 各自做什么？用它们实现一个 warp-level reduction 并对比用 SMEM 的版本
- **CUDA Graphs**：什么场景能吃掉 launch overhead？vLLM 为什么用它？用了之后还能怎么进一步优化？
- **occupancy**：高 occupancy 一定更快吗？什么情况下 low occupancy 反而最优？（答到 per-thread register pressure 换 ILP）
