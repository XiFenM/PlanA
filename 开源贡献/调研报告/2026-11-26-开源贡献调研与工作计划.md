## 1. 核心结论与首轮工作计划

先打通 **1 个零租卡破冰单 + 1 个贴紧推理框架/AMD 主线的核心代表作**，不要同时在三四个仓库铺摊子：

1. **第 1 站（最快破冰，纯 CPU，0 租卡成本）**：**`qualcomm/aimet#4138`**（Qwen3-VL SpinQuant 融合 LayerNorm bias 重复计算）。复现条件、误差对比（`0.10 → 1e-7`）和修法都很清晰，全仓 11 个 Open PR 均未触及，一口气同时命中高通官方仓、Qwen3-VL 多模态与量化。
2. **第 2 站（核心代表作，二选一）**：
   - **路线 A（KV Cache / C++ 数据面 / AMD 通信栈）**：在 **`ROCm/mori#1095`**（2026-11-25 刚发布的 UMBP 下一阶段路线图）下认领一项纯 Linux/本地 SSD 的 P1/P2 模块（例如 SSD 重启索引重建或 `#920`/`#770`），或直接修 **`ROCm/rocm-aic#221`**（块对齐前缀缓存分歧）/ **`LMCache/LMCache#6748`**（GPU↔CPU 非标准 KV layout 复用错乱）。
   - **路线 B（多模态推理服务 + AMD 单卡实操）**：在 **`sgl-project/sglang-omni#2416`**（AMD ROCm 支持路线图）下认领一个单卡可跑的小模型（如 `Qwen3-TTS CustomVoice` 或 `Whisper` 的 ROCm 使能与回归测试），或先修 **`sgl-project/sglang-omni#4629`**（realtime 会话中途断连槽位滞留）。
3. **Arm 方向避坑**：`ARM-software/kleidiai` 在 GitHub 上是只读镜像（源仓在 GitLab 且为纯微内核），`microsoft/onnxruntime` GitHub 仓库在 2026-11-26 实时检测返回 `HTTP 404`。Arm China 框架岗优先用上述通用框架/后端贡献证明能力，Arm 端侧与 DevRel 结合 `pytorch/executorch` 和本地 [M4-Arm64-TTS 实践计划](../../推理框架/实践/M4-Arm64-TTS/项目计划.md) 推进。

## 5. 动手前核验清单与回传标准

### 5.1 每次领题前必查 4 件事

1. **重查最新 `main`/`develop`**：确认缺陷尚未被近期 commit 顺带修复。
2. **关键词重查 Open PR**：同时按 issue 号和核心函数名/文件名搜 PR，避开“issue 没挂 assignee 但已有 PR”的情况。
3. **先跑最小复现再留言**：确认能在当前硬件条件下稳定复现（或明确标出哪一段需维护者硬件 CI）。
4. **先短留言确认分工**：写明复现 commit、拟改范围、可自测环境和未测边界，再正式开写大改动。

### 5.2 完成后回传 `PlanA` 的标准

每完成一个 PR（无论已提交、评审中还是已合并），在 `../oss-contrib/summaries/` 按模板落盘一份总结，包含：
- 仓库、Issue/PR 链接、当前状态（已提交 / 评审中 / 已合并 / 已关闭）与精确 commit SHA；
- 问题根因、本人改动范围、排除的替代方案；
- 实际运行过的测试命令、硬件环境与明确未验证的边界；
- 可直接复用于简历与面试的 3 句话叙事和 2 个预期追问。

然后执行 `python3 scripts/sync_with_plana.py push-summaries` 回传至 `PlanA/开源贡献/成果总结/`。
