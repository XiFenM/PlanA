## 01 · 纠正EP必然触发All-to-All的判断

层级：mechanism；质量：A；模板：correction；事实范围：{"kind": "evergreen"}

**意图**

仅凭启用 EP 能否断言一定有 All-to-All？请给出一种不需要跨卡 dispatch 的布局，并说明如何合并结果。

**场景**

讨论的是一次 MoE 前向；各逻辑专家分别由一个 rank 负责，具体输入和输出布局需要说明。

**正确**

不能。若各卡已有完整同序输入，可分别计算本地专家贡献，再按同一 Token 做 SUM AllReduce。

**错误**

我一直以为开启ep之后必定会有all2all通信在moe计算中。

**说明**

**结论：**EP 描述专家参数的分布；通信由激活布局、专家归属及输出布局共同决定。

**反例：**各 rank 持有相同输入，只计算本地选中专家的加权贡献；无贡献的位置为零。SUM AllReduce 后各 rank 得到完整输出。

**边界：**反例要求同一逻辑分配不被重复计算，且最终输出需要复制到各 rank；不能外推所有框架配置。来源：学习记录 §3。

## 02 · 区分专家参数分布与Token激活的切分轴

层级：atomic；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

启用 EP 后，能否判断各卡原始 Token 一定不同，或每个 Token 的 H 维向量一定被切开？

**答案**

**结论：**不能。专家参数归属、Token 行分布和隐藏维切分是不同的布局问题。

**维度：**X 的形状为 [T,H]。沿 T 分片是不同 Token 分到不同设备；沿 H 分片是拆开单个 Token 的隐藏向量。

**执行：**在不叠加专家内部 TP 的算例中，每个选中专家消费完整的 H 维输入；初始 Token 是否复制还取决于 DP、TP、SP 等组合。

**边界：**判断 dispatch 要同时固定输入位置、专家位置和最终输出归属；专家同卡不保证没有跨卡往返。

**锚点**

专家归属／Token 行／隐藏维分别判断

## 03 · 核对top-k分配总数和单专家Token数上界

层级：atomic；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

T 个 Token 各选择 K 个不同的逻辑专家，且不丢弃分配。总专家任务数和单个专家任务数分别满足什么约束？

**答案**

**结论：**总分配数为 TK；每个逻辑专家最多收到 T 个 Token。

$$
\sum_e n_e=TK,\qquad 0\le n_e\le T
$$

**含义：**n_e 统计路由给逻辑专家 e 的 Token–expert 分配。一个 Token 在这里不能多次选择同一个逻辑专家。

**边界：**丢弃 D 条分配后，保留任务数变为 TK−D；padding 槽位和物理冗余副本不应被计作新增逻辑分配。

**锚点**

先固定逻辑分配与丢弃规则

**来源**

W2 单元一学习记录 · §4、11–12

## 04 · 区分相同输入存储与不同专家输出的复用

层级：atomic；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

同一个隐藏向量 x 同时被专家 E0 和 E2 选中。能否只计算 E0(x)，再将其结果复用为 E2(x)？

**答案**

**结论：**一般不能；两个专家的参数不同，输入相同不足以证明输出等价。

**任务身份：**一条专家计算任务由 Token 输入和专家参数共同确定。两个专家可以读取同一份输入存储，但仍需分别完成各自的计算。

**边界：**偶然得到相同数值也不是普遍可复用的依据；只有另有等价性证明时才能采用相应优化。

**锚点**

共享输入不等于共享计算结果

## 05 · 解释top-k展开后的结果如何还原原Token

层级：mechanism；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

MoE 将 T 个 Token 按 top-k 展开，并按专家重新排列为 TK 条任务。专家计算后，为什么仅按原 Token 编号排序还不够？需要保留哪些映射？

**答案**

**结论：**还必须按原 Token 汇合对应专家结果，并使用正确路由权重求和，才能恢复 T 个输出向量。

**映射：**每条打包结果需要能定位原 Token，以及该分支对应的专家或路由权重；打包行号不是最终输出 Token 编号。

**符号：**x_t 是 Token t 的输入隐藏向量，S_t 是选中的专家集合，g_{t,e} 是对应路由权重，E_e 是专家 e 的函数，y_t 是还原后的输出。

$$
y_t=\sum_{e\in S_t}g_{t,e}E_e(x_t)
$$

**边界：**公式采用不丢弃分配的约定；若有容量处理，应先按模型规则确定有效分配与权重。

**锚点**

展开→按专家计算→按原Token加权汇合

## 06 · 依据目标设备去重规则计算激活传输量

层级：mechanism；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

假设不使用专家内部 TP，隐藏维为 H、每元素 b 字节。源 GPU r 与目标 GPU s 不同，s 尚未持有所需输入，dispatch 对“同一 Token、同一目标 GPU”只发一份。如何计算 r→s 的激活载荷？若两个目标 GPU 位于同一节点，能否自动再去重？

**答案**

**结论：**按需要从 r 传到 s 的不同 Token 数 U_{r→s} 计费；节点级去重必须另外明确，不能自动假定。

$$
D_{r\to s}=U_{r\to s}\,H\,b
$$

**重复消费：**同一目标 GPU 上多个专家可以消费一次收到的完整向量；发往不同 GPU 的分配仍是不同目标。

**边界：**不做节点级去重时，同一 Token 发往远端节点两张 GPU 的两份载荷都计入源节点→目标节点方向的链路载荷；这里只计激活，不含元数据、padding 或协议开销。

**锚点**

去重粒度是目标GPU还是目标节点

**来源**

W2 单元一学习记录 · §4、7

## 07 · 解释回传前局部加权合并如何减少向量份数

层级：mechanism；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

同一 Token 的多个选中专家位于同一远端 GPU，且该 GPU 已获得路由权重。如何减少 combine 回传向量份数，同时保持原加权和的数学关系？

**答案**

**结论：**先在远端 GPU 按原 Token 合并本卡专家的加权贡献，再回传一个部分结果向量。

**符号：**x_t 是 Token t 的输入，g_{t,e} 是路由权重，E_e 是专家函数；A_{t,s} 是实际指派给 GPU s 执行的该 Token 专家分支集合，r_t^{(s)} 是本卡贡献，y_t 是最终输出。

$$
r_t^{(s)}=\sum_{e\in A_{t,s}}g_{t,e}E_e(x_t),\qquad y_t=\sum_s r_t^{(s)}
$$

**分配：**对 s 的求和包括来源卡自身；每条逻辑分配只计一次。有冗余专家副本时，A_{t,s} 按实际执行分配确定，不能把所有持有同名专家的卡都计入。

**权重：**只有一个本地分支时也应按该规则乘权重；来源卡收到已加权贡献后直接合并，不能再次重复乘同一权重。

**边界：**需要明确权重可用性、回传数据类型与实际合并策略；数学关系相同不构成浮点逐位一致或性能收益的实测证明。

**锚点**

按Token合并本卡贡献，再回来源卡

## 08 · 按独立与共享带宽资源推导通信时间下界

层级：mechanism；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

在理想载荷模型中，为什么不能总用所有通信字节之和除以一个链路带宽？请区分独立全双工方向、共享同向出口和严格串行阶段。

**答案**

**结论：**先识别哪些流量共享同一资源，再按资源的总载荷和带宽求下界。

**独立方向：**两个方向可同时使用各自带宽时，阶段下界取两方向传输时间的最大值。例如 48MB／16MB，各方向16GB/s，下界为3ms。

**共享出口：**同向流共享出口时先合计载荷。例如32MB和16MB共用16GB/s出口，下界为3ms。

**阶段依赖：**严格串行阶段的各阶段下界相加；发送与接收是同批载荷，不重复计一次传输。

**边界：**例中单位为十进制，忽略启动、协议、计算及其他争用；阶段重叠或拓扑变化时必须重新建模。

**锚点**

独立取最大，共享先求和，串行再相加

W2 单元一学习记录 · §9

**边界：**均分专家数、均分任务数和均分真实耗时不是同一件事；调整策略和周期由具体实现确定。

**锚点**

移动参数所属位置，保留逻辑专家含义

**答案**

**边界：**同参数是当前推理讨论的前提；这不等于已经实现了训练期间副本同步或测得负载均衡收益。

**锚点**

物理副本增加，逻辑分配仍只执行一次

**边界：**该题明确采用容量截断；不能把它推广为所有 MoE 或推理服务的默认行为。

**锚点**

路由需求≠有效任务≠物理槽位

## 15 · 推导SwiGLU专家的激活与权重形状

**问题**

无 bias 的 SwiGLU 专家收到 P[n,H]，中间维度为 F，采用行向量数学布局。写出三组权重、门控中间激活 U 和输出 Z 的形状；n 增大时哪些形状改变？

**答案**

**结论：**gate/up 权重各为[H,F]，down为[F,H]；U为[n,F]，Z为[n,H]。n改变激活行数，不改变这三组权重形状。

U=\operatorname{SiLU}(PW_{gate})\odot(PW_{up}),\qquad Z=UW_{down}
$$

**操作：**SiLU逐元素作用，⊙为对应元素相乘；gate/up两支的F通道必须对应。

**边界：**这里是数学布局；框架可能转置存储或合并gate/up权重。三组数学权重不等于三次独立kernel调用。

**锚点**

动态Token行数，固定H到F到H映射

**问题**

SwiGLU 专家的输入 P[n,H] 在 p 个 TP rank 上完整复制；n 是 Token 行数、H 是隐藏维、F 是中间维，F 可被 p 整除。gate/up 沿相同 F 通道切分，down 沿对应 F 轴切分，忽略 bias。如何得到每卡完整输出？请说明局部张量形状与通信。

**答案**

**结论：**各卡先得到U_r[n,F/p]，再得到局部Z_r[n,H]；要让每卡持有完整输出，需要SUM AllReduce。

$$
Z=UW_{down}=\sum_{r=0}^{p-1}U_rW_{down,r}=\sum_r Z_r
$$

**语义：**局部Z_r和完整Z形状相同，但局部只含部分中间通道的贡献。数学上的U拼接不要求执行时先物化完整U。

**边界：**这里明确要求每卡完整复制输出；若出口采用其他布局，通信也应按新约定推导。

**锚点**

切分归约轴，得到同一输出的部分和

**正确含义：**SUM ReduceScatter 对齐全局元素完成归约，并把不同结果片段分给各rank；所得[2,H]是部分Token的完整结果。

## 20 · 解释分块Attention为何需要归一化统计

层级：mechanism；质量：A；模板：technical-qa；事实范围：{"kind": "evergreen"}

**问题**

对同一个Query，将可见K/V分为A、B两块。o_A、o_B分别是块内softmax后的输出，L_A、L_B是基于同一原始score标尺的指数和。如何合并为全局Attention输出，为什么只有局部输出不够？

**答案**

**结论：**按两块的归一化质量重新加权，不能直接相加或无条件平均。

$$
o=\frac{L_Ao_A+L_Bo_B}{L_A+L_B},\qquad L_A=\sum_{j\in A}e^{s_j}
$$

**反证：**给A块所有score加ln2，o_A不变而L_A翻倍，A的全局权重改变；只保留o_A无法识别这项变化。

**边界：**L在此不是log值，也不是分别减去各块最大值后的未校正分母；稳定实现需要保留等价统计和统一尺度。

**锚点**

局部归一化输出丢失块间相对质量
