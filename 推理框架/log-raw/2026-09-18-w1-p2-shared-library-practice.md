三项预测都正确。更精确地说：**app 引用了 `compute(int)`，链接时由 lib-a 满足这个引用；运行时装入 lib-b 后，还必须找到同一个符号。** 同名共享库不保证提供相同的函数。

现在取得第一组二进制证据。在 **PlanA 根目录**执行：

```bash
readelf -d ../plana-w1-env/p2-build/app | rg 'NEEDED|RPATH|RUNPATH'

nm -D -C --undefined-only ../plana-w1-env/p2-build/app | rg 'compute'

nm -D -C --defined-only ../plana-w1-env/p2-build/lib-a/libw1probe.so | rg 'compute'

nm -D -C --defined-only ../plana-w1-env/p2-build/lib-b/libw1probe.so | rg 'compute'
```

这些选项的作用是：

- `readelf -d`：查看动态链接信息，包括依赖项和内置搜索路径。
- `nm -D`：查看动态符号；`-C` 将 C++ 符号名还原为可读形式。
- `U`：该文件引用但没有定义的符号；`T` 通常表示代码段中定义的符号。动态链接程序存在 `U` 很正常，关键是运行时能否找到定义。

**请贴出相关输出，并说明 app 需要的符号与两份库提供的符号是否匹配。** 这一步检查二进制内容，随后再核对目标进程实际加载了哪份库。
