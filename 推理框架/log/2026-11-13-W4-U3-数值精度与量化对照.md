## 学习过程

<a id="w4-u3-p01"></a>

- [要点] 某个投影用 FP32 累加，为什么从 BF16 换 FP16 仍可能出现 Inf？我从指数范围较小想到输入转换或写回已可能溢出。导师补明，已有的 Inf 再转为 FP32 仍是 Inf，一个算子的部分和精度也不能覆盖整图。（消息 `msg-e62076fafc8240736676`、`msg-d017613759ac0bcca9d3`）

<a id="w4-u3-p02"></a>

- [纠错] 看 group 从 128 缩到 64 后的重建误差，我说“分组量化的group大小和TTFT没有关系”。我的依据是这次浮点存储未改，实验只观察了重建误差。导师把“和 TTFT 没有关系”的适用范围收在这次实验，低位部署的时延、打包与元数据开销要另测。（消息 `msg-a6fce7734d340c16a1d7`、`msg-64da3b884209c892b742`）

<a id="w4-u3-p03"></a>

- [要点] 两条路径用相同 packed 权重，为何还会算出不同函数？我先问清乙用的是合并补偿以前的参数，再说明 scale 和 zero point 只重建 WD 的近似值。乙仍输入 X，缺少输入侧 D⁻¹，比较速度前应先恢复计算语义。（消息 `msg-dac6044f93781e105be9`、`msg-79663204453591c833e4`、`msg-c4de73aa1c35ac57eabf`、`msg-9a0cff2edcbe1f72aa45`）

<a id="w4-u3-p04"></a>

- [纠错] 在口述加载过程时，我把“按通道放缩的D等参数”和 packed 权重一并列作加载对象。实际可以在导出前就把 D⁻¹ 折进前一层，权重也可能在进入矩阵乘前先反量化。换一道题后，我指出多乘一次 D⁻¹ 就会改变整图语义，而用同一份已变换输入比较两个投影实现，仍可能局部通过。（消息 `msg-a1dfe6b86e2cdb050b61`、`msg-7700b82d0874c45f24dd`、`msg-171e07cc150c393e5a39`）

<a id="w4-u3-p05"></a>

- [转折] 我起初从显存利用率设置直接解释总显存“基本不变”。看到可用 KV 块随请求长度和数量变化后，我改为分别看固定权重、预分配池、池内空闲量、激活和临时区。固定池容量并不能预告新并发与上下文下的峰值余量。（消息 `msg-7b0fe6a6e85c26497eb6`、`msg-5b3a698102d20f6a70b2`、`msg-82e288a712f705b2762b`、`msg-f873b88bddbfa010a915`）

<a id="w4-u3-p06"></a>

- [高价值问题] 量化实验还要再跑一遍完整 CPU 模型吗？上一单元的独立 CPU 参考耗时很长，我提出先明确验证目标。这次用同一 packed 表示和相同输入做局部 GPU FP32 参考，整模质量另用固定任务的答案核对，性能则由 GPU 服务计时。（消息 `msg-838926daab6963145406`、`msg-dbda66028f91280565cd`）

<a id="w4-u3-p07"></a>

- [转折] 新实例的 vLLM 和镜像能力与原测试包预期有出入，预检先暴露了版本与 CLI 检测问题。最终 BF16 基线对照的是 AWQ／FP16 路径。事前我预期权重变小、KV 容量变大、吞吐提升，复盘时必须把激活 dtype 与底座 revision 的边界一并带回解释。（消息 `msg-1314475c670f67de10e1`、`msg-faf375158a221c9136cc`、`msg-7fda4b32dd75674a2474`、`msg-b117ac92255a7f167e25`、`msg-93f98c50372843fd7a75`）

<a id="w4-u3-p08"></a>

- [要点] 实测哪些地方推翻了原来的预测？载入占用从 2.98 到 1.10 GiB，KV 容量增加，但每轮同为 6,144 个输出 token 时，完成窗口变长，吞吐从 359.84 降到 297.16 token/s。我报告 TTFT P50 下降、ITL P50 上升而 P99 下降，并主动问这两个分位数怎样共存。典型间隔和尾部阈值可以分别改变。（消息 `msg-b117ac92255a7f167e25`、`msg-93f98c50372843fd7a75`、`msg-66ba5883c0c36da9d1f3`、`msg-201cc08f3901c94ea32b`）

<a id="w4-u3-p09"></a>

- [要点] 在反向变式里，P99 变差还能推出吞吐下降吗？我依据相同输出总数和更短的总窗口，直接推出吞吐上升。识别这个方向已有足够数据，解释窗口为何变化才需要 profiler。（消息 `msg-66ba5883c0c36da9d1f3`、`msg-201cc08f3901c94ea32b`、`msg-9d40cf27c22bf4eb54f4`）
