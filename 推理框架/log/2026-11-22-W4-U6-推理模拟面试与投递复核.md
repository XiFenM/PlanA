## 学习过程

<a id="w4-u6-p01"></a>

- [要点] 同一张图里可以怎样并列“毫秒／调用”和“毫秒／步”？我要求补上“每步调用数，单位是次调用/步”。同一主机线程串行调用 N 次时才可用单次耗时乘 N 估算该部分，整步还含其他工作。（消息 `msg-5efed713fbf04b4d802c`、`msg-32642dab81c369e0c236`、`msg-efdcbedc2fb602e346a2`）

<a id="w4-u6-p02"></a>

- [纠错] 我在解释 AMD 实验时把预算增大直接接到“减少了端到端所需要的处理步总数”。在只有 8 条普通 decode、每步各出 1 个且预算够用的变式里，两档都要一起走 32 步。我据此把实测吞吐和 ITL P99 的变化与“是否少走了步”分开，后者要看实际调度记录。（消息 `msg-e2c459d45d743c42da66`、`msg-0498a349ca290d770020`、`msg-97f850b10e2bdcc5a487`、`msg-a23203c01dd526c23dcb`）

<a id="w4-u6-p03"></a>

- [要点] 单卡请求如何从 prefill 走到客户端首个输出？现场从前端分词、到引擎排批、与已有 decode 分摊额度，一直讲到最后一个 prefill 分块后的采样。改为非流式时我能指出客户端只看到完整结果。流式 TTFT 则从客户端发出请求计到实际首个生成 token，服务端打点要另说起止位置。（消息 `msg-46ee691119297f144f35`、`msg-f3656855af3bb9c938c8`、`msg-10c0f26393c4c880e668`、`msg-7e7daee6e03fb79e3f93`）

<a id="w4-u6-p04"></a>

- [纠错] 我把 logits 说成“logits的概率分布”，并坦言忘了怎样从隐藏向量算出来。最后一个输入位置的隐藏向量经过输出线性层，先得到词表大小的原始分数，按解码策略选取 token。听到“每个权重向量做点积”后，我主动把整排点积收束为一次线性变换。（消息 `msg-d602d824c2a089025cc4`、`msg-9de502ac4b9f694bb48c`、`msg-7bc46680c59b63b9aee7`、`msg-9377f586e08f15a09595`、`msg-e962182cbf392f0fc16e`）

<a id="w4-u6-p05"></a>

- [要点] 生成下一枚 token 时，缓存里读什么、再写什么？我先说历史 K、V 可以直接复用，再补当前输入的 K、V 需要计算并写回。导师补齐当前 Q 用于查询。读历史块靠每请求的逻辑块到物理块映射，写新 K、V 的具体槽位则由 slot mapping 指出。（消息 `msg-6c9b4ac4d111ceccbb15`、`msg-5c64b3bd01d120d5bfcb`、`msg-50aad1065ffd254c522a`、`msg-12af56ec2ad00f66d314`、`msg-3d61d580df99524f5c50`、`msg-a17fc9824e8cbd684dd1`）

<a id="w4-u6-p06"></a>

- [转折] 我在调度题中途指出自己还没回答完，又把原因补成保护正在 decode 的连续输出。复盘页面最终改为“参考要点＋可独立背记的口述”，现场的停顿、识别错误以及导师提供的说法留在可回查材料里，不能算成学习者独立首答。（消息 `msg-6199443e5747a377822b`、`msg-3fa9e5ec98ccf999f48a`、`msg-36d690a74402917fc0f4`、`msg-2df70afe8ab06a645284`、`msg-b3452039901b891818fc`、`msg-6bd881796713c37239fa`）

<a id="w4-u6-p07"></a>

- [要点] 视频 OOM 的介绍怎样区分定位、修复和跑通？我沿 Python 报错栈找到 Conv3D，再追到底层把颜色通道移到末维后触发对齐和显存膨胀，讲到模型侧展平与算子按元数据解释输入。单算子、同一视频请求都能跑完，支持“原故障未再出现”。对数值正确性还要说清比较的层次。视频整模 token 对照的历史证据以[单元五的核实](../../计划/八周冲刺进度/历史记录/W4-学习验收记录.md#w4-u5-regression-reference-20261120)为准。（消息 `msg-b3a2492959e8d86f5755`、`msg-2df86ad1c48c15ee27b0`、`msg-b1fd18a506095703f87a`、`msg-cec50f87d3a0bbee1002`、`msg-24a8a603d767e8a5cb83`）

<a id="w4-u6-p08"></a>

- [纠错] 图片 TTFT 的重复次数，我在语音里说“我记得是五次还是十次”。核对后的口径是 Qwen2.5-VL-32B、10 个单图用例、单并发，每个用例优化前后各发一次流式请求，两条路径分别对十个客户端 TTFT 取均值，从分钟级到 5 秒以内。单并发在学员前半段已讲出，导师后来纠正了“漏讲”的提示。（消息 `msg-cadfd2039642c27b51cb`、`msg-7a754fce1b3083284cda`、`msg-167ac879470790eae7c6`、`msg-525be499b96ea7840767`、`msg-130bf39c4a19f6f08e04`、`msg-bf5709558c3f96a837ac`、`msg-a7ac278e884cdd26f4a2`）

<a id="w4-u6-p09"></a>

- [要点] Prefill 主动推送 KV，decode 收到完成通知就能提交 attention 吗？我先交代谁预留目标空间，随后在主机内存中转的变式里指出，收到网络数据后，计算流还要等本地 H2D 拷贝完成。通知要说清对应的是哪一段传输。（消息 `msg-87c625192672a9f05813`、`msg-13f255ea31ea8eed140f`、`msg-8f615a0bac77128efadc`、`msg-a64028a40a2b8778ba5e`、`msg-5a31efe51779df474552`）

<a id="w4-u6-p10"></a>

- [转折] 我从一层一个 token 出发推数据量，一次口述收尾漏说 K、V 各一份，随后补齐。BF16 每元素 2 字节与 K、V 两份是不同的因子，最后再乘 KV 头数、head dim、层数与有效 token 数。语音引导曾把 256 MiB 说成半个 GiB。学员复述纠正为四分之一个 GiB，按 25 GiB/s 得到 10 ms，另外还要等 H2D。（消息 `msg-0185eb4020d9b98e0715`、`msg-ef6b06201eefeb6da0b2`、`msg-9cbbadfb00ce7d9bdd23`、`msg-f33f3ad21facf805cbeb`、`msg-a71f320d96ea7f24e5c7`、`msg-71bd119bc753a939a464`）

<a id="w4-u6-p11"></a>

- [纠错] 讨论传输超时，我起先想终止通道后“然后直接去复用”。请求判失败可以先隔离显存块，回收还要有旧传输停止访问的确认，包括 decode 端已提交的本地拷贝。（消息 `msg-5557d2c02241cacb9ec3`、`msg-80b55bcfef1c576a3967`、`msg-9813d9ff567f82814ca4`、`msg-950f6178c398c9a74170`、`msg-33435205077004e21bff`、`msg-2ce8c61a01c74c597184`）

<a id="w4-u6-p12"></a>

- [要点] 哪种对照能把 TTFT 差值归给专用算子？先前原项目的模型调用、权重布局和算子实现一起改变，核准后的口述把收益表述为联合结果。最后换到只改算子内部实现、模型调用与布局都固定的题设，我能把这组差值归给此次隔离的改动。（消息 `msg-bf5709558c3f96a837ac`、`msg-a7ac278e884cdd26f4a2`、`msg-2ce8c61a01c74c597184`、`msg-34aab93ee6c03fd1fed6`）

<a id="w4-u6-p13"></a>

- [转折] 先书面选定相同两台单卡做双完整实例与 PD 分离的重放，用 ITL P99 看“回答到一半卡”，同时核 TTFT 与吞吐。本人明确第一次直接写成。后来独立口述“首字慢”的变式，把排队等待与 prefill 执行时间分开，解释拆分要连同跨机 KV 开销一起评估。最终投递材料和证据的去向见[准备度复核](../../计划/八周冲刺进度/历史记录/W4-学习验收记录.md#w4-u6-mastery-gate-20261122)。（消息 `msg-f65e433859e2c51b8a4a`、`msg-a062c1afa68289f20c5c`、`msg-e8061b807ff02b853f00`、`msg-ac1f32d857541a5be572`、`msg-ae6144ddfa0494a37317`、`msg-9f1490aec7b9026de061`、`msg-72df41c227c3bc6268bb`、`msg-ad445e46e167071a8a44`）

<a id="w4-u6-p14"></a>

- [要点] 准备度复核如何回到具体岗位？我确认 GLM 的 TP=8 是单机八卡，也要求 HR 介绍保留原稿。目标 96121 对模型接入和推理性能的要求，由 B 版材料与既有单卡实操支撑。多节点项目和上游协作仍按另外的证据判断。（消息 `msg-bb7fe8aab8c1be5fc451`、`msg-5efed713fbf04b4d802c`、`msg-47b3790e07a7b9da8f16`、`msg-ff352ba69abbc9ebed07`、`msg-27ac1193ea50b3ee66a2`、`msg-ffd9ca1eb9137a3de8d4`、`msg-ad445e46e167071a8a44`）
