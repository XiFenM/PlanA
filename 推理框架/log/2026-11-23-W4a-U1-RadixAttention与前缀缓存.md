## 学习过程

<a id="w4a-u1-p01"></a>

- [转折] 我要求最后一个 MTP 单元接回自己做过的 GLM 项目，也指出第一单元的页面一开始就跳入细节。调整后的入口先放整周的两个学习项目，再用两个共享提示词的请求讲完 RadixAttention 的目的与数据流，最后从源码走读提取节点问题。[课程导入](../../课程网页/八周计划/plana-jd-w4a-sglang-specdec.html#w4a-overview)（消息 `msg-5a15c1a1f15c088f2706`、`msg-fe3e3a416bf8c949ef92`、`msg-01437fbda2927b7fb883`、`msg-6659bf48001f49fbeb97`、`msg-724e850015bd22fb4962`、`msg-3d866487db4750f4b1ed`）

<a id="w4a-u1-p02"></a>

- [要点] 第 5 个 token 首次分叉，后面相同位置的 token ID 又相同，还能继续复用吗？我独立判断 C 只能复用 A 的前 4 个位置。从第 5 位起，因果注意力可见的上文变了，后缀需要在新上下文里做前向。（消息 `msg-42a621793bf43193f5f8`、`msg-1458eba7454e117950e8`）

<a id="w4a-u1-p03"></a>

- [要点] 两人共享前缀，最后一个请求放下引用时，该段会马上归还给分配器吗？我先看 B 结束后 D 仍持有引用，再看 D 结束后树下是否还有驻留子节点。只有当前缀成为无引用叶节点且还需要腾空间，才可能继续淘汰。若删一片后缀已经够用，前缀仍可供后来的请求命中。（消息 `msg-0b710681751f0445d29a`、`msg-8615aed253427fee53ff`）

<a id="w4a-u1-p04"></a>

- [要点] 49 个输入位置中只有第 20 位不同，两种粒度分别能用到哪里？我算出 SGLang 每页 1 个时能用前 19 位，vLLM 每块 16 个并按整块查找时能用前 16 位。第三块的 ID 即使都相同，它继承的第二块哈希已经改变，不能作为独立命中。（消息 `msg-72d6feb01e33dee595d7`、`msg-4473db0965cf4df80c4d`）

<a id="w4a-u1-p05"></a>

- [高价值问题] “那二者的区别到底在哪呢”？我意识到两边调整粒度都能改变命中率。把页与查找块都设为 16 后，本例都只能命中前 16 个位置。SGLang 按子节点和连续 ID 找已有槽号，vLLM 则把前块哈希、本块 ID 和附加信息编码为键，逐块寻找可用前缀。（消息 `msg-525688278c71a4b06094`、`msg-4473db0965cf4df80c4d`、`msg-2bfd6e529ab371728ab8`、`msg-55ef2fd4945ae44f4b78`）

<a id="w4a-u1-p06"></a>

- [高价值问题] vLLM 先回收哪块，和 SGLang 的“尾部优先”是不是同一个意思？vLLM 本例中无哈希空闲块优先，仍有哈希的空闲块按队列头分配。同一请求同时释放的完整缓存块以相反的逻辑顺序进入队尾。SGLang 则先筛无引用的驻留叶子，再由淘汰策略挑选，默认 LRU 比较最后访问时间。（消息 `msg-173f3e6da62445053eaa`、`msg-387ed6d31a30bead0b90`、`msg-35354295f13fccb1ee79`、`msg-77169f32b4ef4be459a4`）

<a id="w4a-u1-p07"></a>

- [转折] 我从“回收整个叶子”追问到请求尾页所在的位置。若 A 的末页后面还接着更长请求的后缀，A 的末页就在内部节点。被选中的压缩叶节点则可能包含两页，缺一页也会一次归还两页。这两个反例和空闲队列的对照已放在[回收与再利用](../../课程网页/八周计划/plana-jd-w4a-sglang-specdec.html#add-4-2)。（消息 `msg-b6c95fec3a197f8cf93b`、`msg-97bef11b8900b4c592ac`、`msg-cd462591545b478d5351`、`msg-cba2804fbc2b514d7ec6`）

<a id="w4a-u1-p08"></a>

- [要点] 有一台能命中 2,048 个讲义位置但要排队，另一台空闲却要全量 prefill，选谁？我比较排队时间与省下的输入计算，并提出发送同一流式请求比较首 token。导师把临界值补准为两条真实 prefill 路径的耗时差。复测应恢复各自的初始缓存和排队状态，并从各自客户端发送计到首个生成 token。（消息 `msg-008902d7c156e8caaa31`、`msg-54c5b16e99f8024060c5`、`msg-937059fb9c285272a828`）
