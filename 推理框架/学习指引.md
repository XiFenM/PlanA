# 推理框架学习指引（5 周主线 / Track A 核心）

## 0. 入场点

- **为什么学**：这是你目标岗的第一命题。你 CV 上写了"精通 vLLM、SGLang 源码及架构"，必须把这句话变成真的——能在白板上画出 vLLM V1 scheduler 的状态机、讲清 PagedAttention block table 的 CoW、手写 RadixAttention 的 LRU、解释 continuous batching 相对 static 的收益公式。
- **终点（5 周后必须能做到）**：
    1. 白板画 vLLM V1 scheduler 一个 step 的完整流程（prefill + decode 混合、抢占、swap）
    2. 白板讲 PagedAttention 的 block table、物理/逻辑映射、CoW、prefix caching
    3. 白板讲 SGLang RadixAttention 的 insert / match / evict
    4. 讲清 Speculative Decoding（draft model vs EAGLE vs MTP）的数学收益公式和系统挑战
    5. 能回答 [common_problems.md](../面试准备/common_problems.md) 里："flash attention 系列优化"、"vllm 调度机制"、"模型运行时的内存碎片问题如何处理"、"推理框架未来发展痛点"
- **时间预算**：5 周 × 32.5h − (Leetcode 4h/周 + 其他 ~6h/周 杂项) ≈ **110–120h**。

13b. 🟥 ⭐ **P-EAGLE 论文 + vLLM 博客（2026-02/03）**

    - **时间**：**2.5h**

## 3. 实践任务

> 每个任务都映射到上面的资料，不做空中楼阁。

### 任务 1 — 一阶原理计算（W3，2h）

- **要求**：用 Jax Scaling Book 的方法（资料 1），手算下面四个场景的理论 TPOT：
    - Llama-3-8B on 4070 Ti（FP16，seq=2048，batch=1 和 16）
    - Llama-3-70B on H100（FP16，seq=2048，batch=1 和 16）
- **对比**：在 H100 上真实跑 vLLM 的 benchmark 脚本 `benchmarks/benchmark_throughput.py`，看实测和理论的差距（通常 60–80% 之间）
- **产出**：一张 csv + 一段 300 字分析

### 任务 2 — 复现 Mini-PagedAttention（W3 末，6h）

- **要求**：用纯 Python + numpy 实现：
    - 固定 block size（比如 16）
    - block table 映射逻辑：`logical_block_id → physical_block_id`
    - 支持 prefix caching（相同前缀 hash 复用）
    - 支持 CoW（beam search 两个分支共享前缀，发散时拷贝）
- **不要求**：性能、CUDA
- **产出**：`推理框架/mini_paged_attn.py` 可跑 + 一段单元测试

### 任务 3 — 手写 Mini-RadixCache（W5，8h）

- **要求**：参考 SGLang 的 `radix_cache.py` 实现：
    - `insert(tokens, kv_value)` / `match_prefix(tokens) -> (kv, matched_len)`
    - 引用计数 + LRU 淘汰
    - 带一个打印整棵树的 debug 函数
- **产出**：`推理框架/mini_radix_cache.py` + 3 组多轮对话的插入演示
- **进阶**：把它跟任务 2 的 mini paged attention 组合起来

### 任务 4 — vLLM V1 Scheduler 源码走读博客（W4，8h）

- **要求**：选 vLLM 最新 release，写一篇 2000–3000 字博客（草稿即可）：
    - 一个完整的 `step()` 流程图
    - `Waiting / Running / Preempted` 三态转换
    - budget-based 调度怎么让 chunked prefill 和 decode 自然混合
    - 抢占路径：什么时候选 swap，什么时候选 recompute
- **产出**：`推理框架/blog_vllm_v1_scheduler.md`

### 任务 5 — 跑 EAGLE-3 并观测接受率（W6，4h）

- **要求**：在 H100 上启动 vLLM spec decode 模式（EAGLE-3），跑 3 组 prompt（简单 QA / 代码 / 长文档总结）
    - 观察 `acceptance_rate` / `speedup`
    - 对比不使用 spec decode 的吞吐
    - **加分项**：如果 SGLang MTP 环境也能搭起来，多跑一组 MTP 模式对比
- **产出**：`推理框架/spec_decode_numbers.md` 数据表 + 简评

### 任务 6 — TTFT / TPOT 矩阵（W7，6h）

- **要求**：H100 单卡，Qwen2-7B-Instruct，测下面三个配置：
    - 普通推理
    - Chunked Prefill 开启
    - 不同 `max_num_batched_tokens`（512 / 2048 / 8192）
- **产出**：一张 TTFT / TPOT / Throughput 表，说明 chunked prefill 怎么影响 tail latency

### 2025Q4-2026Q1 新题（跟进最新资料）

- ⭐ **vLLM V1 → MRV2 变了什么？为什么 Q1 2026 要把 "MRV2 on by default" 列为 P0？**（答：GPU-native 输入准备 + async-first 调度 + piecewise CUDA graph for PP）
- ⭐ **EAGLE-3 之后 spec decode 往哪走？为什么没有 EAGLE-4？**（答：战场从"接受率"转到"drafter 延迟"；P-EAGLE 把 drafter 顺序化改并行，B200 1.10-1.69×；不存在 EAGLE-4，SafeAILab 也没发）
- ⭐ **Wide-EP 从"能跑"到"生产可用"的关键是什么？**（答：Elastic EP 2026-03 解决失败容忍，expert-GPU 映射解耦，单 GPU 挂了 <10s 恢复；配合 DeepGEMM Mega MoE 2026-04 把通信和计算全融合）
- **NVIDIA Dynamo 1.0 GA 相比 2025-03 preview 加了什么？**（答：agentic routing、cache pinning、ModelExpress 7× 启动加速、GB300 Grove topology-aware）
- **DeepSeek-V3.2 DSA 对 serving 侧意味着什么？**（答：Lightning Indexer FP8 scorer + top-k 把复杂度从 O(L²) 降到 O(Lk)，是 2026 长上下文 serving 的新范式）
- **SOSP'25 的 Jenga 解决什么问题？为什么已经 merge 进 vLLM？**（答：hybrid/Mamba 模型的异构 KV 维度，vLLM 现有的 PagedAttention KV manager 假设同构，Jenga 打破这个假设）
- **2025Q4-2026Q1 推理框架整体是新范式重塑还是成熟期？**（答：成熟期——PD 分离 / wide-EP / MTP/EAGLE 都进入打补丁阶段；主题是 Blackwell 对齐 + 生态整合，三件事同月发生：Dynamo GA / llm-d 进 CNCF / Mooncake 进 PyTorch Ecosystem）
- **MoE serving 的三阶段演化？**（答：能跑 → 跑得快 → 跑得稳：DeepEP 2025Q1 解决吞吐；Wide-EP 2025Q3 解决规模；Elastic EP 2026-03 解决可用性）
