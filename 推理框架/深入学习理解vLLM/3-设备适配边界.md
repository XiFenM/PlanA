设备变化不必直接改变请求调度语义。本文整理 vLLM 现有扩展点与必须保留的契约，说明何时可以替换设备实现，何时才需要讨论核心接口修改。

## 来源与适用条件

本文依据 vLLM `v0.26.0 @ 568afb3a13806beb53bb2e6bd518269357b237c0`，承接[请求生命周期与输出](2-Request-Lifecycle-and-Output.md#pass-d-execution-contract)。下述场景假定请求与 token 调度语义保持不变，设备运行时、KV padding、融合算子和 TP 子组通信的差异可以通过既有接口表达。

这些边界用于解释源码契约，不代表某款芯片已经完成实现或运行验证。OOT Platform 的公开规范要求平台指定 Worker、Attention backend 与 communicator，因此设备接入首先需要核对这些扩展面。[OOT Platform 规范](https://github.com/vllm-project/vllm/blob/568afb3a13806beb53bb2e6bd518269357b237c0/docs/design/plugin_system.md#L100-L117)

## 六层适配矩阵

适配方式取决于差异落在哪个边界。无论内部实现怎样替换，对上层承诺的数学语义、资源信息和执行依赖都必须保持一致。

| 层次 | 处理方式与接入点 | 必须保留的契约 |
|---|---|---|
| HTTP／前端 | 保持协议处理不变 | 输入语义、流式输出和取消语义；进程放置不决定是否需要修改协议 |
| EngineCore／Scheduler | 保持普通请求生命周期与逻辑 KV 调度 | 请求状态、token budget、逻辑块归属、抢占／恢复与结束清理相互一致 |
| Platform／Worker／ModelRunner | 平台插件通过 `check_and_update_config()` 设置 `parallel_config.worker_cls`；Worker 构造自定义 Runner，适配或替换设备执行实现 | 消费 `SchedulerOutput` 并返回约定结果；报告真实 KV 规格／可用内存并兑现分配方案；执行与采样的完成语义正确 |
| KV cache／Attention backend | 使用 `get_kv_cache_shape()`、`get_kv_cache_stride_order()`、`KVCacheSpec.page_size_bytes`，并适配实际分配及读写实现 | padding 后实际字节占用纳入预算；逻辑 token、block table、slot mapping 与物理布局一致，读取遵守请求边界和注意力语义 |
| 普通算子 | 注册底层 PyTorch 算子；通过 `register_oot` 替换相应 vLLM 算子类，在 `forward_oot` 调用设备实现 | 保持数学语义、支持的 shape／dtype／device、输入修改／返回值及执行依赖契约；注册动作本身不是正确性契约 |
| 设备通信 | Platform 的 `get_device_communicator_cls()` 选择自定义 communicator | 正确绑定子组与 rank，保持 collective 数学语义、tensor 行为和后续消费所需的执行依赖 |

## 设备实现与上层契约

ModelRunner 可以由自定义 Worker 构造，不能仅凭需要不同的 Runner，就判断必须修改 EngineCore。执行层仍需消费 `SchedulerOutput` 并返回上层约定的结果；自定义实现也必须保留执行与采样之间的完成语义。

KV 的逻辑调度与物理布局需要对应。若设备要求 padding，页大小报告、实际分配和读写实现必须一致；仅修改物理 tensor 的形状，不能替代对实际字节占用的预算。普通算子和通信层同样需要保持输入输出语义及后续消费所依赖的执行顺序。

## 何时需要 core patch

core patch 指修改框架核心接口或流程，不能作为换芯片的默认起点。提出修改时，应分别说明：

1. 目标设备需要表达的内存、同步、完成或调度语义。
2. 现有字段和 hook 已经能够表达的部分。
3. 当前接口无法传递的信息，或无法保证的执行顺序。

如果 `SchedulerOutput`、`KVCacheSpec`、`WorkerBase` 或 backend 契约确实无法表达所需语义，才有依据提出窄范围核心修改。页大小漏报或已有抢占流程没有被正确使用，首先属于实现、配置或契约遵守问题。换芯片、出现 OOM、需要自定义 Runner，都不足以单独证明核心接口必须修改。
