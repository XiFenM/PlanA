- **终点（W16 末必须能做到）**：
    1. **KV cache 计算器级熟练**：给 (模型参数、seq_len、batch、resolution) 写一张 KV 大小表，覆盖 MHA / GQA / MLA × FP16 / FP8 / NVFP4 / KIVI-2bit 四精度

### A. Attention 演进 MHA → GQA → MLA（W15 核心，12h）

1. 🟨 **MQA (Shazeer 2019)**
    - 链接：https://arxiv.org/abs/1911.02150
    - **精读 1 条**：为什么 MQA=GQA(g=1) 是 KV 压缩的极端，为什么实际没人用纯 MQA（退化严重）
    - **时间**：**0.5h**

2. 🟥 **GQA (Ainslie 2023)**
    - 链接：https://arxiv.org/abs/2305.13245
    - **精读**：§3（GQA 定义）+ §5 实验中的"从 MHA 初始化 → GQA uptrain"的低成本方案
    - **关键系统视角**：`n_kv_heads` / `n_heads` 比值直接决定 KV cache 大小和 per-step 访存带宽
    - **时间**：**1.5h**

3. 🟥 ⭐ **DeepSeek-V2 Tech Report（MLA 章节）**
    - 链接：https://arxiv.org/abs/2405.04434
    - **精读**：§2.1 MLA（低秩联合压缩，decoupled RoPE）
    - **核心数学**：KV 每 token 只存 `d_c + d_rope` 维（DSV3 具体是 512+64=576），对比 MHA/GQA 减少约 5-10 倍
    - **时间**：**3h**
    - **产出**：手推一遍 MLA 的"absorbed weight"推理技巧（W_UQ·W_UK^T 和 W_UV·W_O 在推理时可合并，避免显式重构 K/V）

4. 🟥 ⭐⭐ **DeepSeek-V3 Tech Report**（本板块中心文档）
    - 链接：https://arxiv.org/abs/2412.19437
    - **精读**：§2.1.1 MLA 实施、§2.1.2 DeepSeekMoE 辅助损失无关负载均衡、§2.1.3 MTP、§3.3 FP8 训练
    - **为什么是中心**：MLA + MoE + MTP + FP8 四件套**在一篇里全讲清**，读完覆盖本板块 A/D/E/F 四节的一半内容
    - **时间**：**4h**

5. 🟨 **FlashMLA (DeepSeek, 2025-02) + DSA 改版状态**
    - 链接：https://github.com/deepseek-ai/FlashMLA
    - **精读**：README + kernel 签名（不深入 CUTLASS/CuTe 代码，那是算子板块 Track B 的事）
    - **时间**：**1h**
    - **2025-09 后状态**：DeepSeek-V3.2 引入 **DSA (DeepSeek Sparse Attention)**，FlashMLA 已被修改为 DSA 后端（Lightning Indexer FP8 scorer + top-k 选择，O(L²)→O(Lk)）；具体见 SGLang 博客 https://www.lmsys.org/blog/2025-09-29-deepseek-V32/ 。DSA 架构与稀疏注意力讨论在 §A 资料 8 (DSA 论文)

#### 稀疏 attention 三件套（2025 的"MLA 之后"主线）

> 2025 Q1-Q4 业界同时出现三条稀疏 attention 路线：**NSA (DeepSeek)** 偏硬件对齐块结构、**MoBA (Kimi)** 偏块级 gating、**DSA (DeepSeek-V3.2)** 偏"MLA 之上叠 top-k 索引器"。面试被问"MLA 之后下一步"时三者是标准答案三件套。

7. 🟥 **NSA: Native Sparse Attention (DeepSeek, 2025-02)**
    - 链接：https://arxiv.org/abs/2502.11089
    - **精读**：§3 三分支结构（compressed / selected / sliding）+ §5 硬件友好的 kernel 结构
    - **时间**：**1.5h**

8. 🟥 ⭐ **DSA: DeepSeek Sparse Attention (DeepSeek-V3.2，2025-09 Exp / 2025-12 正式报告)** 🆕

    - 代码：https://github.com/deepseek-ai/DeepSeek-V3.2-Exp
    - HF：https://huggingface.co/deepseek-ai/DeepSeek-V3.2
    - **为什么必读**：这是在**已经有 MLA** 的基础上叠"闪电索引器 + top-k=2048 token 选择器"，把 attention 复杂度从 O(L²) 降到 O(L·k)。**直接改变推理 kernel 形状**——vLLM 已适配。对你本职工作最相关的 2025 年后半新方法。
    - **精读**：闪电索引器结构 + top-k 选择的 kernel 流程 + 与 MLA 的 compose 关系

#### 深度残差的重新思考

13. 🟨 **Kimi Attention Residuals / Block AttnRes (Moonshot, 2026-03)** 🆕
    - 论文：https://arxiv.org/abs/2603.15031
    - 代码：https://github.com/MoonshotAI/Attention-Residuals
    - **用法**：**替换残差连接**——不再固定累加，而是跨深度做 softmax attention；Block AttnRes 只跨 ~8 个块做，开销小
    - **对框架影响**：forward 要保留层间激活做 depth-attention，activation memory / recomputation 策略要重做
    - **时间**：**1h**（略读概念，不需要深入推导）

14. 🟥 **mHC: Manifold-Constrained Hyper-Connections (DeepSeek-AI, 2026-01)** 🆕 —— 就是你问的 "DeepSeek MHC"
    - 论文：https://arxiv.org/abs/2512.24880
    - **为什么必读**：DeepSeek 2026 年初放出的残差连接扩展方案。**沿着 "Hyper-Connections (HC)" 继续往前推**：HC 已经把残差 stream 宽度扩展、多条连接多样化，但破坏了残差本来的 identity mapping 性质（→ 训练不稳、scaling 受限、访存开销大）。mHC 把 HC 的残差空间**投影到特定流形**上，恢复 identity mapping，同时做了工程优化
    - **系统视角**：对你本职工作意义很大——这类"改残差"的新工作影响的是 forward/backward 的图结构和每层的 activation memory，对应你手上的非 NV 芯片也要重新算 memory footprint。Kimi AttnRes（§A 资料 13）是另一条并行路线，mHC 是 DeepSeek 自家延展
    - **精读**：Abstract + Figure 1 对比（Residual / HC / mHC 三个残差范式）+ §3 流形约束的数学 + §5 工程优化段
    - **时间**：**2h**
    - **配读**：Hyper-Connections (HC) 原始论文作为背景（arXiv 搜 "Hyper-Connections DeepSeek"，若 2025 年发表）
    - **补记**：这篇是上次 agent 搜到了但**误判成非 DeepSeek** 的论文。用户查证截图显示通讯作者邮箱 `xie.zhenda@deepseek.com` + 抬头 DeepSeek logo，确认 DeepSeek-AI 官方出品

## 4. 自测题（学完要能 5 分钟白板回答）

直接映射 [common_problems.md](../面试准备/common_problems.md)（⭐ = 核心必答）：

### 架构类

- ⭐ **MLA 相对 MHA / GQA 的 KV 压缩比是多少？数学推导** —— 用任务 1 的计算器讲
- ⭐ **MLA 的 "absorbed weight" 推理技巧是什么？** —— 为什么推理不用显式重构 K/V
- ⭐ **DeepSeekMoE fine-grained + shared 相对 Mixtral top-2 的差异和动机**
- ⭐ **DSV3 的 auxiliary-loss-free 负载均衡怎么做？训练目标不污染吗？**
- **Llama-4 iRoPE 相对普通 RoPE 有什么改动？**（面试听过就答得上）—— RoPE:NoPE = 3:1 交错，NoPE 层"无位置编码"支持外推
- **NSA / MoBA / DSA 三种 2025 稀疏 attention 思路的对比**（硬件对齐块 / MoE-style gating / MLA 上叠 top-k 索引器）
- ⭐ **DSA (DeepSeek-V3.2) 相对 MLA 多做了什么？对推理 kernel 形状有什么改变？** —— 闪电索引器 + top-k=2048 token 选择器，复杂度 O(L²) → O(L·k)
- ⭐ **Engram 是什么？为什么它是"正交于 MoE 的第二条稀疏性轴"？** —— 静态 N-gram 记忆 lookup，可 offload 到 host RAM；U-型 scaling law（20-25% 参数做 memory 最优）
- **Kimi Linear / KDA 混合 3:1（KDA:MLA）怎么做到 KV -75%？** —— 3/4 层是线性 attention 不存 KV，只 1/4 层 MLA
- **Qwen3-Next 的 Gated DeltaNet + Gated Attention 混合为什么选 3:1？** —— 稀疏 MoE + 大部分层 O(N) 线性、关键层保留 softmax 表达力
- **Attention Residuals 相对标准残差连接解决什么问题？对 activation memory 有什么影响？** —— 跨深度做 softmax attention 替代累加，forward 要保留层间激活做 depth-attention
- **mHC (Manifold-Constrained Hyper-Connections) 相对 HC / 标准残差的改进是什么？** —— HC 扩残差宽度 + 多连接，但破坏 identity mapping 导致训练不稳；mHC 把残差空间投影到流形上恢复 identity mapping + 做访存优化

### 位置编码类

- ⭐ **RoPE 的旋转公式（白板推导 2D 情况）**
- ⭐ **YaRN 解决的是什么问题？NTK-by-parts 为什么比 Position Interpolation 好？**
- ⭐ **Qwen2.5-VL M-RoPE 三维分频怎么分配 embedding dim？时间和空间怎么共存？**

- ⭐ **Weight only int4 和 FP8 量化的应用场景差异**
- ⭐ **为什么只量化 weight，不量化 activation？**
- ⭐ **动态量化 vs 静态量化的区别、各自适用场景**
- ⭐ **NVFP4 / MXFP4 相对传统 int4 的核心差别是什么？**（微缩放块 + scale 单独一层）
- **NVFP4 能不能用来预训练？**（2025 新证实：能，B 级 LLM 可预训练到 multi-trillion token，见资料 30b）
- ⭐ **精度下降时怎么找精度异常点？**（用 common_problems 原题）
