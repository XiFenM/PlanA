# 英语复习与制卡：PlanA 适配

本文只定义英语子轨道的路径、事实职责和授权边界。英语反馈、结构化过程记录和 Markji 暂存卡片的行为
分别由中央 `english-coach`、`study-log` 与 `memo-cards` Skill 拥有；本文不保存第二份 prompt、模板、
卡片质量规则或自动执行流程。

## 1. 三类职责

| 职责 | PlanA 位置 | 所有者与边界 |
| --- | --- | --- |
| 英语计划与进度 | [学习指引.md](学习指引.md)、[进度.md](进度.md) | 保存目标、训练节奏和用户确认的进度；不保存逐轮 coaching 行为 |
| 结构化过程记录 | `英语/log/` | 由 `study-log` 按用户明确请求生成；只保留误解、纠错、高价值问题和关键转折 |
| Markji 暂存卡片 | `英语/cards/` | 由 `memo-cards` 按用户明确制卡请求预览或发布；生成本地受管 Markdown 与 XLSX，用户明确要求时也可通过官方 API 上传 |

原始可见文本对话默认不保存。用户明确要求保存原文时，由 `study-log` 单独确认边界与隐私，保存到仓库内同级 `英语/log-raw/`，与结构化文件同名配对。原文不作为英语回顾或制卡的输入，保存不自动授权 Git 提交或公开。

## 2. 显式交接，不自动串联

1. `english-coach` 普通随行反馈和英语回顾默认只存在于当前对话，保持零写入。
2. 用户明确要求整理本次学习过程时，才交给 `study-log`，并由本轮请求选择具体会话、边界和精确目标。
3. 用户明确要求制卡时，才让 `memo-cards` 消费已获准的 structured log 或当前明确材料。日志生成成功
   不等于授权制卡，制卡成功也不等于授权导入 Markji、提交或推送。
4. 更新已有记录或受管卡片前先展示精确 diff；legacy 接管、人工漂移、来源变化、模板升级、删除、冲突
   或跨文件刷新都必须重新确认。

可以直接用自然语言表达意图，例如“把刚才确认过的英语纠错整理成学习记录”或“预览今天值得做成
墨墨卡片的内容”。也可以用一句话同时提出，例如“英语收尾：整理今天的记录并预览卡片”——这就是对两项
操作的明确请求，按顺序执行，不再逐项追问；写入和覆盖仍按各 Skill 的预览与确认规则。不要使用快捷命令，
也不要把学习收尾当作隐式触发。

## 3. 素材与数量

正式卡片只接收稳定、可追溯、已经核验且值得反复强化的内容：真实语言错误、主动产出表达、稳定辨析、
技术语块或成熟技术结论。raw 对话、`[遗留]`、猜测、冲突和未核验时效事实只进入 blocked preview，
不直接制卡。

英语卡片默认精选。完成准入、原子化与去重后，每个学习日以新增 **8–12 张逻辑卡**作为软目标：

- 少于 8 张时按实际质量产出，不凑数；
- 超过 12 张时，候选先按等级（A 在 B 前）再按重要性排序，超出部分列为延后并说明原因（A 级也不例外），
  不静默丢弃，由用户决定是否完整转换；
- 用户明确要求完整转换时，输出全部通过质量门槛且完成去重的候选；
- 刷新既有逻辑卡不计入新增数量。

这个数量只帮助控制复习负担，不是硬上限，也不构成创建、覆盖或导入授权。

## 4. 受管上下文与历史产物

version 2 配置把 `英语/log/` 声明为 `study-log` 的 structured 目标，并让 `english-coach`、`memo-cards`
各自显式声明同一 tracked collection。该 handoff 只允许定位 Git-tracked UTF-8 成员；未跟踪文件不会进入
materialized allowlist，也不会因为位于同一目录而获得读取权限。

`英语/cards/` 是 `memo-cards` 的输出和 inventory root。现有无 manifest 的日志和卡片保持 legacy，
不批量重写；只有用户明确刷新某个目标时，才预览 adoption diff。中央 Skill 的 Markji 3.8+ 模板 registry
和兼容合同是现役事实源，本仓库不再维护平行的行为 prompt 或模板规则。

## 5. Markji 手工边界

`memo-cards` 默认在本仓库生成可审阅的受管 Markdown 与每模板一个 XLSX，由用户在 Markji 中逐模板导入；
用户明确要求时，也可以通过官方 API 把卡片追加到已有自建牌组的指定章节。Skill 不上传媒体、不覆盖或删除
远端卡片，也不声称改变远端卡片状态。
