## 5. AMD 单卡：复用两个实验主题

### 5.1 异步拷贝与生命周期

接续已有 H2D／D2H 项目，使用一个小型“输入拷贝 → 计算 → 输出拷贝”程序比较同步基线与依赖正确的异步路径。

关注四个问题：

1. Host 提交返回和设备完成分别发生在何时？
2. pinned Host 内存、Stream／Event 如何建立生产与消费依赖？
3. CPU 何时可以读取输出，设备与 Host 分配何时可以复用？
4. 时间线上是否存在重叠，以及该工作负载是否因此受益？

完成依据是正确性、明确的生命周期、可解释的时间线和有条件的性能结论；不要求异步版本必须加速。由 Agent 主导与维护相称的测试和测量方法，学习者负责约定中的核心实现、运行前预测与结果解释，具体分工在练习约定中说明。

### 5.2 小模型服务性能与量化

选择所租 GPU 和软件版本已经支持、能够运行 BF16 与一种选定量化方案的小模型，复用 W4 单元二、三：

- 建立固定模型／revision、输入输出、精度和软件配置的 BF16 服务基线。
- 单独改变一项调度参数，观察 TTFT、TPOT／ITL、吞吐的取舍。
- 另做量化／BF16 对照，保留精度、显存和性能结果。
- 先选少量代表性负载；只在观测支持进一步追查时增加配置。
- 记录预热、重复、运行顺序和正确性判据；样本不足时不作稳健尾延迟结论。
- profile 用于归因，干净计时用于服务性能；已有历史数据只有在口径完整且匹配时才复用。

租用前准备输入与脚本，先核对软件支持及 profiler 能力。可按两个短窗口组织：一次核验环境与异步机制，一次完成模型对照；具体时长和费用在实际使用前确定。环境不兼容时优先收缩到可运行主题，按原计划受限环境分支继续，并保留未取得的实测证据。

## 6. 公司多机多卡：一个跨节点推理主案例

建议主问题：**同一真实负载跨机后，执行时间增加主要来自数据传输、rank 较晚到达，还是 Host／执行队列？**

优先复用已有 GLM TP8 与 allreduce 等待归因；成本过高时选择公司已经支持的较小模型。首轮以两机为主，四机仅在两机结论说明有必要时用于扩展验证，不以用满 32 卡作为目标。

### 6.1 对照选择

| 实际支持情况 | 首轮对照 | 可以判断什么 |
| --- | --- | --- |
| 同一模型、相同总卡数与并行度可跨不同节点布置 | 例如单机 8 卡与双机各 4 卡，均 TP8 | 在其他条件一致时分析拓扑布置影响；先确认该 rank 布置受支持 |
| 仅能比较不同卡数或并行度 | 例如单机 TP8 与双机 TP16 | 分析扩展性；计算资源、张量切分及拓扑同时变化，不能将全部差异归因于网络 |
| 跨机主要为 DP 多副本 | 固定请求负载与分发策略，比较副本数、排队与吞吐 | 证明副本扩展与负载分配能力，不包装为跨节点 TP 通信优化 |

跨机形态、实际 TCP／RDMA／其他传输与模型适配范围由环境记录确认，不由机器数量推断。

### 6.2 实施步骤

1. **建立基线**：固定版本、模型、精度、输入输出、并发和并行配置，先验证正确性，再记录端到端结果。
2. **观察与归因**：采集一个短时间窗口；如需分离框架调度与通信路径，提取一个主要 collective，按真实 shape、dtype、rank 数和消息大小做匹配微基准。
3. **一个调整或反证**：根据证据选择一个已有配置或窄范围实现变化，例如 Host 准备、Padding、提交次数或执行依赖；复验正确性和性能，不预设固定加速比例。
4. **有条件的负例**：若有适合的测试环境，可引入一次有界 rank 延迟，观察实际等待／超时行为；不追加自动恢复系统或破坏性网络注入。
5. **停止扩展**：已有证据能回答主问题即结束本轮；如果需要从零实现分布式 backend、PD 或 EP，转为独立候选，不并入当前小案例。

首轮可参考 2–3 次短会话、约 4–6 小时有效工作，目的仅是取得基线并选出值得追查的问题；不承诺完整案例在此时限内完成，也不把预计用时记为实际工时。

### 6.3 测量与产物

- collective 调用区间可能包含排队、到达偏斜和同步等待，不能直接命名为网络传输时间。
- 不直接相减不同主机的原始时间戳。端到端请求由同一客户端计时；各 rank 通过请求、迭代和 collective 序号关联，本地计时与跨机时间对齐的依据分别记录。
- 微基准的统一入口／屏障会改变真实服务的到达偏斜，其结果用于诊断，不替代真实负载结果。
- 请求成功不等于输出正确。采用事先明确的模型／算子判据；浮点归约顺序变化与真正的实现错误分别判断。
- 保留负结果与未解释波动，不用小规模结果推断更大集群性能。

本案例只需形成一组相互关联的产物：**配置与拓扑说明、可重复运行的方法、带条件的结果表、支撑归因的时间线**。这些是同一个案例的组成部分，不要求另写四份报告。

| 内容 | 采用的证据 | 保留的边界 |
| --- | --- | --- |
| 跨设备／跨节点执行、正确性、通信归因 | 公司真实实验 | 只支持实际运行的后端、拓扑和负载 |
| HIP 内存、异步执行与 profiling | AMD 单卡真实实验 | 不覆盖多卡通信与节点间拓扑 |
| RCCL API、调用约束与实现路径 | 固定版本官方文档、源码与测试分析 | 不将编译、单 rank、mock 或接口类比视为 AMD 多卡验证 |
| RCCL 多卡性能、AMD 网络与故障行为 | 本轮无对应设备实证 | 明确保留未覆盖，不设为计划完成前提 |

完成迁移讨论需要解释“哪些语义可对应、哪些条件不同、哪些需要重新验证”，而非仅列 API 对照表。公司已有 PD／EP 路径时可以选择现成路径验证；没有时不要求新建，相关岗位实施缺口继续保留。

### 7.2 先核已有素材，再决定新增贡献

优先核对[能力与经历总表](../面试准备/自我准备/能力与经历总表.md)及[项目档案](../面试准备/自我准备/projects/README.md)：

- GLM 最终服务指标与算子／任务评测分别取材，Host 插桩结果不换算成服务加速倍数。
- allreduce 等待归因可证明跨层诊断，不自动推导通信算法或网络带宽优化。
- D2H 的生命周期回归、不同并发正负结果与持续负载缺口保持各自边界。
- 训练通信项目先恢复具体 collective、配置、同步契约与验证记录，不恢复尚未确认的宽泛主张。
- [2025 年工作总结](../面试准备/工作经历总结/2025年度个人年终总结.md)已有上游协作线索，先确认 PR／issue、本人角色、测试与状态；旧诊断中的“无公开 upstream”不作为新的事实结论。

确有缺口时，从 W4 起只选一个可独立验证的上游问题，按[开源推进节奏](#early-contribution)形成最小复现、测试、窄修复或文档澄清。采用前核对当前源码与已有 issue／PR，避免重复工作。沿用原计划 W6 的“可公开评审工件”标准，该标准可以提前达到；W6 接续已有贡献，不是统一启动点。不以 merge 为硬条件，也不未经实测提交硬件性能结论。

## 8. 英语口语：在既有英语与 Mock 时间内增强

Mock 指模拟面试，由面试官式提问、学习者口头回答、连续追问、反馈与针对性复测组成。它用于检查技术解释和交流表现；英语表达按当次安排穿插，模拟面试不默认全部使用英语。

用户于 2026-11-10 明确场次分配，唯一计数规则见[原计划 §5.3 的正式 Mock 总表](高级AI框架开发工程师-八周证据冲刺计划.md#mock-schedule)：W4 计第一场推理 Mock，W7 保留一场训练 Mock，W8 只补第二场推理 Mock 与必要复测。W5／W6 的项目口述与英文迁移陈述是练习或局部复测，正式追问并入 W8；复测沿用原场证据，不增加固定正式场次。

短期目标是用英语讲清真实项目、理解常见追问，并在卡住时澄清或换一种表达。现有档案不替代近期口语基线，语言表现与技术理解分开评价。

### 8.1 时间分配

在[原计划 §5 的英语与 Mock 时段](高级AI框架开发工程师-八周证据冲刺计划.md#52-每个日历周投入模板)内，可采用 **5 次 × 15 分钟主动表达 + 45 分钟中英文综合练习／Mock**。

45 分钟在对应 W4／W7／W8 正式场次时并入该场；其他日历周用于普通追问练习或针对性复测，不按每周模板新增正式 Mock。正式场次时长或当周安排不适合该模板时，在同一总预算内调整，不要求额外凑满五次。

旧英语长期计划的每日 60–75 分钟不与本方案叠加。

### 8.2 第一轮练习安排

以下是四个练习阶段，供约四个日历周后复查；不是新增四个有效周，也不与 W4–W7 强制逐一对应。

| 阶段 | 主题 | 观察目标 |
| --- | --- | --- |
| 一 | 一次真实口语基线、自我介绍与 GLM 概述 | 说清问题、职责和结果，能给短版与展开版 |
| 二 | H2D 异常排查 | 讲清现象、假设、验证、根因和修复，接住原因追问 |
| 三 | D2H、性能取舍与 AMD 迁移 | 解释依赖、负结果与证据边界；尚未实施的实验按计划表达 |
| 四 | 随机追问与综合练习 | 被打断后续接、听不清时澄清、换问法后仍能回答 |

单次采用“听问题 → 关键词组织 → 主动回答与追问 → 针对性反馈 → 换问法表达”，隔次再无稿复述。具体语言支架、纠错与节奏由中央 english-coach 执行，本文件只保存目标与排期，不另设 coaching prompt。

观察是否答到问题、职责与因果是否清楚、卡住后能否继续、换条件后能否表达；不以语速或背稿熟练度单独判断。转写可用于结构与用词检查，发音、重音与停顿需要原音频。练习记录、制卡和音频归档仍由用户按需请求，不作为默认每次产出。

## 9. 后续每周开启时的执行方式

用户要求开启某一周时，按以下顺序进行；同周后续 Lesson 开课时复用已经确认的选择，只核对变化：

1. **读取原计划与本方案**：读取原计划对应周的目标、范围、验收与预算，本方案的周次映射和相关硬件分支，以及既有周进度和唯一学习断点。
2. **对照已有证据**：从对应项目档案与 Lesson evidence 判断哪些已经覆盖、哪些是素材待核、哪些确需新增理解或实测。原简历、旧诊断和市场研究不覆盖后续本人确认及实际验证。
3. **选择一个主要增量并接续同一开源题**：在该周原目标内选定主案例、数据／源码版本和实验环境；从 W4 起另核对固定开源时段的下一小步。说明两者是否复用产物、如何使用原预算，以及哪些候选本周不展开，不把开源时段变成每周新开项目。
4. **给出整合后的开课安排**：一起说明原目标、采用的增强、预计资源、证据类型和适用完成条件；涉及 Mock 时先按原计划总表核对已完成场次与未过项，只安排本阶段对应场次及必要复测。技术教学继续按 guide-learning，英语反馈按 english-coach。已明确授权开启该周时，不重复询问是否应用本方案；具体 Lesson 与正式练习按既有流程办理。
5. **继续单处记录**：实际约定和结果写入原有周进度／Lesson，实际工时写入对应模块；精确下一动作由唯一断点维护。本文不新增完成勾选表。
6. **周末或语义结束时复核**：说明已形成的证据、剩余缺口和下一周候选。新硬件或新的面试反馈可以改变后续选材；若扩大既定目标、预算或验收门，先明确变化，不把新建议自动变成任务。

开周简要说明只需涵盖：**原目标、复用证据、一个增强重点、环境分支、完成依据**。不需要另建开周计划模板或重复总结文件。
