#### 任务与交付

实现一个 C++20 的 `SingleSlot` 小类：只服务一个生产线程、一个消费线程，主线程负责关闭，并在相关线程结束后才销毁槽对象。槽内一次保存一批四个 `int32_t` 元素；本练习只传入合法长度与取值范围的数据，不考动态容量和通用参数校验。

学习者只填写 `slot.hpp` 中的核心状态、同步与三个方法。导师先提供必要头文件、公共接口与未实现占位，不给出核心状态选择或同步逻辑；线程启动、join、测试输入、回调和运行脚本由导师维护。预测与结果解释在对话中完成，不要求额外撰写分析文章。

```cpp
using Batch = std::vector<std::int32_t>;
using Reader = std::function<void(const Batch&)>;
bool publish(const Batch& batch);
bool consume(const Reader& reader);
void close();
```

这些方法属于 `SingleSlot`；`Reader` 表示由测试提供的读取函数，学习者只需在约定的时机调用它，不需要实现通用回调封装。测试保证输入 batch 在 publish 调用期间保持有效、没有其他线程修改它；reader 对象在 consume 调用期间也保持有效。

| 方法 | 公开行为与完成边界 |
|---|---|
| `publish(batch)` | 等待槽可接收后保存本批，接受成功返回 true；成功后调用者可以释放或修改原输入，槽仍保存本批数据。关闭状态生效后拒绝新批并返回 false；正在等空槽的发布也能因关闭结束等待。publish 与 close 并发时，以同锁保护下的实际接收／关闭顺序决定结果，不按两个调用开始的墙钟顺序判断。 |
| `consume(reader)` | 等待一批可消费数据，或者等待结束条件。取得本批后，让 reader 同步借用槽内数据；reader 返回前，这批数据及其存储保持有效，下一批不能改变它。处理一批后返回 true；关闭且没有剩余批次时返回 false，不再调用 reader。 |
| `close()` | 停止接受新批，并使相关等待者能够检查关闭状态。已经接受的批次仍按约定消费；正在发生的借用保持到 reader 返回。重复 close 安全。close 不承诺调用时消费已经结束，也不要求立即返回；允许因取得状态锁而等待。最终线程等待与槽对象销毁由主线程安排。 |

reader 在本练习中正常返回、不抛异常、不重入 SingleSlot、不保存传入数据的引用或指针，也不派生异步读取；因此 reader 返回可作为本次借用的完成边界。核心实现可以选择全程持锁读取，或用占用状态允许锁外读取；只要满足公开契约，不强制某一种方案。测试不会要求必须锁外执行回调，也不会把关闭延迟当成性能门槛。
