## W4-U1-P1：MatMul 模型与实测对照

- **版本**：1。
- **所属 Lesson**：[`plana-jd-w4-validation-interview`](../W4.md#lesson-plana-jd-w4-validation-interview)。
- **接受时间**：2026-11-10。用户确认按所提范围准备测试包，要求准备并检查通过后通知，再由本人租用 GPU。
- **目标与缺口**：主要补足 `w4-u1-o3-evidence` 的同案例真实数据与模型对照；复用已通过的理解与迁移证据，不追加核心代码实现能力或第二个算子。
- **任务**：在同一 GPU、同一 PyTorch 后端下执行 `C=A@B`，K=5120、N=25600，M=128／256。A/B/C 为 BF16，按已核对的 FP32 计算／累加条件建模；实际指令未检查时不声称已证明指令路径。
- **输入**：固定种子 20261110；A 由标准正态样本除以 √K 后转 BF16，B 由标准正态样本转 BF16；A128 取 A256 前 128 行，B 共享，均为连续行主序。无旧 C 读取、bias、激活、通信或量化。
- **交付**：学习者在对话中提交测量前的预测、执行测试包并返回原始结果、解释结果及证据边界。Agent 提供和维护方法、脚本、测试与核验说明。

### 验收项

1. **环境与预测（P1）**：设备、分区／共享条件、软件版本与精度设置可追溯；正式测量前有学习者提出的、带机制依据和成立条件的预测。环境或精度无法核对时先停止对应实测，不归因为学习者未通过。
2. **正确性（P2）**：从实际 BF16 输入构造 IEEE FP32 参考，计时外比较全输出。输出和参考均有限；相对 L2 误差 `≤0.01`，最大绝对误差 `≤0.01×max(abs(Cref))+0.001`，两项同时通过。这是本次合成输入的工程容差，不是逐位相等或通用误差保证。
3. **采样与保真（P3）**：输入输出预分配，每个 shape 预热 20 次；正式 5 轮，每轮每个 shape 连续调用 20 次、轮间交替顺序。保存设备事件总时间、调用数及摊销时间，统计每个 shape 的 5 个区间均值的 median/min/max；不将其当作 100 个独立样本，不将含可能提交间隙的区间称为纯 kernel 时间。正确性失败保留数据但停止有效性能汇总。
4. **模型对照（P4）**：学习者沿同一案例解释 F、Q₀、AI、资源条件与性能上界／时间下界、实测时间、有效吞吐和模型比率。不同 M 对应不同工作量，不把耗时比称为同任务优化加速比。实际流量缺失保持 `null`，Q₀/t 明确为模型值。
5. **结论边界（P5）**：区分结果、候选机制和未知；每个成功的性能主张有至少一个由证据排除的假设或负结果，未解偏差另行保留。没有成功性能主张时可如实给出证据不足，不强行制造异常。预测与结果不一致本身不算失败，不要求固定加速幅度或 Roofline 达成率。

运行前的支持／否定／证据不足判据和方法理由见[测试包说明](../../../推理框架/实践/W4-U1/README.md#4-固定方法与指标含义)。脚本不替代学习者的结果解释。

### 整周验收中的 PD 拆分书面首答（2026-11-22）

学习者自选了模型可放入单卡、两台机器各一张卡的场景，假设高峰时长 prompt 的 prefill 会干扰正在出词的请求。对照组在两台机器上各跑一个完整实例，拆分组一台做 prefill、一台做 decode，两组按相同到达时间重放同一批请求。学习者用客户端相邻输出 token 间隔的 P99（ms）衡量卡顿。比较时计入跨机 KV 传输的影响，只有停顿改善、TTFT 和输出吞吐也满足要求时才采用拆分。

### 整周验收中的首字等待口述（2026-11-22）

学习者在实时口述中将首字等待对应到 TTFT，解释了分离 prefill 和 decode 可以减轻两者争用，也提出高批量下 decode 本身变慢的可能。首答由首字慢推断 prefill 压力大、拆分不值得。导师提醒，调度排队也会拉长首字等待，并追问如何用部署对照验证这个判断。

<a id="w4-week-pd-oral-followup-20261122"></a>

学习者随后在实时语音中沿用自己选定的场景。模型可放在单卡上，两台机器各用一张卡。对照组的两台机器各运行一个完整实例，实验组的一台负责 prefill，另一台负责 decode。主指标是客户端从发出请求到收到第一个生成 token 的时间，以毫秒计。学习者提出在服务端分别计量排队和 prefill 计算耗时，只有客户端 TTFT 明显缩短、TPOT 和 ITL 仍满足服务要求，才选择拆分。同一批请求按相同到达时刻回放的条件见[此前的书面首答](#w4-week-pd-written-opening-20261122)。
