# 月底晋级评审（Monthly Promotion Review）

> **使用方式**：每月最后一个周日，开一个**全新的 AI 会话**，切到仓库根目录，发这句话：
>
> > 请严格按 `计划/月底晋级评审.md` 的规范，对本月（YYYY-MM）做一次晋级评审。
>
> 与 [周更流程.md](周更流程.md) 配对——周更负责**资料流入**（写周报，不动稳定版），本流程负责**资料沉淀**（把高分条目升入稳定版 `学习指引.md`）。

---

## 1. 这是什么 / 为什么独立成文

[周更流程.md §8](周更流程.md) 已写明晋级机制的骨架；本文件把它扩成一份完整 SOP，原因有二：

- **节奏不同**：周更靠 agent 跑搜索 + 写稿，是"流入"；月底评审纯人工读 + 取舍 + 编辑，是"沉淀"。两件事用同一份文档容易互相干扰。
- **判据更重**：晋级一旦做了，会污染稳定课程的优先级排布。需要一套"两周后还重要吗"级别的冷判据，比周报入选标准严格。

**核心边界**：
- 周更**绝不**动 `学习指引.md`。
- 月底评审**绝不**重新做搜索（如发现遗漏，回到周更流程补一份周报，不在本流程里临时搜）。
- 评审**只对**本月已生成的周报里 §晋级候选 节列出的条目进行处理。

---

## 2. 触发条件

| 条件 | 取值 |
|---|---|
| 频率 | 每月最后一个周日 |
| 前置 | 本月至少有 3 份周报（< 3 跳过本月，下月再办）|
| 例外 | 出现"行业级事件"（一次性砸出整套架构/库，如 DeepSeek V4 周）时，可在事件发生 2 周后单独触发一次"专题评审"，无需等月底 |
| 单次耗时 | 60–90 min（含读 4 份周报 + 实际编辑）|

---

## 3. 评审判据（Rubric）

每条候选过 5 道关。**≥ 3 道 yes 才进入建议晋级清单**；4–5 道 yes 是强建议；≤ 2 道 yes 建议拒绝。评分只生成建议，最终决定由用户拍板；所有条目均保留在原周报作历史快照。

| # | 关键问题 | 关注的失败模式 |
|---|---|---|
| Q1 | **两周后还重要吗？** | 拒绝热点疲劳——发布周大家都在转，但 2 周后已被替代版本盖过的，不晋级 |
| Q2 | **会被面试问到吗？** | 拒绝"看起来很酷但面试不会问"的研究向条目（除非你打算用作博客素材） |
| Q3 | **在板块当前焦点窗口里吗？** | 拒绝"距离当前主攻板块超过 2 个板块"的内容（与周更同源标准） |
| Q4 | **有信息增量吗？** | 拒绝纯综述/转述——必须给出**新数据 / 新设计 / 新接口**的至少一项 |
| Q5 | **它替代或回答了某个 TODO？** | 加分项——明确补正稳定版指引里某个 `🟡 待补` / `TODO` 注解的，几乎自动晋级 |

**特别红线**：

- 🚫 **3 个月内同一主题已晋级 ≥ 2 条** → 暂停接收，避免该主题膨胀（除非新条目明确替代旧条目）
- 🚫 **作者 affiliation 未经验证** → 退回周报，要求在周更流程里用作者主页、机构主页或论文原文补验证后再决定；月底评审本身不临时搜索
- 🚫 **链接已 404 / 仓库已 archive** → 标记为不晋级，原周报条目末尾追加 "（链接已失效，YYYY-MM-DD）"

---

## 4. 准备工作（< 15 min）

按顺序做完才进入实操：

1. `ls 计划/周报/` 拿到本月的周报清单
2. 依次打开本月每份周报，**只读 §晋级候选 节**——其他节是历史快照，不在本流程处理
3. 把所有候选项汇总到一张临时表（脑子里或临时草稿），列：`来源周报 | 标题 | 建议归属 | 推荐分级`
4. 对照 [计划/主计划.md](主计划.md) 当前周次，记下"现在主攻什么板块"——这影响 Q3 判据
5. 扫一眼 [计划/进度总表.md](进度总表.md)，看哪些板块进度严重落后——落后板块**收紧**晋级（避免清单膨胀加重负担），领先板块可适度放宽

## 5. 实操步骤（每条候选独立处理）

### Step 1：过 Rubric

按 §3 的 5 道关打分，得到**建议晋级 / 建议拒绝 / 建议待定**。先完成全部候选评分，展示清单、每条得分和理由，**等用户确认后才编辑文件**。

- 用户确认晋级 → 进 Step 2
- 用户确认拒绝 → 进 Step 6（反向同步，标记拒绝原因）
- 用户确认待定 → 进 Step 6（只追加待定状态，不动稳定版）

### Step 2：定位插入点

在目标 `{板块}/学习指引.md` 中找到该候选**应该插入的小节**。判断要点：

- 该小节已有同主题条目？→ 选 §5b 替代或并列
- 该小节是空白领域？→ 选 §5a 新增
- 该候选跨多个小节？→ **主条目放最相关的一节**，其他节用 "（详见 §X 资料 N）" 交叉链接，**不重复列内容**

### Step 3a：新增条目

按现有格式插入新行：

```markdown
N. 🟥/🟨/🟩 [⭐/⭐⭐] **<标题>** 🆕
    - 链接：<url>
    - **为什么读**：<2-3 句，解释面试/学习价值>
    - **精读 / 略读 / 跳过**：<时间预算 + 重点段落>
    - **晋级自**：周报 [YYYY-Wxx](../计划/周报/YYYY-Wxx.md)
```

**编号规则**：保留现有编号顺序，新条目用**字母后缀**（如已有资料 19，新增插在它后面就是 `19a`、`19b`）。**绝不**对老条目重新编号——交叉引用全靠编号锚定。

### Step 3b：替代老条目

老条目**保留 ID 位置**，但加替代注解。例如 EAGLE-2 → EAGLE-3：

```markdown
12. 🟥 **EAGLE-3** ⭐ （替代自 EAGLE-2，2026-05-XX）
    - 链接：<新链接>
    - ...
```

老条目不删——历史快照保持完整。如果信息量大，可在条目末尾追加 "_老版本说明：EAGLE-2 链接保留在周报 [2026-Wxx](...)_"。

### Step 4：更新对应 `进度.md`

如果晋级的是 🟥 必读资料，对应板块的 `进度.md` 也必须加一行：

- `📊 汇总` 表的 `🟥 必读资料 总数` +1
- `📖 必读资料` 节的对应章节加一行（带 ⬜ 状态、时间预算、空"开始/完成"列）
- 如果是 🟨 / 🟩，则只更新 `📂 选读/背景` 节对应章节的"🟨 数 / 🟩 数 / 累计预算"列

### Step 5：写 Changelog

在该 `学习指引.md` **顶部**找到 `## Changelog` 节（没有就新建一节，紧跟开篇说明之后）。追加一行：

```markdown
- 2026-05-31 (W22 月底)：新增 §B 资料 19c "FlashInfer 论文" 🟥 ⭐，晋级自周报 2026-W18
- 2026-05-31 (W22 月底)：§E 资料 12 EAGLE-2 → EAGLE-3 替代，晋级自周报 2026-W20
```

格式硬约束：日期 + 周次 + 一句话变更 + 来源周报。

### Step 6：反向同步到周报

无论晋级与否，回到原周报，在该候选条目末尾追加一行注解：

- 晋级：`> **状态**：✅ 已晋级到 [推理框架/学习指引.md §B §19c](../../推理框架/学习指引.md)，2026-05-31`
- 拒绝：`> **状态**：⏭ 未晋级（理由：Q2 失败——研究向，面试不会问），2026-05-31`
- 待定：`> **状态**：🔖 留到下月评审，2026-05-31`

**永远不删周报里的老条目**——它是当时的历史快照。

---

## 6. 全部处理完后（< 5 min）

1. `git status` 检查改动文件，确认只动了：① 已晋级条目对应的 `{板块}/学习指引.md` ② 必要的 `{板块}/进度.md` ③ 候选条目所在的**本月各来源周报**（仅追加状态注解）④ `计划/进度总表.md` 的月度复盘日志。**不应**改动主计划、周更流程或本 SOP。
2. 在 [计划/进度总表.md](进度总表.md) 末尾的"周末 / 月度复盘日志"节追加一行：`YYYY-MM 月底评审：晋级 N 条 / 拒绝 M 条 / 待定 K 条`
3. Commit message 模板：

```
月底晋级评审 YYYY-MM：晋级 N 条

晋级：
- {学习指引文件}: {新条目编号} {标题}
- ...

替代：
- {学习指引文件}: {ID} {老→新}

来源：周报 W17–W20
```

## 7. 元规则 / 防腐

- **拒绝堆数量**：一个月晋级 0–5 条是正常区间；> 8 条说明判据松了，下月收紧
- **允许跳月**：本月没好货就诚实跳过，不为"养成习惯"硬凑
- **怀疑就拒**：拿不准的不晋级——晋级了再撤回的成本远高于"留在周报里下月再看"
- **替代不删**：老条目永远保留 ID 位置 + 内容，只加注解。删除会破坏交叉引用
- **不在评审中搜资料**：发现遗漏 → 回头补一份周报 → 下月一并评审
- **晋级日期定锚**：用月底那天的日期做 Changelog 锚定，不用候选条目自己的发布日

## 10. 与周更流程的边界

| 维度 | 周更流程（[周更流程.md](周更流程.md)）| 月底晋级评审（本文件）|
|---|---|---|
| 频率 | 每周日 | 每月最后一个周日 |
| 触发主语 | "本周新出了什么？" | "本月哪些值得长期保留？" |
| 主要工具 | 互联网搜索 / 网页读取 / 子代理并行 | 阅读 + 编辑（不联网）|
| 改动 `学习指引.md` | ❌ 永不 | ✅ 主战场 |
| 改动 `进度.md` | ❌ 永不 | ✅ 必要时 |
| 写新文件 | 周报 | （不写，只编辑）|
| 关注的失败模式 | 漏掉新资料 | 让稳定版被噪声污染 |

两者通过 §晋级候选 节解耦——周报负责提名，月评负责裁决。
