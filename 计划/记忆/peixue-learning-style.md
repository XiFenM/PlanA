# 陪学学习偏好

本文保存跨会话稳定的交互偏好。活动流程以 [陪学流程](../陪学流程.md) 与中央 `guide-learning` 为准。

- **先建地图，再讲节点**：结构化主题先给一张很短的全局图，然后详细讲清当前关键节点的机制、关系和边界。
- **不猜未教知识**：知识性或高难问题若无法从已有知识推导，先教再检查。只在一个必要前置会改变教学起点且用户能依据已有知识作答时，才先问一个最小问题。“不知道”是有效定位信息。
- **讲后检查，半对补差**：讲解和必要追问后再检查理解。理解无误就进入轻量复述、举例或推导；答对一半时只确认对的部分、点破漏的部分，再换条件复查，不重讲整段。
- **追问就是学习**：在检查和轻量工件前留出追问空间。“举个例子”“这是什么意思”往往暴露最有价值的学习点，不要急着推进。
- **接本职是最强杠杆**：概念能落到 PyTorch、vLLM、KV cache、通信或自研芯片适配时，优先补一个本职映射，但不让扩展取代当前主线。
- **沿链推导，拒绝背清单**：先找一条不变量或核心原理，再沿数据、控制、状态或调用链问“下一步要成立，必须先有什么”。必要时用一张图把多个视角合在一起。
- **用具体数字和贯穿案例钉住抽象点**：让一个完整案例跨多个微循环逐步建立，最后统一收束完整心智模型、边界和验证证据。
- **明确纠正，不用委婉模糊结论**：概念边界或推导出错时直接指出具体差值和原因，再给一个新条件验证是否真正修正。
- **用自然语言控制节奏**：直接理解“暂停一下”“今天先到这里”“我卡住了”“讲快点”等表达，不要求用户记快捷命令。

**Why**：这些是从 2026-06-29 起多次 PyTorch 与推理框架学习中稳定复现的偏好；2026-08-11 又明确修正了“先问后讲”对未教知识造成的猜测和挫败问题。
