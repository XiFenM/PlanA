# 陪学流程：AI 带着我执行每日学习

这套流程把"有计划但执行不下去"的日常学习，变成一条 **AI 全程带练** 的每日动线。核心设计原则只有一句：

> **每次「收尾」都写明断点所处的状态：资料内部保留唯一下一动作，阶段边界只记录已完成内容并等用户选下一份资料。下次「开场」先读断点，学习全程以文章结构走，学完即成文。**

它是 [主计划.md](主计划.md) 执行层的补全：主计划 / `进度.md` 负责"学什么、追踪到哪"，本流程负责"怎么坐下来、怎么不被打断带跑、怎么不忘记进度"。形态对标 [英语/review-workflow.md](../英语/review-workflow.md) 之于英语轨——一篇分步 SOP + CLAUDE.md 里一个常驻模式（`## AI 陪学模式`）。

针对三个真实痛点：

| 痛点 | 本流程的解法 |
| --- | --- |
| 工作打断 + 怠惰，难以沉浸 | 学习中的 `/暂停`-`/继续` 快照（打断成本≈0）+ `/卡住` 15 分钟再入坡道 |
| 重回学习忘了学到哪 | 断点机制（[学习断点.md](学习断点.md)）+ 开场先读断点的续接仪式 |
| 想要 AI 带着学、且学完能成文 | 带练循环「讲→问→挖→派→盯」以文章 8 段式为骨架；用户产出学习工件，AI 代笔草稿，`/成文` 完成装配 |

---

## 三阶段总览

```
开场 / 续接              学习中                       收尾
─────────              ─────────                    ─────────
读 学习断点.md      →    讲→问→挖→派→盯 循环         →    A 写 进度.md（先 diff 后确认）
读 进度总表 / 主计划       （先问后讲，每轮一个         B 覆盖 学习断点.md（自动）
给 4 行复述 + 菜单          文章子点 + 一个微动作）      C 增改文章草稿（/成文 装配）
                         /暂停·/继续 快照
                         /卡住 15 分钟小门
```

**按会话走**：一次"开始学习 … 收工"是一个会话。开场 O(1) 续接，中途随时可暂停 / 再入，收尾三处落盘把光标交给下一次。

## 文章结构 = 陪学骨架

一个"学习主题" = 一篇文章（或多节文章里的一大节，如 `1-Internal-Overview.md` 的 §1 张量）。带练每一步的产出，**就是文章对应章节的原始素材**；章节填满即成文。章节名取自 [文章模版.md](文章模版.md) /（系列总纲 [0-Index](../PyTorch/深入学习理解PyTorch/0-Index.md)）的 8 段式：

| 文章节 | 触发时机 | 陪学动作（先问后讲） | 素材落到哪 |
| --- | --- | --- | --- |
| 资料来源 | 开场 | 从 `学习指引.md` 资源确认今天读哪份一手资料 | §资料来源 |
| 先猜再学 | 进入新主题 | **先问**三类问题（工程师想懂 / 实践疑问 / 新人疑问），逼我写「我的直觉」再开讲 | §先猜再学 |
| 学习过程 | 学习中主循环 | 讲（原文转述 + 难点）→ 问（检索）→ 派（我写「思考与理解」）；随手记反直觉点 / 源码锚点 / 尚未理解 | §学习过程 |
| 读后回顾 | 主题收口 | 回到 §先猜 的直觉，标"过去的我多天真" | §读后回顾 |
| 下游透镜 | 主题收口 | 提示「过往经验」+ 构造「面试 Q&A」 | §下游透镜 |
| 思维导图总结 | `/成文` 时 | 凝练整体结构 | §思维导图 |
| 后续预告 | 收尾 | 汇总"尚未理解"+"下一节预告" | §后续预告 **＋** [学习断点.md](学习断点.md) |

> 关键耦合：**只有在已选定资料或任务的内部**，文章 `§后续预告` 才可作为续接光标。一份资料或一个阶段完结后，后续预告只是问题债务，不能自动决定下一份资料。
> **忠于原文脉络（别超前）**：学习顺序和文章生成都跟着原资料的逻辑走。例：原文「算子调度」节只点出"还有个 variable 调度"，并未展开反向图 / saved tensor——那些是后续 autograd 节的料；则 §1.3 也只到"选 kernel + 外层有个 variable 调度"为止，variable 记录什么留到 §2。
> 纯理论板块（模型理论 / Leetcode）按文章模版括注退化：源码锚点 → 论文 §X.Y；实践 → 手算 / 反例构造 / 数值验证。

## Step 1 — 开场 / 续接（修"忘了学到哪"）

我说 `开始学习` / `继续学习` / `今天学什么` 触发。AI 固定动作：

1. **先读 [学习断点.md](学习断点.md)**「当前断点」→ 先判断是「资料 / 任务内部」还是「阶段边界」，再取对应字段。
2. 读当前模块的 `进度.md`，再读 [进度总表.md](进度总表.md) + [主计划.md](主计划.md) §1（工作日 4.5h = Leetcode 45m + 精读 1.5h + 实战 2h）对齐剩余预算与节奏——**只读不改**。
3. **4 行复述**（让我秒回状态）：
   - ① 上次学什么，学到什么程度
   - ② **内部断点**：复述唯一下一动作；**阶段边界**：明确「下一资料待你决定」，不夹带候选
   - ③ 隔了几天（>1 天先给 2 句「回血复述」再继续）
   - ④ 今天可用时间与当前模块剩余预算
4. **给菜单、不独断**：
   - 内部断点：`[1] 按断点继续  [2] 我只有 X 分钟  [3] 换个子点  [4] 先回血`
   - 阶段边界：`[1] 我指定下一份资料  [2] 请帮我选取下一份学习资料  [3] 今天先不开新阶段`。只有用户明确选 `[2]` 或给出同义请求，才能推荐下一资料；推荐后仍等用户拍板。

## Step 2 — 学习中（修"打断"和"带着学"）

**讲→问→挖→派→盯** 循环，每轮一个文章子点，先问后讲：

- **讲**：贴着资料 / 文章原文讲下一子点（原文转述 + 难点拆解）。**能接本职就接**——凡概念能落到我的 PrivateUse1 / 自研后端 / 推理框架（vLLM / KV cache）日常，必接一句；这是我学得最快、最容易冒出超纲洞见的地方（实证：device 轴扩展的 runtime 成本、custom op 的 autograd 注册、version counter 当调试器，都是这么挖出来的）。
- **问**：1–2 题检索式提问，先逼我产出再纠正——对齐「先猜再学」和面试脱口而出。**难度卡在"我大概率答对一半"**：价值在确认对的那半、点破漏的那半（这是带练最有效的一拍）。
- **挖**：抛"派"**之前先留一拍让我追问**（"举个例子？""这是什么意思？"）。我的 clarifying question 往往才是最高质量的学习点——别急着推进到"派"；有疑先答透，深挖处可主动问"要不要在这开一个进阶 / 扩展块"，再回主线。
- **派**：每轮收尾给**唯一一个**动词开头的微动作，输出形式是**学习产物**——复述 / 总结 / 举例场景 / 自测答题 / 反问——**绝不让我直接写博客段落**。陪学的意义是交互式引导我学；文章由 **AI 据我的学习产物代笔**，我只在最后审稿。（如"用三句话复述 dispatch 按什么选 kernel"，而非"写 §1.3 第一段"。）
- **盯**：我走神 / 卡壳时，复述那个微动作把我拉回，不重新长篇开讲。

> `/快`：我在状态里、不想听讲解时，跳过"讲"，只保留"问 + 派"。

### 工作打断：`/暂停` … `/继续`

- `/暂停`：AI 立刻把热缓存写进 [学习断点.md](学习断点.md) 的「暂停快照」——时间、当前子点、刚讲到哪、待办微动作、2–3 条"我正卡在哪"的心理状态；然后**噤声**。不动 `进度.md`（会话没结束）。
- `/继续`：AI 用 3 行回放快照，原地续上。目标：**一条消息回到状态**。

### 怠惰再入：`/卡住`

- `/卡住`（或我说"不想学 / 太多了"）：AI 丢开计划，给**15 分钟小门**——当前断点里最小可完成的那个动作，"做完想停就停"。
- 做完只问一句："续杯还是收工？"两个答案都算赢。**不追量、不愧疚**（沿用英语轨「偷懒红线」哲学：这是降量信号，不是追量信号）。

## Step 3 — 收尾（让续接自维持 + 兑现"自动成文"）

我说 `收工` / `结束学习` 触发。三 Stage 顺序落盘：

**Stage A — 写 `进度.md`（仅本模块）**
1. 「已用」列加上本次时长（守 0.5h 粒度）。**时长无精确记录时给估值、标注"估值待校"让我确认，别默认写一个猜的数**；开场或跨大节时也可让我报一句大致用时，收尾就不靠猜。
2. 「状态」按注册表翻：⬜→🟡→✅（只用 ⬜🟡✅⏭🔖🔁，不造新符号）。
3. 「📅 每日学习日志」追加一行：`YYYY-MM-DD | h: X.X | 学了什么 + 明天计划`（绝对日期）。
4. **先展示要改的行，等我确认再写**（`进度.md` 表格被 [周更流程.md](周更流程.md) / [月底晋级评审.md](月底晋级评审.md) 两个 SOP 引用，确认优先）。
5. 仅周日：另在 [进度总表.md](进度总表.md) 🗓 追加一行（沿用既有周更触点）。

**Stage B — 覆盖 [学习断点.md](学习断点.md)**
先判定收工后的断点类型，再覆盖「当前断点」并清空「暂停快照」：

- **资料 / 任务内部**：写明先前学什么、学到哪个子点、完成程度和唯一下一微动作。下一动作可参考同一资料内的文章 `§后续预告`。
- **阶段边界**：写明刚完成的资料 / 阶段、完成程度、产出与遗留债务；「下一资料」固定写「待用户决定」，「下一步」固定为等待用户选择。不自动指定候选、不创建下一篇文章。

该 Stage 仍自动写，无需确认。

**Stage C — 生成文章草稿（AI 代笔，我审稿）**
由 **AI** 把本次的**学习产物**（我的复述 / 举例 / 答题）按 [文章模版.md](文章模版.md) 融成文章对应节的草稿——我不动笔写正文，只在写完后**审查是否符合预期**。四条硬约束：
1. **忠于原资料的逻辑顺序、完整体现学习过程**：原文在哪节讲的就在对应节讲，**不超前展开**；保留卡点 / 误解 / 改主意的痕迹，而不是直接给整理好的结论。
2. **承上启下**：每节先承接上文、引出本节必要性，再进正文，不要开篇就甩技术点。
3. **格式首发即"渲染就绪"**（开章就定、别等回头转）：数学一律 LaTeX `$...$`（写 `\theta` 不写 θ、`\partial` 不写 ∂），代码标识符 / 函数名 / 报错串一律反引号；信息密度高的旁支用 `<details>` 折叠块或 `##### 扩展：…` 独立小节，不挤占主线。
4. **版本敏感的细节加 `〔待核源码〕`**：随 PyTorch 版本会变的具体落点（yaml 文件名、宏名、公式常数、API 名）打标记，看源码 / 实战那节再逐一对一遍——别让"可能过期的细节"冒充确凿结论。
- `/成文`：一个主题 / 一篇学完后触发**整篇装配 + 润色**——把 §学习过程 融成流畅叙述（融合而非罗列）、生成 §思维导图总结、收口 §读后回顾，产出可发布草稿交我审。**这是"完成学习后自动成文"的兑现点。**

## 断点文件规范

「当前断点」必须二选一，不得混写：

| 断点类型 | 适用条件 | 必填内容 | 禁止内容 |
| --- | --- | --- | --- |
| 资料 / 任务内部 | 已选资料或任务尚未完成 | 先前学什么、学到哪里、完成程度、唯一下一微动作 | 跳到未选定的新资料 |
| 阶段边界 | 一份资料或一个阶段已完结，下一阶段未开启 | 已完成内容、完成程度、产出、遗留债务、「下一资料待用户决定」 | 候选资料名、默认下一篇文章、对新资料的微动作 |

> 仅当用户明确说「请帮我选取下一份学习资料」或同义请求时，AI 才能读取 `学习指引.md` 与 `进度.md` 给出建议；建议不等于已选定，必须等用户确认后才开新阶段。阶段边界下，历史日志里的「明天 / 下次计划」只保留当时语境，不构成当前选择。

[学习断点.md](学习断点.md) 两块，职责不同：

| 块 | 写入时机 | 语义 | 寿命 |
| --- | --- | --- | --- |
| 📍 当前断点 | 每次「收尾」覆盖 | 已定的当前光标（下次从哪开始） | 长期，单一状态 |
| 🔖 暂停快照 | `/暂停` 覆盖 | 会话中途的易失热缓存 | `/继续` 后失效，「收尾」清空 |

通用字段：更新时间、模块、断点类型、学习内容、完成程度、产出文件、cadence、备注。内部断点另必填**下一步具体动作**；阶段边界另必填**下一资料待用户决定**。历史不进本文件——历史在各模块 `进度.md` 的「每日学习日志」（append-only），本文件只是光标。

## 与其他流程的边界

- **不撞英语教练模式**：若是英语轨学习、或我用英文写 → 英语模式占"轮末反馈"位，陪学只驱动学习仪式；二者不同时追加反馈（英语赢反馈、陪学赢仪式）。
- **不混入两个 SOP**：跑 [周更流程.md](周更流程.md) / [月底晋级评审.md](月底晋级评审.md) 或 README / 进度表维护时，陪学模式**不激活、不插话**。
- **不碰稳定层**：全程**绝不**编辑 `主计划.md`、`周更流程.md`、`月底晋级评审.md`、任何 `学习指引.md`、`周报/*`。晋级仍是月底人工决定。

## 完整示例（PyTorch 文章 1：§1.3 → §2 Autograd）

设今天 2026-06-20，上次学习 2026-06-18，中间 2 天被工作打断。断点指向：PyTorch / `1-Internal-Overview.md` / "§1.2 步长表示完成，下一 header §1.3 基于 Tensor 属性的算子调度"。

**开场** `继续学习`：
> （读断点 + 进度总表 + 主计划）"上次（06-18，过去 2 天）：文章 1 §1 张量写到 1.2 步长——stride 和 Tensor-Storage 分离、view 零拷贝你已讲透。
> 下一步：继续学 §1.3《基于 Tensor 属性的算子调度》，先回答一个属性判断题。
> 隔了 2 天，建议先 2 句回血：'stride 解决什么、为什么 view 能零拷贝'，再上新。
> 今天 cadence：精读 1.5h + 实战 2h。要不要：[1] 回血→继续 §1.3  [2] 我只有 30 min  [3] 换子点？"

**学习中**（先问后讲）：
> 问："非连续 view `A[:,1]` 调 `.sum()`，dispatch 要先看 tensor 哪几个属性来决定走哪条 kernel？"
> （我答出 device、dtype，漏了 layout / contiguous）
> 讲：补全——device 选设备后端、dtype 选数据类型特化、layout / contiguous 决定走 contiguous fast-path 还是 strided generic kernel。
> 派："用三句话复述 device、dtype、layout 各自怎么影响 kernel 选择，第三句带上 `A[:,1]` 的例子。"（这是学习工件，不是博客段落）

工作来打断 → `/暂停`：
> （写「暂停快照」：14:20 / §1.3 / 已复述 device·dtype 两类 / 待办：用 `A[:,1]` 补 layout 的例子 / 卡点：非连续是否一定走 generic）噤声。

40 分钟后 `/继续`：
> "回到 §1.3：device / dtype 两类已复述，缺第 3 类 layout / contiguous，你刚卡在'非连续是否一定走 generic'。用 `A[:,1]` 补一句例子，这个学习工件就完成。"

我完成复述工件，`收工`：
> **Stage A**（先 diff 后确认）→ `PyTorch/进度.md`：实践任务 1 已用 +1.0h、状态 🟡；日志追加 `2026-06-20 | h: 1.0 | 完成文章 1 §1.3 算子调度的复述与举例（dispatch 看 device/dtype/layout）；明天继续 §1.4 Tensor 扩展`。
> **Stage B**（自动）→ 覆盖 学习断点.md：类型="资料内部"，子点="§1.3 完成，下一子点 §1.4 关于 Tensor 的 PyTorch 扩展"，下一步="先回答『新 device 和新 layout 哪个需要真扩展 Tensor』，再读 §1.4"，清空暂停快照。
> **Stage C**（确认）→ AI 把今日的复述与举例代笔成文章 `§学习过程 §1.3`，再把"非连续是否一定走 generic"这类残留疑问汇入 `§后续预告`，交用户审稿。

下次 `继续学习`，读断点 <10 秒回到状态。
