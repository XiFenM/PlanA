# 陪学流程：PlanA 仓库适配

本文只定义 PlanA 的人类可读流程和文件职责。Agent 的教学、练习、Review、mastery
和稀疏写入规则以中央 `guide-learning` Skill 为准，不在本文复制第二套 Skill 正文。
本文解决的是：恢复时读哪里、学习状态写哪里、哪些产物必须按需生成。

本仓库通过 `.agent-skills-config/guide-learning.json` 提供 version 2 受管适配。生成 Skill 中的
`.agent-skills-context.json` 只把本文件、仓库指令、学习偏好、主计划、全局进度和资料目录定位为只读
事实，并把 [学习断点.md](学习断点.md) 定位为唯一 Checkpoint 候选。Program、Lesson 和 Session event
仍从 Checkpoint 引用及实际仓库内容发现，不把当前临时冲刺固化进静态配置。context 与
`allowlist.write_paths` 都不授权创建、修改、推进、结课、提交或推送。

## 1. 唯一事实源

| 逻辑职责 | PlanA 位置 | 只保存 | 不保存 |
| --- | --- | --- | --- |
| Program 控制面 | [主计划.md](主计划.md) 或用户明确启动的专项计划 | 长期目标、范围、候选 Lesson、已授权 Lesson 引用和条件性前台指针 | Lesson evidence、精确游标、会话历史 |
| Lesson 证据账本 | 当前能力的设计包、实验包或明确的 Lesson 专属章节 | 2–4 个目标、来源、阶段、证据目标以及实际发生的练习、finding 和 mastery | 完整教学、逐题对话、精确恢复位置 |
| Session event | 相应模块 `进度.md` 的每日日志或 Lesson 已有 event 索引 | 一段实质完成动作、证据链接、未关闭问题和用户确认的时长 | 当前游标、完整会话、Lesson 状态副本 |
| Checkpoint | [学习断点.md](学习断点.md) | 前台上下文、精确语义位置、恰好一个下一动作、前进门槛和条件性返回点 | 完成内容长叙述、预算、cadence、finding 明细、历史快照 |
| 知识产物 | 各模块的文章、设计包或实验记录 | 稳定结论、可追溯证据和设计取舍 | 当前游标或第二份 mastery 结论 |
| 过程记录／原始对话／卡片 | 由 `study-log`、`memo-cards` 按需生成 | 各自能力边界内的产物 | Program、Lesson 阶段、Checkpoint 或 mastery 裁决 |

同一语义只有一个活动写入者。[进度总表.md](进度总表.md) 仍是周期性派生 dashboard，
不随每次学习同步；各模块 `学习指引.md`、[周更流程.md](周更流程.md)、
[月底晋级评审.md](月底晋级评审.md) 不属于日常陪学的写入面。

## 2. 开始与恢复

用户自然表达开始、继续或恢复学习时：

1. 先读 [学习断点.md](学习断点.md)，再按其引用读取当前 Program、Lesson 证据账本和最近证据。
2. 做低成本 drift 核验：来源版本、范围、工件和下一动作没变时只读恢复；差异会改变责任或路径时才让用户选择。
3. 开场只投影当前上下文、精确位置和唯一首动作。有实际阻塞或前进门槛时再补一句。
4. 处于 Lesson 或阶段边界时，候选顺序不等于授权；等用户选定后才启动下一 Lesson。

一次答疑直接解决当前问题，默认不读无关长期状态、不创建 ID、不写文件。只有用户明确
开展跨会话 Course 时才建立 Program 和已授权 Lesson；一段可恢复的学习也可只是独立 Session。

## 3. 学习微循环

对结构化主题先给一张很短的全局图，再围绕每个关键节点执行：

1. **讲**：详细讲清当前节点的中心关系、机制和边界；优先沿可推导链组织，并按需连接 PyTorch、vLLM、KV cache 或自研芯片实务。
2. **挖**：留出追问空间，只做服务当前节点的必要扩展。
3. **探**：对刚讲过的内容或已确认的前置提一个最有区分力的检查题。不让学习者猜尚未教授且无法推导的知识事实。
4. **答与判**：让学习者完整暴露当前理解。理解无误时直接进入轻量“做”；只有存在差距时才补正确理解与目标之间的差值。
5. **再探**：补差后换条件、例子或问法复查，不让学习者机械重复标准答案。
6. **做**：完成一个几分钟内可完成的复述、举例、自测、映射或推导工件。
7. **验**：即时纠正并判断是否推进；证据不足时缩小节点或补最短前置。

一个完整案例可跨多个微循环累积建立。全部节点覆盖后，先合成完整心智模型，再用 2–4 个最低充分
的跨节点问题验收中心模型、关键边界和未直接讲过的同构迁移。

## 4. 正式练习与关闭

- 综合验收已满足本 Lesson 预先声明的 required mastery 维度时，跳过形式性练习，进入 mastery gate。
- 仍缺独立实践、迁移或实证证据时，只设计能补足缺口的最小正式练习。
- 练习开始前一次展示“为什么做、你交付什么、怎样算通过、四类文件边界、帮助如何影响证据、非目标与完成门槛”，等用户接受后才建验收工件。
- 学习者保持 learner-owned 核心产物所有权；Agent 不因一次失败默认接管。实质性帮助只撤销受影响范围的独立证据，之后用无提示同构新变式恢复。
- Lesson gate 按“目标 × required 维度”展示最小证据。只有用户确认后才写 final mastery 和 `complete`；不自动启动下一 Lesson 或 optional 内容。

## 5. 稀疏写入与自然语言控制

用户可直接说“暂停一下”“继续刚才的学习”“今天先到这里”“我卡住了”或“讲快一点”。
不要求快捷命令或固定措辞。

| 事件 | 写入规则 |
| --- | --- |
| 普通讲解、追问、理解检查、正确回答和关键节点推进 | 零写入 |
| 无实质进展的立即暂停或无 drift 恢复 | 零写入 |
| 有实质进展的暂停或计划内收尾 | 当段最多一条 Session event；仍有恢复任务时覆盖唯一 Checkpoint，不改写 Lesson 为 paused 或 complete |
| 练习契约接受、核心工件提交、durable finding、验证改变 evidence／mastery、跨过综合验收 | 只同步归属文件中发生语义变化的部分；下一动作用于跨会话恢复时才更新 Checkpoint |
| 关闭 Lesson 或 Program | 先展示证据并取得确认；关闭后等待下一 Lesson 授权 |

实际学习时长只在用户提供或确认后记入对应模块 `进度.md`；修改前依旧展示计划行并等用户确认，
不猜测时长。只在周日或已有 SOP 触点更新派生 [进度总表.md](进度总表.md)。

文章、结构化学习记录、原始可见对话、记忆卡和英语回顾都不绑定在收尾事务上。主题完整且值得整理时，
Agent 可以自然提议文章；用户确认素材范围和目标后才起草或写入。学习记录、原始对话、卡片和英语回顾
分别交给 `study-log`、`memo-cards` 和 `english-coach`，并各自单独取得授权。

## 6. 临时专项与返回点

只有旁支需要跨会话推进、形成独立目标或产物，或替换原唯一下一动作时，才建立临时专项。启动时：

1. 冻结原 Program／Lesson 的当前位置；
2. 在专项计划与 Checkpoint 中保存唯一返回点；
3. 不把原 Lesson 正文和证据复制进专项；
4. 专项结束时展示结果和原返回点，让用户选择返回、延长或转向，不自动跳回。

单轮旁支答疑不建立专项状态。

## 7. 边界

- 广泛资料发现、周更、月底晋级和长期资料治理归 `resource-planning`；`guide-learning` 只做当前学习目标所需的最小核验。
- 英语轨学习或英文技术表达中，`english-coach` 拥有轮末英语反馈，`guide-learning` 只驱动学习流程，不重复追加反馈。
- 日常陪学不修改 [主计划.md](主计划.md)、[周更流程.md](周更流程.md)、[月底晋级评审.md](月底晋级评审.md)、任何 `学习指引.md` 或过往周报。
- 已完成的学习记录、原始对话、历史 Skill 名称和旧路径都是 legacy evidence，迁移不批量改写。
- `resource-planning` 已选中最新版中央核心，但本轮不挂载 PlanA 持久上下文，只允许无配置、纯对话、
  零写入的专题 research。在 source/query 目录、portfolio slot 和 registry bootstrap 整体迁移并通过
  独立评审前，不保存 research brief、不运行持久 refresh/review，也不让旧周更／月底 SOP 绕过该边界。
