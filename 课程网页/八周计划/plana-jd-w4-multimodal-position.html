一张道路照片怎样进入语言模型？

给模型一张道路照片，再问一句“前面是什么路况？”你已经知道，文字经过分词和词嵌入（embedding）后，每个位置都有一个向量。照片最初只有红、绿、蓝三个通道的像素值。模型怎样把它们变成同样宽的向量，又怎样知道哪些内容在画面左边、哪些在右边？

沿着这张照片看 Qwen2.5-VL-32B-Instruct 的实现。处理器先把图像切成小块（patch），你在项目里接触过的 Conv3D 随后会读到这些像素块。视觉编码器提取特征，模型再把特征放进语言模型的输入序列。走到位置编码时，我们回到同一张图，看模型怎样使用时间、高、宽三个方向的位置。

读到最后，可以拿这张照片或一段短视频，沿途指出每个张量装的是什么、Conv3D 从哪里读数据，以及把位置配错会影响哪一步。

上一课讲过，同样形状的张量可以用不同精度存储。这次还要看张量里的数按什么顺序摆放。即使形状和精度都相同，第一个数也可能来自画面的不同地方。

1图像特征怎样填进文本序列？

跟着一条请求读 vLLM 0.33.0 的三个接口，先找到视觉编码和文本嵌入汇合的地方。

假设请求里有一张 RGB 图像和一句“请描述图中的道路情况”。分词器把文字转成 token ID，模型再按 ID 从词嵌入表取向量。提示模板也给图像留了一个标记。路口和隧道用的标记 ID 相同，光查这个 ID 对应的向量，模型还看不到照片的内容。

图像处理器（processor）读取像素，切出一块块 patch，同时记录它们在图上怎样排列。视觉编码器（vision encoder）为每个 patch 提取特征，再用注意力把其他位置的信息纳入特征。merger 把相邻位置的特征合并成语言模型能接收的向量。框架把这些向量依次填到提示中为这张图预留的位置。

一张图有多少个 patch，又占多少个序列位置？

P 是处理器从一张图切出的 patch 数量。处理器把每个 patch 的像素值展开，一块写一行，得到二维张量 pixel_values。因此，这个张量有 P 行。V 是空间合并后的视觉位置数，也是这张图在语言模型输入序列里占的位置数。这里说的一个“视觉 token”，就是占用一个位置的视觉特征向量。

再看向量的宽度。Dv 是视觉编码器内部每个特征向量的元素数，Dl 是语言模型每个输入向量的元素数。L 记整条请求的输入序列长度，包含文字、控制标记和图像占位。下表列出这款 32B 模型的参数。

矩阵中的一行来自图上哪里？

处理器先把同一时间块内的 patch 网格划成 2 × 2 的合并组。它从原图左上角起，沿着一排从左到右走完所有组，再换到下一排。每到一组，就依次把左上、右上、左下、右下四个 patch 写进 pixel_values 的连续四行。这样，后面要一起合并的四块从一开始就排在一起。

要找单张图里某个 patch 的行下标，可以先数它在原图的哪一组，再看它是组里的哪一块。设原图组号为 g，组内编号为 j，两者都从 0 开始，那么行下标就是 4 * g + j。这一行里再按通道、时间、高、宽存放该 patch 的 1176 个值。注意力窗口在视觉编码器里才参与特征重排。对照处理器构造像素块矩阵的实现和同一个 patch 在四个阶段的下标。

3一个 patch 怎样变成 1280 个特征值？

继续看那张处理后为 448 × 448 像素的道路照片。先跟进 vLLM 的 Qwen2_5_VisionPatchEmbed，再看视觉编码器如何让不同位置交换信息。

照片已经切成 1024 个 patch。图像处理器把每个 patch 的 1176 个值写成一行，因此 pixel_values 的形状是 [1024, 1176]。左上角四个 patch 的行彼此相邻。现在沿着其中一行，看看 Conv3D 读到了什么。

一个卷积核怎样读这一行？

把每行的 1176 个值按处理器写入时的顺序展开看，里面有 3 个颜色通道、2 个时间切片，每个切片高和宽都是 14 像素。静态照片的两个切片来自同一张图。view 用这四个轴解释原来的一行，复用同一份存储。于是 Conv3D 收到的逻辑形状为 [1024, 3, 2, 14, 14]。第一维数的是本次送进算子的 patch，每个 patch 在卷积接口里充当一个独立样本。

卷积核在时间、高、宽三个方向的大小和步长都是 (2, 14, 14)，正好覆盖一个 patch。模型为每个输出通道学一套覆盖全部输入通道和时空位置的权重，共有 1280 套，权重张量的形状是 [1280, 3, 2, 14, 14]。其中一套权重与这行的 1176 个值逐项相乘并求和，就得到一个特征值。这个投影没有偏置。1280 套权重分别算一次，便得到这个 patch 的特征向量。

沿用上一节的符号，P 是 patch 数量，Kpix 是每个 patch 展开后的元素数，Dv 是输出特征宽度。令矩阵 X 的每一行是一个 patch，矩阵 W 的每一行是一套按相同顺序展开的卷积核权重。这次计算就可以写成 Y=XW⊤Y=XW^\topY=XW⊤。输出 Y 有 P 行、Dv 列。这也解释了为什么这一步可以用矩阵乘法实现。

P = pixel_values.shape[0]
patches = pixel_values.view(P, 3, 2, 14, 14)
projected = patch_embed.proj(patches)       # [P, 1280, 1, 1, 1]
patch_features = projected.view(P, 1280)

读第三行时，留意最后三个 1。每个 patch 的时间、高、宽方向都只容得下一个卷积窗口。去掉这三个单元素轴，得到 [1024, 1280] 的特征矩阵。源码在这个函数内部把 patch 数量命名为 L，对应本页的 P。卷积层按执行条件可以走三维卷积或矩阵乘法，两条路径都要保留像素值与权重的对应关系。

一个位置从哪里得到周围道路的信息？

Conv3D 逐行读取 patch。输入矩阵下标为 i 的那块像素，投影后仍在特征矩阵的下标 i，只是每行从 1176 个输入值变成了 1280 个特征值。现在要让车道线上相邻的几段交换信息，视觉编码器才把同一局部窗口里的特征放到一起。

具体做法是先把特征矩阵看成 [合并组数, 4, 1280]，再用 window_index 沿第一维重新取组。每次一起取出同一组的四行，组内顺序保持原样。接着把它展平回 [patch 数量, 1280]，供注意力读取。多数层只在同一窗口内计算注意力，这张图的一个完整窗口覆盖 8 × 8 个 patch。从 patch 投影到窗口重排的调用顺序

这套配置的 32 层视觉编码器中，第 8、16、24、32 层让这张静态照片的全部 patch 相互做注意力，其余层使用局部窗口。这里的层号从 1 开始。经过这些层，每个位置仍有一个 1280 维向量，但向量已经能带上其他位置的信息。

卷积、空间合并和注意力各看多大一块？

哪个操作一次看哪些输入对位置做什么

2 × 2 空间合并组同一时间块内相邻的 4 个 patch，覆盖 28 × 28 像素。处理器先让这 4 个 patch 在矩阵中连续。它们各自通过 Conv3D 和视觉注意力，到 merger 才合成 1 个视觉向量。
局部注意力窗口同一时间块中最多 8 × 8 个 patch，即 112 × 112 像素。换成上面的合并组，一个窗口最多容纳 4 × 4 组。窗口内每个 patch 都能读取同窗其他 patch 的特征。64 个 patch 做完这一层仍有 64 个输出位置。图像边缘的窗口可以更小。
整图注意力对这张静态图，一次覆盖 32 × 32 个 patch。固定实现按每个时间块划分整图注意力范围。第 8、16、24、32 层让不同局部窗口的 patch 也能交换信息，层号从 1 起算。这些层同样保留各个 patch 的输出位置。

4四个视觉位置怎样合成一个，又怎样填进提示词？

同样做完 256 个小方块，视觉网络就得到了 256 行输出。此时各组仍按注意力窗口的处理次序排列。vLLM 用 reverse_indices 恢复这些组在原图网格里的顺序，后面才能把第一组、第二组依次写进属于它们的占位。遇到多张图时，框架还会按每张图自己的网格计算它产生了多少行，把各张图的特征分别交给后续接口。

同一个 patch 怎样排进注意力窗口，合并后又怎样回到原位？

把照片处理后的高、宽换成 56 × 140 像素。高、宽各除以 14，得到 4 行、10 列 patch。每 2 × 2 个 patch 编成一组，于是原图有 2 行、5 列组。这里的坐标、组号和矩阵下标一律从 0 开始。看右上角的 patch，记作 A。它的坐标是（行 0，列 9），在原图组 4 的右上角，组内编号为 1。

处理器写完组 3 后，先写同一排右边的组 4，再换到下一排的组 5。图上组 4 已经在右窗，组 5 还在左窗，可见此时处理器走的是整幅图的组序。组 4 从下标 16 开始，A 的像素就在 pixel_values[17]。把 Conv3D 的输出记作 E，A 的特征也在 E[17]。

等到视觉编码器准备窗口注意力的输入，才用另一种读法。先取左窗的 0、1、2、3、5、6、7、8 组，再取右窗的 4、9 组。边缘用于索引对齐的空格会被滤掉。组 4 在窗口顺序中的下标是 8，组内编号仍然是 1，所以重排后的特征矩阵在下标 8 * 4 + 1 = 33 处读到原来的 E[17]。原矩阵 pixel_values 仍按处理器的顺序存放。

读这两个数组时，先说清手上有什么编号。如果手上有窗口顺序中的下标 k，读 window_index[k] 得到原图组号 g。如果手上有原图组号 g，读 reverse_indices[g] 就能找到它在窗口顺序中的下标 k。本例的两张索引表如下。

window_index    = [0, 1, 2, 3, 5, 6, 7, 8, 4, 9]
reverse_indices = [0, 1, 2, 3, 8, 4, 5, 6, 7, 9]

以组 4 为例，window_index[8] = 4。构造逆索引时，就在 reverse_indices[4] 写下 8。merger 已经按窗口顺序每组算出一行，因此原图顺序的第 4 号位置应从 window_rows[8] 取值。框架对每个组做同一件事。

reverse_indices = [0] * len(window_index)
for k, g in enumerate(window_index):
    reverse_indices[g] = k
grid_rows = [window_rows[k] for k in reverse_indices]

源码用张量赋值一次完成循环，最后一行对应 hidden_states[reverse_indices, :]。恢复的是各组的先后次序。每行向量仍然保留刚刚经过注意力和 merger 算出的全部特征，接下来就可以按原图的组序写入各个图像占位。逆索引的构造、重排、merger 和恢复顺序

5为什么旋转 Q 和 K，点积就能用上相对位置？

接着语言模型第一层的入口，先看一个注意力头如何给一对位置打分。RoFormer §3.2 给出旋转的数学关系，Qwen2Attention.forward 给出它在模型中的调用位置。

前面追踪的组 4 已经回到正确的图像占位。现在，图后的一个词要从图像里读取信息。语言模型先把各位置的隐藏向量投影成查询 Q、键 K 和值 V。一个查询用自己和各个可见键的点积计算权重，再按权重汇总它们的 V。这里的 V 指注意力中的值向量，前文的视觉位置数则是一个计数。

先用一维序列讲清位置怎样进入点积。设查询位于 m，键位于 n。在同一个头中取出两维，用列向量 qmq_mqm​ 和 knk_nkn​ 表示这一对分量在旋转前的值。可以把它们看成同一平面上的两支箭头。RoPE 为这对维度规定一个角频率 ω\omegaω，表示位置每增加 1，箭头逆时针转过多少弧度。

旋转保持各自的长度，点积却还取决于两支箭头的夹角。把两支已经旋转的箭头一起反向转过查询的角度，点积保持原值。查询回到旋转前的方向，键相对原方向只转过两者的角度差。代数上，旋转矩阵的转置正好把角度取反。

用两支最简单的箭头试一下。旋转前都取 (1, 0)，起点在圆心，箭头指向正右方。图中为便于观察，取每格转 30°。先比较“原位置”和“两者同移”，再把查询单独往后移一格。

三个坐标怎样用在一个 128 维的头上？

这款 Qwen2.5-VL 的配置给出 mrope_section = [16, 24, 24]。它数的是 64 对旋转分量。前 16 对用时间坐标，接下来 24 对用高坐标，最后 24 对用宽坐标。每对仍用自己的角频率。代码的 NeoX 排列把头内下标 j 与 j + 64 配成一对。比如对组 4，第 20 对用高度坐标 5，第 50 对用宽度坐标 9，这里的编号从 0 开始。

t, h, w = positions[:, i]
angles = torch.cat((t * inv_freq[:16],
                    h * inv_freq[16:40],
                    w * inv_freq[40:64]))

i 是序列下标，inv_freq 依次存放 64 个角频率。真实实现会查正余弦表并按上面的区间选轴，用相应角度分别旋转该位置的 Q 和 K。普通文字的三个坐标相同，这个位置内的每一对分量便都用同一个位置编号，和一维 RoPE 的用法一致。

最后把两处注意力接回原图。视觉编码器在 merger 之前用合并前的行、列给 patch 分配空间旋转角，特征按窗口重排时，对应角度也要一起配好。语言模型在 merger 之后拿到恢复组序的视觉特征，才在 [3, L] 的位置张量上使用这里的 T、H、W 三段。两处都能追到处理器给的网格，使用的位置粒度不同。

RoPE 把位置信息用在注意力打分上。每个位置先算出自己的 Q、K、V。在一个头里，把 Q 的分量两两配成二维向量，K 也按同样的方式配对。一对分量有自己的角频率。拿 token 的位置乘这个频率，就得到这一对应该转过的角度。旋转保留了向量的长度，也让位置有机会改变 Q 和 K 的夹角。

为什么能体现相对位置？设查询在位置 m，键在位置 n。做点积时查询那一侧要转置，旋转矩阵的转置相当于沿反方向转回去。这样合在一起，留下的就是 n 减 m，再乘这一对的角频率。只要旋转前的 Q 和 K 固定，把这两个位置同时后移相同距离，这一对的点积就保持不变。

符号与名词

processor（处理器）
把文本和图像或视频整理成模型输入。图像处理器输出像素块矩阵以及每张图的网格尺寸。
vision encoder 与 merger
视觉编码器提取 patch 的特征，并通过注意力在不同位置之间传递信息。merger 合并相邻位置的特征，把向量宽度变成语言模型需要的 5120。
P、V、Kpix
P 是一张图切出的 patch 数量。V 是空间合并后的视觉位置数。Kpix 是一个 patch 展开后的元素数，本例为 1176。
网格行的值 (t, h, w)
t 是时间块数，h 和 w 是每个时间块在空间合并之前有多少行、多少列 patch。
F、Hr、Wr、τ、p、s
F 是送去切块的采样帧数。Hr 和 Wr 是调整尺寸后的像素高和宽。每个时间块取 τ = 2 帧，每个 patch 的边长 p = 14 像素，每个空间合并组的边长 s = 2 个 patch。
Dv、Dl、L
Dv 是视觉编码器的特征宽度，本模型为 1280。Dl 是语言模型的特征宽度，为 5120。L 是整条请求的输入序列长度。
图像占位位置
输入序列中为图像预留的位置。在这些位置，语言模型读取视觉网络输出的向量。
X、W、Y
X 的每行存一个 patch 的输入值，W 的每行存一个输出通道的卷积核权重。两者用同一顺序展开。Y 的每行存该 patch 投影后的特征。
window_index 与 reverse_indices
视觉编码器用 window_index 把 Conv3D 输出的特征按窗口重排。每次移动一个 2 × 2 合并组的四行。merger 把四行合成一行后，reverse_indices 再把各组的向量排回原图组序。
RoPE 的旋转平面
一个注意力头中的一对特征分量。该对的角频率乘以位置编号，得到它在特征平面里的转角，单位为弧度。
mrope_section
它指定时间、高、宽三个方向各用多少对特征分量做旋转，本模型分别用 16、24、24 对。positions 的每一列提供一个序列位置的三个坐标。
