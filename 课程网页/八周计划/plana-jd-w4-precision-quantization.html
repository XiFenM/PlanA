1同样 16 位，为什么仍有不同的数值取舍

固定 PyTorch 类型定义中的位编码、转换与 numeric_limits。先沿投影例子理解范围和舍入，完成本轮检查后再按需对照源码。

假设投影需要保留权重里接近 1 的细小差异，同时另一些激活或中间结果可能处在很大的数量级。我们没有无限位数，必须在“覆盖多少数量级”和“每个数量级分得多细”之间分配编码空间。只比较总位数，无法回答这两个问题。

指数管数量级，小数位管局部分辨率

对规格化二进制浮点数，用 s 表示符号位，f 表示显式小数位数，F 表示这些小数位编码的整数，e 表示实际指数。它的数值可以写为：

x=(−1)s(1+F2f)2ex=(-1)^s\left(1+\frac{F}{2^f}\right)2^ex=(−1)s(1+2fF​)2e

这里的首位 1 是隐含的，不占 f 的位数。因而 FP16 的 10 个显式小数位对应 11 位有效二进制精度，BF16 的 7 个对应 8 位。指数位越多，通常能覆盖更多数量级；在同一数量级里，小数位越多，可表示值越密。

对该格式覆盖的有限规格化正数，在同一指数区间 [2e,2e+1)[2^e,2^{e+1})[2e,2e+1)，相邻可表示值的间距为 Δ=2e−f\Delta=2^{e-f}Δ=2e−f。因此浮点数在整个数轴上并非等间距：数量级越大，绝对间距通常也越大。下面只比较 1 向上的间距，也就是 [1,2) 这个局部区间。表中的 Inf 是无穷特殊值，NaN 是非数值结果；“最大有限正值”不包含这些特殊编码。

范围用尽、接近零和特殊值

如果转换后的格式装不下所需大小，会遇到溢出；其表现由具体格式和转换规则决定，可能涉及 Inf、NaN 或饱和处理。接近零时，次正规数用不带隐含首位 1 的编码继续表示更小的值，但相对分辨率逐渐变差；再小的值可能在舍入后变为零。

本节的 FP8 专指 float8_e4m3fn 与 float8_e5m2。E4M3FN 没有 Inf，却仍有 NaN；这既不意味着所有编码都有限，也不意味着所有转换都自动截到 448。它们不能与 FNUZ 等变体混用。具体缩放与溢出策略留到量化映射和实际后端时核对。

宽累加能保护后续计算，不能恢复已丢信息

更宽的 accumulation dtype 通常能减少求和新引入的舍入误差；如果它的指数范围也更大，还能容纳更大的中间和。BF16 与 FP32 的指数范围相同，不能仅凭“FP32 累加”就保证不溢出。

宽累加既不能恢复输入舍入已经抹掉的差异，也不能单独保证窄类型写回不会再次舍入或溢出。FP32 本身也有有限精度，归约顺序和融合方式仍可能影响数值结果。

把内部数学类型落到源码

在对应上一课实际 Torch 构建的源码里，opmath_type 将 Half、BF16 及这里两种 FP8 映射到 float。这是供算子实现选用的内部数学类型。下面的 BF16 C++ 标量加法重载展示了一个具体用法：先转换为 float 相加，再按返回类型变回 BF16。

inline C10_HOST_DEVICE BFloat16
operator+(const BFloat16& a, const BFloat16& b) {
  return static_cast<float>(a) + static_cast<float>(b);
}

这只能裁决这个标量重载。张量 GEMM 可以选用另一套后端和 intrinsic；AccumulateType 也提供默认映射，但实现不被强制使用它。因此，“配置写 BF16”“类型映射为 float”和“这个具体 kernel 如何执行”是不同证据层次。

同理，上一课的 CPU FP32 参考是在给定 BF16 权重数值的前提下核对计算。它提高了参考侧内部运算精度，却没有恢复一个未被保留下来的原始 FP32 模型。讨论正确性时，应说清比较的是表示误差、算子计算误差，还是任务输出质量。

结论：沿数据流标出每次转换、内部运算、部分和与写回，再问误差从哪里进入。宽类型能减少后续误差，却不是对整条路径的无条件保证。

固定源码：opmath 映射、累加映射与使用范围、BF16 标量加法。它们解释实现约定，不证明所有设备内核都采用相同精度路径。

检查 1FP32 累加能否排除精度问题

同一模型服务把权重和中间张量的存储从 BF16 改为 FP16 后，部分请求开始出现 Inf；模型结构、输入请求及其他主要配置保持不变。已核对某个投影 kernel 仍用 FP32 累加，但尚未定位第一个 Inf 产生的位置，也未核对其他算子的内部计算类型。

工程师认为：“两种存储都是 16 位，关键 kernel 又用 FP32 累加，因此可以排除精度问题；把异常输出 .float() 就能恢复。”请判断这两个说法，并沿数据流说明你会优先核对哪些事实。

用自己的话解释即可，无需计算或猜具体 GPU 指令，也不需要先认定唯一根因。

参考要点

BF16 与 FP16 同为 16 位，但指数／小数位分配不同。FP16 的有限范围更小，因此转换或后续运算中的溢出仍是需要检查的候选原因，不能仅凭总位数排除精度问题；题目还不足以认定唯一根因。

某个投影 kernel 的 FP32 累加只约束它的部分和，不覆盖之前的输入转换、结果写回或其他算子的内部数学。应沿数据流寻找第一个非有限值，核对该点前后的实际数值、转换与运算类型。

已经得到的 Inf 转成 FP32 后仍是 Inf，原来的有限数值没有因此恢复。这是确定的类型转换，不是随机或不可控行为；需要回到信息丢失之前的输入与运算去修正或重算，而不是只转换最终异常输出。

缩小 scale 会更细，也可能丢掉更大的值

在码域和 z 固定时，s 越小，重建刻度越密，同时覆盖的区间也越窄。对没有发生裁剪的值，按本节理想实数比例与 RNE 模型，舍入误差不超过 s/2；被裁剪的 12 则重建为 2.75，误差不受这个半格上界约束。

因此，选 scale 不是“越小越好”。保留离群值可能让大量小权重共用过粗的刻度；缩窄范围、允许裁剪，又可能损失少数但重要的权重。实际工具还会受到 scale 存储精度及浮点运算的影响，半格附近不能把数学模型与任意实现要求为逐 bit 相同。

量化仿真验证数值变化，不自动完成低位部署

可以先把量化、裁剪、重建连起来，观察近似值会造成什么误差。PyTorch 的这个接口示例以 FP32 输入得到浮点重建结果：

w_simulated = torch.fake_quantize_per_tensor_affine(
    w_fp32, scale=0.25, zero_point=4,
    quant_min=0, quant_max=15)

即便码域只用了 16 个整数，这个返回张量也不是 packed 4-bit 权重。若之后把重建值作为普通 BF16 权重交给原线性层，数值已经改变，存储和执行路径却仍可能保留原来的形式。真实收益还需要核对紧凑表示、参数布局以及消费它们的执行路径；这也是下一节点要连接的部分。

结论：scale 决定刻度间距，zero point 决定零的编码位置，粒度决定谁共用参数。表示误差、真实存储与执行收益是相连但不同的问题，需要分别核对。

整数映射与顺序依据 ONNX v1.16.0／opset 21；仿真语义依据 固定 PyTorch API；分组元数据见 vLLM v0.26.0 的 AutoAWQ。数值表是按定义复算，不是框架运行或 gfx1100 量化实测。

检查 2误差变小，为什么没有省显存或加速

一个团队在部署前做 4 位量化仿真：对每个输出通道沿 K 维每连续 128 个权重选一组 scale，离线完成舍入、裁剪和重建，最后保存为与原权重同形的 BF16 张量。服务只加载这些 BF16 张量，不读取整数码或 scale，仍使用原来的 BF16 kernel。

相同请求与实际输出长度下，把 group 从 128 缩小到 64 后，权重重建误差下降，但权重存储字节数和 TTFT 几乎没变。工程师据此认为“分组量化没有价值，只要继续缩小 group，TTFT 总会下降”。你如何判断这份实验已经验证了什么、尚未验证什么？若后续真正保存 packed 4-bit 权重并采用相应执行路径，缩小 group 还要权衡哪些代价？

围绕表示、存储和执行解释即可，不需要写 kernel 或计算显存，也不需要猜具体量化后端。

参考要点

这份实验检验了指定离线量化仿真下的权重重建误差。group 从 128 改为 64 后误差下降，是该数据与参数选择下的观察；它尚未验证真实低位存储／执行的性能，也不能仅凭权重误差证明完整任务质量提高。

服务仍加载同形 BF16 权重、使用原 BF16 kernel，没有通过 packed 4-bit 权重或相应执行路径获得节省。因此不能用这份 TTFT 结果否定分组量化的价值，也不能保证只缩小 group 就会加速。更精确地说，本实验没有建立低位部署收益；不能把它扩大成“任何权重数值变化都不影响服务时间”的通则。

真正低位部署时，更小 group 通常需要更多 scale；zero point 是否额外存储及怎样打包要看具体方案和后端。还要权衡元数据、布局／对齐、参数访问和反量化／计算路径的成本。在本题已将元数据丢弃、只读重建 BF16 的服务里，不应虚构这些元数据的运行时访问成本。

4AWQ、W4A16 与 kernel：沿一份权重走完三层关系

主线为 AWQ 论文 v5 的通道缩放，以及固定官方搜索代码；执行层再对照 vLLM v0.26.0 的 AutoAWQ dense linear 路径。先沿本节主例读，检查后再按需查看具体实现。

上一节已经区分量化仿真和实际部署。现在有一份标为 W4A16 的模型，我们要追踪三个不同问题：权重是怎样选出近似值的，整数码与参数怎样保存，后端又怎样消费这些存储。AWQ 是一种量化方法，W4A16 是权重与激活的表示约定，kernel 才是具体执行路径。它们彼此相关，却不能互相替代。

为什么不能只看权重大小

继续采用 Y=XW⊤Y=XW^\topY=XW⊤。只量化权重时，令 E=W^−WE=\hat W-WE=W^−W，则 Y^−Y=XE⊤\hat Y-Y=XE^\topY^−Y=XE⊤。对一个输出位置，某一通道的权重误差会乘上对应输入激活。因此，数值不大的权重也可能对输出很重要。

把投影缩成一个三通道的构造例：权重行为 [−7,0.26,8][-7,0.26,8][−7,0.26,8]，输入为 [1,10,1][1,10,1][1,10,1]，原输出为 3.6。三项权重同组，用 4 位无符号码 0…15、组步长 sg=1s_g=1sg​=1、zero point zg=7z_g=7zg​=7。直接量化会把 0.26 重建成 0，输出变为 1；小权重对应的大激活使这份误差被放大。

这说明激活统计值得参与选择，不是说“大激活通道对每个 token 都必然最重要”。实际输出还涉及相关性与误差相消；校准统计是搜索的线索，仍要用匹配的输出或任务依据评估。

AWQ 实际怎样利用校准数据

AWQ 先用一小批校准输入前向运行，收集相关 Linear 的输入激活。固定官方实现使用每个输入通道的平均绝对激活幅度来生成缩放候选；变量虽然名为 x_max，实际计算并非最大值。候选经过模拟量化后，用校准输入上的模块输出误差评分。

该实现搜索 20 个 α=0,0.05,…,0.95\alpha=0,0.05,\ldots,0.95α=0,0.05,…,0.95，构造与激活幅度幂相关的通道系数，并包含数值下限与公共归一化；评分的模块可以比一个 Linear 更大。还会进行另一个 weight clipping 搜索。通道补偿在精确算术下是等价变换，裁剪则是主动引入近似，二者职责不同。

“保护重要权重”不等于把固定的 1% 权重永久保留为 FP16。论文中的高精度保留实验用来揭示重要通道，AWQ 的主要做法是通过缩放保护它们，再进行低位量化。候选搜索仍会评估输出误差，运行时也仍需要反量化；这些过程不等于用常规反向传播微调模型权重。

部署时，输入补偿可以在图结构允许时折叠进前一层，例如相应归一化参数，从而避免额外显式除法。若上游输出还有其他消费者，必须一致处理这些路径；也不能任意把缩放移过一个非线性。最终导出与加载要保留整个变换，不能只搬走当前 Linear 的整数权重。

方法依据 AWQ v5 §3.1与§3.2；候选与评分见固定官方 auto_scale.py，应用与裁剪次序见 pre_quant.py。这是该方法与实现的说明，不是本课已运行校准。

检查 3相同 W4A16 标签，是否仍是同一个计算

某次 AWQ 导出使用正对角变换 D，其中至少一个系数不为 1。它将当前投影的权重变为 WD 后量化，并把对应的输入补偿 D⁻¹ 合并进前一层参数。题设给定：这个等价变换及折叠本身已经验证无误。甲后端完整加载了这些修改；迁移到另一种 GPU 时，乙加载了相同的 packed 权重、group scale 和 zero point，却沿用未修改的前一层参数。两边都显示 W4A16、group size 128，乙也能返回文本。

参考要点

反量化的组 scale 与 zero point 恢复的是变换后权重 WD 的近似值，记为 W_q。通道变换 D 决定不同输入通道怎样重标度；组量化参数决定整数码怎样映射回数值，两者职责不同。

题设澄清：乙既没有保留前一层中合并的补偿，也没有在别处补做。甲的当前投影计算为 (XD−1)Wq⊤(XD^{-1})W_q^\top(XD−1)Wq⊤​，乙为 XWq⊤XW_q^\topXWq⊤​。遗漏补偿破坏了原来的等价关系；即使某些输入碰巧得到相同结果，也不存在一般的等价保证。这项语义变化不能归为正常量化误差。

速度比较之前，要核对完整模型变换与加载、格式和目标后端的实际执行支持，再分别检查实现数值与量化后的任务质量。能生成文本只表明有限输入下执行结束，不能替代这些验证；相同 W4A16 和 group size 标签也不提供它们的证明。

5比较哪两个结果，决定了“正确”能说明什么

沿用同一模型与投影。数值判据对应 PyTorch 固定版本的 assert_close；模型层面补充官方 PPL 定义，先读本节的比较对象，再按需查看来源。

现在假设一份量化模型能在目标后端加载，也能生成文本。我们取同一个输入请求，把它与原 BF16 服务对照，发现输出有差异。只看到“误差”还不能判断是量化近似使然，还是打包、加载、补偿或 kernel 实现出了问题：不同问题需要不同参考。

先把当前投影的参考对象固定下来

继续用 X[M,K]X[M,K]X[M,K] 与 W[N,K]W[N,K]W[N,K]，本例 K=1536、N=8960。AWQ 处理后的权重在数学上近似 WD。把导出文件里的整数码、组 scale 和 zero point 按约定独立解释出来，得到 Wq[N,K]W_q[N,K]Wq​[N,K]。它已经包含量化误差，既不是原始 W，也不是尚未量化的 WD。

令 A[M,K]A[M,K]A[M,K] 表示实际送进这个投影的输入张量；正确加载的图已经把前一层补偿作用在它上面。因此，检查此处 kernel 时应使用同一份 A，不能再额外补偿一次。先把 A 与 W_q 中已有的数值提升到较宽类型，构造简单参考：

第二项若与原 BF16 流程比较，差异还可能包含图变换的有限精度影响、其他层的计算差异及量化近似。只有把局部输入和其余执行条件对齐，才能进一步归因。第三项则把“接近 BF16”与“符合任务要求”分开：BF16 也可能答错，量化结果偶尔与 BF16 不同也可能同样正确。

数值容差不是任务质量门槛

对相同形状的有限数值，令 p_i 为被检查元素，r_i 为参考元素。一个常用判据是：

atol 是绝对误差容限，单位与元素相同；rtol 是无量纲的相对容限。参考接近零时，相对误差容易失真，atol 提供明确的绝对尺度。还应单独检查本应有限的位置是否出现 NaN／Inf，并查看最大绝对误差及误差分布，避免只报一个平均值掩盖局部异常。

容差要根据参考精度、累加规模、被测类型和已有可信基线在比较前说明；不能发现失败后不断放宽直到通过。它回答的是给定数值比较是否足够接近，不能直接改写成“任务准确率可下降这么多”。同理，官方测试里的阈值只适用于对应的用例，不是新设备、新模型的通用质量标准。

为什么生成文本不同，不能马上定位到 kernel

语言模型每一步先输出词表中各候选 token 的分数，称为 logits，再由解码规则选出下一个 token。如果最靠前两个候选的分数很接近，一个小扰动就可能改变选择。下一步两边已读到不同前缀，差异会沿生成过程扩散。固定随机种子或使用贪心解码，能减少一些变化来源，却不能保证近似模型逐 token 一致。

因此，需要观察模型数值偏移时，可以给两边完全相同的已知前缀，对齐位置比较 logits、概率或目标 token 的概率。这种“始终喂给同一条已知文本”的比较，常称为 teacher forcing；它让我们在相同条件下比较预测，而不是把分岔之后的两个状态硬凑在一起。

设评测文本中实际计分的目标 token 为 t1,…,tTt_1,\ldots,t_Tt1​,…,tT​，对应的实际上下文记为 cic_ici​，它可以包含未计分的前缀；T 只计有效目标。NLL 是这些目标的平均负对数概率；PPL 是它的指数：

NLL=−1T∑i=1Tlog⁡p(ti∣ci),PPL=exp⁡(NLL)\mathrm{NLL}=-\frac{1}{T}\sum_{i=1}^{T}\log p(t_i\mid c_i),\qquad \mathrm{PPL}=\exp(\mathrm{NLL})NLL=−T1​i=1∑T​logp(ti​∣ci​),PPL=exp(NLL)

在同一语料、tokenizer、上下文切分与计分规则下，PPL 较低表示模型对这段文本的预测更好。它不能直接说明指令遵循、字段抽取或事实问答的得分。这里介绍它是为了读懂评测报告，不要求本次同时增加 PPL、大型任务集和逐层排障三套必做项目。

PPL 的定义及 tokenizer／上下文窗口边界见 Transformers 官方说明（2026-11-13 查阅）。本节只采用指标定义，不沿用页面示例模型的分数。

为这一份对照选择小而清楚的质量口径

本课后续只需为一个模型、一种受支持方案确定相称的判据。例如，若关心从短材料中提取字段，可以固定样本、标准字段和答案规范化规则，先比较 BF16 与量化模型各自的正确数，再看哪些样本发生退化；如果只检查两边输出一致，就应把结论限定为一致性，不能宣称任务质量已经验证。

评测样本应与用于挑选缩放／裁剪的校准样本分开。反复看评测答案并据此调整参数，也会把评测变成另一种调参数据。固定模型来源、tokenizer 与 chat template、截断／停止规则及解码设置，才知道分数变化来自什么；阈值、样本规模和具体工具留正式练习约定时一次确定。

本节归纳先写清“谁与谁比较”，再解释误差：同表示参考检查实现，BF16 对照观察模型偏移，任务标准判断是否可用。三类结论不能相互替代，也不需要把每一种可用指标都变成本课的新任务。

量化压缩权重，不会把全部服务显存都除以四

服务显存中除了权重，还有量化元数据、KV cache、激活及临时工作区、运行时分配；有的配置还包含 CUDA／HIP graph 相关占用。AWQ 的 W4A16 约定也没有自动量化 KV cache。上一节算出的投影字节数只属于其中一部分。

vLLM 的自动预算路径先由设备总显存与 gpu_memory_utilization 形成请求预算，再扣除测得或估计的非 KV 开销，决定可分配的 KV 空间。用简化记号写出关系：

BKV≈Bbudget−Bweights−BotherB_{\mathrm{KV}}\approx B_{\mathrm{budget}}-B_{\mathrm{weights}}-B_{\mathrm{other}}BKV​≈Bbudget​−Bweights​−Bother​

这里每个 B 都以字节计。B_other 汇总该路径的激活峰值、非 Torch 分配等扣除项，具体版本还处理适用的 graph 和其他预留；实际 KV 分配受块对齐与模型配置约束。若预算不变、其他开销相近，权重占用减少就可能让更多空间分给 KV。于是监控工具里的设备总占用近似不变，同时权重确实变小了。

固定 vLLM commit 568afb3a1380：请求预算、KV 可用量推导与实际分配。“总占用可能不降”是由此得到的条件化推断，具体数量仍以测量为准。

于是有两个都合理、但问题不同的对照。如果关心固定请求负载下的延迟，可保持 KV 容量足够且可比，避免一边发生容量压力、另一边没有；如果关心同一显存预算能支持多少服务负载，可以沿用相同预算策略，允许量化释放的空间变成更多 KV，并将这个容量变化作为机制报告。后一种得到的是部署整体收益，不能全部写成矩阵乘 kernel 加速。

该版本的 kv_cache_memory_bytes 可显式指定 KV 字节数，覆盖自动推导，但启动仍有其他显存检查，它不是“不可能 OOM”的保证。本次还没有选择这种配置；需要使用时再与实验问题一起确定。已有基线的 utilization=0.70 是预算设置，不是服务实测峰值，也不是权重占用。

为什么 decode 变快，TTFT 仍可能没有改善

在相同 token 数和并发形态下，读取更少的权重可能减轻带宽压力；但反量化、元数据读取、布局转换及所选 kernel 也会增加或改变成本。小批 decode 与大块 prefill 的矩阵形状不同，收益可以不同。节点4里 fallback 按展平 token 数选择执行分支，正说明不能仅凭“prefill／decode”名称推出一个固定加速倍数。

按本课客户端发送起点定义，TTFT 包含发送后的服务端排队、prefill 等工作，不计客户端发送前的等待；ITL 反映生成期间相邻输出的间隔；输出吞吐则取决于整个观测窗口。把这些指标分别保留绝对值、跨轮波动和适用负载，才能判断优化究竟改善了哪一种体验。更多 KV 也只有在容量成为约束时才有机会转成更高并发或更少重计算，不能从块数直接算出吞吐提升。

计时复用单元二的预热、干净重复运行和独立短 trace 方法。对固定工作量的性能比较，要核对实际输入／输出 token 数，避免量化模型更早结束使运行量改变；质量评测则保留任务自然需要的停止规则。若研究真实使用场景下的自然生成，也可以保留不同长度，但必须把它作为任务分布的一部分报告。两种口径各有用途。

本节归纳量化是否值得采用，由目标任务、服务门槛和受控测量共同决定。把质量、权重占用、KV 容量、TTFT、ITL 与吞吐放在同一张证据图景中，才能解释收益来自哪里、代价落在哪里。正式对照仍只选一个模型和一种已验证可运行的方案。

补充：预算、KV 池容量与当前占用

gpu_memory_utilization 是自动预算路径的输入，不是把设备实际占用永久锁在某个百分比的开关。初始化会依据权重与运行开销估计来分配 KV 空间；运行时还会遇到具体的 batch、序列长度与算子临时存储。因此，应先给“显存占用”补上对象与测量时刻。

以下限定为同一个未重启的服务：模型、权重表示、并行切分不变，不动态加载额外权重，也不调整已预分配的 KV 池。

观察量在上述前提下能否沿用
常驻权重张量的字节数可以作为该进程的固定量；请求更多不会复制一份完整权重。
预分配 KV 池的总字节数／总块数可以保持不变；它描述池的总容量。
请求实际占用的 KV 块／可用块数随请求进入、增长和结束而变化；它描述池内空间怎样被使用。
激活、临时工作区以及运行时实际占用／峰值不能由旧负载直接保证；batch、序列长度和执行路径可能改变这些开销。

设备级内存监控与 KV 池统计的范围不同：前者观察设备分配，后者观察已管理的块怎样分给请求。预分配池的总容量与其中正在使用的容量，分别对应两种统计；解读使用率前要先核对分母。空闲块指可以再分配的块，不要求其中存放的旧数值已经被清零。

另一方面，激活和临时区可能随负载变化；allocator 还可能保留已经申请的内存，使设备监控值与当前活跃张量字节数不同。因此，旧负载的总占用或峰值不能直接替新负载作证。KV 容量不足可能表现为等待、抢占或重计算，并不一定立刻触发设备 OOM；容量压力和设备分配失败需要分别观察。

补充：P50、P99 和吞吐为什么可以向不同方向变化

profile 帮助定位“为什么”，并不负责定义“发生了什么”

已经知道的是：在这份负载和配置下，完成窗口变长、吞吐变低。尚未知道的是：哪些具体算子、调度等待或数据移动增加了成本，以及各自贡献多大。你提出需要profile证据，适用于这一层根因定位；profile、硬件计数器或受控消融都可以提供额外依据。

一个有源码依据的候选解释是：权重读取减少，但所选AWQ路径的解包、scale处理、反量化或矩阵乘效率抵消了收益。另一个需要区分的关系是：本实验并发固定为8，KV池增大并不会自动让客户端发出更多请求。这些解释应当接受证据检验，不能仅凭吞吐结果宣布某个kernel就是瓶颈。本课不因此新增一套必做profile实验。

实际执行依据是vLLM0.33的普通AutoAWQ分支，以及本次实际选择的FP16。具体开销占比仍未知。

数值偏离与任务得分不是同一个“好坏”

你的质量解释可以作为候选，但更准确的说法是：数值误差描述相对参考的偏离，任务好坏由标准答案决定。BF16参考本身也可能答错；模型预测受到扰动后，某题可能从错误候选变成正确候选，不要求所有变化都降低任务得分。

检查 4吞吐提高，是否就值得采用

以下是假设结果，不是本次实测：某量化方案已通过同表示参考检查，固定任务集的得分也达到事先门槛。在同一 GPU、模型来源、调度配置、输入／输出长度和请求模式下，多轮干净计时显示 ITL 与输出吞吐改善，但 TTFT 变差，超过了目标服务的首次响应门槛；BF16 仍满足该门槛。设备总显存占用近似不变，而日志显示权重占用减少、KV cache 容量增加。

甲认为“吞吐提高就应采用量化”，乙认为“总显存没降，说明权重压缩没有生效”。请分别判断。若模型、硬件和任务不变，转而评估更高并发下的服务容量，现有证据中哪些还能沿用，哪些需要在新负载下重新确认？

说明判断依据与结论范围即可，不需要计算或设计完整实验。

参考要点

量化方案虽改善吞吐与 ITL，却已经违反题设的首次响应门槛，因此尚不满足该目标服务的采用条件。质量通过和某项性能改善，都不能替代另一个必需门槛。

权重占用减少、KV 容量增加与设备总占用近似不变可以并存。自动预算可能把权重释放的空间用于 KV，不能仅凭设备总占用否认压缩；utilization 是预算参数，不把实际总占用锁成常数。

转向更高并发时，原模型与权重身份、格式事实和已有范围内的正确性证据可保留。若进程不重启、加载与池配置均不变，权重字节和固定池总容量也可沿用；旧负载的活跃块数、运行峰值与服务性能不能直接移交。需在新负载下核对容量余量、运行开销及服务门槛，新增形状／路径也要有相应正确性覆盖。

检查 5复查：显存曲线平坦，是否还有余量

同一服务不重启，模型、并行方式和预分配的 KV 池都不变；关闭 prefix caching，也没有请求间的 KV 共享。保持活跃请求数量相同，把输入换成更长但仍在配置允许范围内的上下文。观察到设备总显存占用几乎不变，但调度器记录的可用 KV 块明显减少。

这两个观察矛盾吗？它们是否足以证明新负载仍有充足的内存余量？请说明哪个容量正在被消耗，以及还有哪类运行开销需要核对。

只解释这几种内存量的关系，不需要计算或讨论具体调度算法。

参考要点

不矛盾。KV 池已经预分配，请求可以在池内取得更多块而不让设备再分配同样大小的空间。设备总占用包含权重、KV 池及其他运行内存，不等于 KV 池本身；这里的负载变化是上下文变长，活跃请求数量保持不变。

可用块减少说明池内余量正在被消耗；仅有下降趋势，尚不足以说明剩余块能容纳接下来的请求增长。要结合可用块数、每块覆盖的 token 数、各请求的后续需求及调度约束判断容量，同时核对激活、临时工作区和运行峰值。池容量不足可能触发等待或抢占，与设备 OOM 不是同一个事件。

导师串讲：从一份权重走到一次服务选择

回到本课的 Qwen2.5-1.5B-Instruct 服务。一个 MLP 数学扩展投影读取 X[M,1536]X[M,1536]X[M,1536] 和 W[8960,1536]W[8960,1536]W[8960,1536]。原 BF16 权重元素载荷为 26.25 MiB；如果这些元素全部采用四位整数码，码本身的理想载荷为 6.5625 MiB。这个差距提供了减少存储与读取的机会，但我们还没有得到正确性或服务速度的结论。

第一步先问：哪些数已经改变？BF16、FP16 和明确格式的 FP8 分配给指数与有效数字的位数不同，因此范围和分辨率不同；转换时可能舍入、溢出或下溢。内部使用较宽计算类型，能减少后续运算新产生的一部分误差，但已存下来的输入只有那些数值。storage、内部数学、乘法、累加和写回要沿数据流分别核对。

第二步才是选择量化近似。组内的 scale、zero point 与裁剪范围决定如何用有限整数码覆盖一组数；缩小组可以适应更局部的分布，也增加元数据和布局成本。AWQ 进一步利用校准激活判断哪些通道的权重误差更容易影响输出：对权重施加通道变换 D，同时在输入一侧补偿。它改变量化前各通道的尺度，量化后仍是近似；完整图变换必须随着权重一起交给后端。

第三步是把这种近似变成实际可消费的存储。以本课普通 AutoAWQ 的 group size 128、TP=1 接收布局为例，qweight 是 [1536,1120] 的 int32 容器，每个容器装八个四位码；另有组 scales 与 qzeros。后端需要正确解释位序、分组与本地维度，必要时 repack。int32 在这里描述容器，W4A16 描述部分权重与激活表示，它们都没有单独规定最终乘法指令。

接着跟到执行：读取 packed 参数之后，后端可能在 tile 内反量化并计算，也可能先得到浮点权重再调用矩阵乘。不同 token 数、形状、设备和版本可以选择不同路径。我们核对了 vLLM v0.26.0 普通 dense AWQ 的源码分支，但只有在指定镜像与模型上完成加载、执行和检查，才能形成那个环境的运行证据。方法存在、格式被识别、路径实际跑通，是三个不同事实。

然后给结果选择合适参考。局部实现检查固定实际输入与量化表示，模型对照固定前缀及其他配置，任务评测再看独立样本上的标准答案或评分规则。容差说明允许的数值偏差，任务门槛说明可接受的使用效果；两者的单位、对象和目的不同。把它们各自写清，才知道一条“通过”究竟证明了什么。

最后回到用户感受到的服务。读取更少的权重，可能换来更短的计算时间，也可能在相同显存预算下给 KV 留出更多空间；反量化、工作区以及其他执行阶段又会消耗资源。于是我们沿用单元二的方法，固定可比较的请求与计时条件，分别观察 TTFT、ITL、吞吐、权重字节、KV 容量与运行峰值。原来两档调度的结果只支持当时的 BF16 负载，不能直接冒充量化收益。

把整条链连起来表示决定保留了哪些数值，量化方法决定怎样选择近似，文件和图保存这种近似，后端路径执行它，正确性与任务评测约束可接受的变化，最后由实际服务目标裁决收益。性能结论要落在这条链的末端，并带上相应的环境与负载范围。

尺寸、载荷、方法和固定实现均回到本页已有依据：浮点表示、AWQ 与实际路径、正确性口径、BF16 对照。本节复算的字节数只属于单个数学投影，不是完整模型或设备显存测量。

先沿上面的串讲连接全流程，再回答以下两题。这里检验机制与判断，文字作答即可；面试表达题的 60–90 秒只是组织篇幅的提示，不要求录音或计时。正式口头表现留在 W4 Mock。

综合验收 1面试表达：从文件到服务

请以本课的 Qwen 服务为例，向面试官说明：一份 AWQ／W4A16 checkpoint 从加载到生成结果经历了什么？为什么即使日志注明某个 kernel 使用 FP32 累加，也不足以决定用它替换原 BF16 服务？

按约 60–90 秒面试回答组织，文字作答即可，不必逐项复述全部术语。

参考要点

先核对模型、量化格式和完整图变换，再加载 packed 权重、组 scales／zero point 及其余模型参数。D 是通道变换的数学记号，不保证是 checkpoint 中独立存在的张量；若补偿在导出前已经折入前一层，加载时必须保留这些修改，而不是默认再做一次折叠。

运行时按具体设备、版本、格式、dtype 和形状选择执行路径，必要时 repack；路径可能在 tile 内反量化计算，也可能先得到浮点权重再 matmul。W4A16 不单独承诺乘法指令或累加类型。某个 kernel 使用 FP32 累加，只说明该处求和精度，不能恢复输入／权重量化已丢失的信息，也不能覆盖其他算子或输出写回。

是否替换 BF16 服务，要分别核对实现数值、模型偏移与固定任务质量，再以可比负载观察显存各项、TTFT、ITL 和吞吐是否符合目标。通过一个局部算子检查，或能返回文本，都不能替代整条证据链。

综合验收 2诊断：局部通过，完整模型未达标

某新后端的一个量化投影 kernel，在已覆盖输入上通过了独立解释同一 packed 参数的高精度参考检查。但完整模型在相同已知前缀下的 logits 相对 BF16 的偏差超过预定允许范围，独立任务集得分也低于预定门槛。模型身份、输入与 AWQ 补偿已核对，其他算子尚未逐一检查。

工程师提议放宽与 BF16 比较时的数值容差，并把已经算出的最终 logits 转成 FP32，不重算上游，以此宣告模型达标。请说明上述三项观察分别支持什么，以及这两个动作能否解决问题。

不需要猜唯一根因，也不需要写排障脚本。

参考要点

第一项只表明该投影 kernel 在已覆盖输入／形状上，与同一量化表示的独立参考在容差内一致；它不是未量化 BF16 参考，也没有核验其他算子。第二项说明完整模型未满足预定的 BF16 数值偏移判据；第三项说明独立任务质量未达到门槛。模型身份、输入和补偿已核对，缩小了排查范围，但尚不足以宣布整张图正确或断定唯一根因。

放宽容差只改变判定条件，不改变计算结果；把已有 logits 提升为 FP32，不重算上游，也不能恢复已经损失的信息。质量得分不会因此自动改善。应继续区分量化近似与尚未核验的实现／图问题，并让后续定位服从观测；不能用事后修改门槛代替修复或重新评估方案。

综合验收 3复查：导出语义与局部参考

某导出器已把输入补偿 D⁻¹ 正确折入前一层参数，并将 WD 量化打包；D 为正对角矩阵，至少一个系数不为 1。checkpoint 保存了全部修改后的模型参数，不另存独立的 D。加载器已正确加载这些参数，工程师随后又使用导出时同一个 D，在当前投影前额外执行一次输入乘 D⁻¹，其他参数与计算不变。

局部测试把投影实际收到的同一份输入和同一份 packed 参数同时交给 kernel 与独立高精度参考，在已覆盖输入／形状上检查通过。这项新增补偿是否应保留？局部检查通过能否证明整张图仍保持导出时的计算语义？请说明理由。

只回答这两个边界，不必重新复述整条服务链路。

参考要点

不应保留新增补偿。导出图已经使当前投影收到经过 D⁻¹ 补偿的输入，再乘一次同一个 D⁻¹ 就额外改变了输入。数学上它由 XD⁻¹ 变成 XD⁻²，破坏一般的导出等价关系；某些输入碰巧得到相同输出，不会恢复这项保证。

局部 kernel 与参考共同读取的是实际送入的同一份输入，因此它们可以同时正确计算这个局部任务，却共同绕过“上游是否给对输入”的问题。检查通过只证明已覆盖输入／形状下的局部一致性，不能证明整图仍保持导出时的计算语义。

检查 6复查：尾部间隔与总吞吐

另一组受控对照中，两种服务处理同一组请求，全部成功，实际输出token总数与并发配置相同。服务B的总完成窗口缩短了，但raw ITL P99升高。有人说：“P99变差，说明吞吐也下降了；必须先做profile才能判断。”

这段话中哪些判断可以直接用现有数据作出？哪些问题才需要进一步的定位证据？

说明统计关系与证据范围即可，不需要计算或猜具体kernel。

参考要点

两边成功输出的token总数相同，而B的总完成窗口更短，依吞吐定义可直接判断B的吞吐提高。P99升高也是已有数据给出的事实，但它描述高分位间隔阈值，不代表整个分布、均值或吞吐。

这两个观察可以同时成立，不需要先profile才能判断它们。哪些算子、等待或数据移动促成变化，以及各自贡献多少，才需要进一步定位证据。profile是可用方法之一，单个热点或相关性也不能自动证明完整因果关系。

符号与名词

M、K、N
M 是 token 位置数，K 是输入特征数，N 是输出特征数；本课投影为 X[M,K]×W[N,K]ᵀ。
s、F、f、e
规格化二进制浮点数的符号位、整数小数域、小数位数与实际二进制指数。F 在 0 到 2ᶠ−1 之间。
Δ
同一数量级区间内相邻可表示值的间距；不是整个数轴上的固定步长。
RNE
舍入到最近的可表示值；正中间时选择保留最低有效位为偶数的结果。
storage、compute、accumulation、opmath
分别关注内存编码、某一步运算的精度、部分和类型，以及实现采用的内部数学类型映射；它们不是必须依次经过的四个阶段。
s、z、q、重建值
s 是本节取正的 scale；z 是对应实数零的整数码；q 是码域内的整数；重建值为 s(q−z)，通常不等于原值。
G、group size
本课沿数学权重 W[N,K] 的 K 维分组；G 是每组的权重元素数，不是组数。
E_W
权重元素的平均平方重建误差。它不单独等于模型输出误差或任务质量。
AWQ、W4A16
AWQ 是利用激活信息选择权重低位近似的方法；W4A16 描述权重与激活的表示约定，不单独指明全部计算或后端。
D、d_k、s_g
D 是正对角通道变换，d_k 缩放权重列并要求输入侧逆向补偿；s_g 是组内整数码重建的量化步长，二者职责不同。
Q̃
量化再反量化后的近似映射，返回重建权重；不是裸整数码 q。
pack factor、repack
前者是一个存储容器装入多少逻辑低位值；后者是按后端需要转换布局或位序，不是重新运行校准搜索。
同表示参考
独立解释与后端相同的 packed 参数和输入，用简单计算检查实现；其中保留已有量化误差。
teacher forcing／同前缀比较
给两个模型喂相同的已知文本前缀，对齐位置比较预测，避免自由生成分岔后条件不同。
NLL／PPL
有效目标 token 的平均负对数概率及其指数；比较时固定语料、tokenizer、上下文和计分口径。
显存预算与实际占用
预算是分配策略的输入；权重、KV、工作区及设备监控数是不同范围的占用，不能互相代替。
