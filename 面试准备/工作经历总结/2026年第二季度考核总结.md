# 2026 年第二季度公开工作总结

> 本文为公开脱敏版，仅保留可公开的技术职责、工程方法与成果概述。内部组织、客户、项目代号、测试环境及未公开数据均已移除。

## 一、主要工作

### 1. 异步拷贝精度异常诊断

围绕 vLLM V1 推理链路中的偶发异步拷贝异常，建立分层诊断与验证方法：

- 梳理关键异步拷贝路径，提供全局和分类控制能力。
- 建立统一 Replay、异常分类、Trace 和控制变量实验流程。
- 通过屏障、回读、存储与 Stream 关联等手段排除部分候选原因。
- 将问题从全链路随机异常收敛到少数高风险路径。

当前状态为根因闭环中，尚未将强制同步或阶段性阴性结果视为最终修复。

### 2. 不同服务器的性能差异定位

- 将设备算子、CPU 处理、Host 调度和模型执行链路分层分析。
- 确认部分端到端性能差异主要来自 Host 侧开销，而非设备算子本身。
- 通过 Graph 模式降低调度开销，形成可复用的部署和排查建议。

### 3. 第三方测评与环境建设

- 建设模型测评环境，整理测评流程和操作规范。
- 根据公开标准完成精度验证，并明确能力边界与交付范围。
- 沉淀可复用的环境配置和验证方法，降低后续测评接入成本。

### 4. 交付与部署支持

- 支持部署环境、模型行为和输出协议等问题的定位。
- 将技术分析转化为可执行的部署建议和问题处理方案。
- 沉淀可复用的排障结论，减少相似问题的重复定位成本。

## 二、方法与影响

- 建立适用于复杂异步问题的分层开关、Replay、Trace、微型测试和结果归档方法。
- 沉淀“设备算子—Host 开销—通信—模型调度”的分层性能分析方法。
- 完善测评环境、验证流程和交付边界管理。
- 推动跨团队问题以可复现证据、明确假设和回归标准持续收敛。

## 三、下一阶段方向

- 继续完成异步拷贝问题的根因闭环，区分同步、缓存、存储覆盖和 Runtime 可见性等候选原因。
- 在定位最小触发路径后，形成底层修复、端到端 Replay、微型测试和异常统计组成的回归机制。
- 对依赖模型版本、算力和跨团队协作的任务，提前明确输入条件、责任边界与降级方案。
- 将服务器性能分层分析和 Graph 模式部署建议整理为标准排查流程。
