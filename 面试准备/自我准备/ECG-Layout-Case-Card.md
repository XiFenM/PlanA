## F1：主张与适用范围

我负责一个 ECG 多模态模型在自研芯片上的端到端适配、精度对齐和性能优化。模型接收心电图图像与文本指令，基于客户使用 `Transformers` 编写的自定义 `forward` 执行。在完成 Host 路径、小 Shape 计算与融合算子等优化后，我继续根据 Profile 和低批量矩阵乘的 Roofline 估算，与算子同事共同调整静态权重布局。

我在框架侧定义了相应的 Tensor 扩展，在模型加载后的处理阶段完成 blocked Col-major 权重预排布，并负责模型级回归。底层 Kernel 访存实现由算子与硬件同事协同处理。项目端到端时延由最初约 30–40 秒，经常规优化降到约 20 秒，再经权重预排布降至 20 秒以内。以下按这些阶段说明依据，不将全部收益归给布局修改。

项目目标是让模型在目标平台上正常完成推理，并将端到端时延降低到客户可接受的范围。第一轮优化分别处理 Host 侧准备工作、可复用的融合算子，以及 RoPE 系数准备中的小 Shape `BMM` 外积。后者改为广播逐元素乘法，保留数学语义。三项常规优化的单项收益没有分别测量。

## F3：从热点判断到布局方案

第一轮优化后，第二轮 Profile 仍显示小批量矩阵乘占据主要耗时。我结合实际 Shape、数据类型与读写数据量进行 Roofline 初步估算，判断后续应优先检查权重访存。

对 `[b,K] × [K,N]` 的矩阵乘，计算量可按 `F=2bKN` 估算。若输入与权重各从所选存储层读取一次、输出写入一次，流量模型为 `Q_min=s_A·bK+s_B·KN+s_C·bN`，其中 `s_A、s_B、s_C` 是对应元素的存储字节数。低批量下，权重项可能占据大部分流量。这是用于复核判断的方法表达；现场的实际 dtype、读取次数、缓存复用与设备带宽口径仍待核，不能把课程中的公开模型尺寸和假设带宽填入项目数据。

后续分析将问题收敛到原权重布局与 Kernel 分块读取顺序不匹配。团队采用 blocked Col-major：Tile 内部保持行优先，Tile 之间按列优先顺序排列，使静态权重的物理排布适合相应的分块访问。本次调整保持 Tile 大小不变。

当前能够保留的是上述布局与访问方式的关系。具体 Tile 粒度、地址映射、冲突所在的存储层级及实际带宽数据尚未固定，不能据此将根因写成已经证实的 bank conflict，也不能声称所有访存限制已经消除。

## F4：修改位置与个人职责

我在 `PyTorch` 框架侧定义相应的 Tensor 扩展，并在 `Transformers` 模型加载权重后的处理阶段完成预排布。转换完成后不再保留原布局权重，相关层的 prefill 和 decode 都使用预排布权重，后续调用复用这一表示。消费该权重的算子需要遵守相同的布局约定；实际布局标记与 Dispatch 细节仍待核。

这次方案只调整静态权重，没有同时改变激活输入和输出。激活的布局涉及前后算子的接口，继续调整会扩大适配与回归范围。权重预排布技术后来也移植到 `vLLM`，但本卡的端到端秒数仍对应 ECG 的 `Transformers` 运行栈。

| 职责 | 已确认工作 |
|---|---|
| 我负责 | 端到端 Profile、热点 Shape 分析、Host 路径调整、小 Shape 计算重构、Roofline 初步估算、Tensor 扩展、加载期权重预排布，以及模型级精度和性能回归 |
| 我与同事共同完成 | 收敛访存瓶颈、选择 blocked Col-major 方向，评估只调整静态权重的工程边界 |
| 算子与硬件同事负责 | 底层 Kernel 访存实现、硬件访问模式确认及相关算子优化 |

这项预排布覆盖模型中所有使用静态参数权重的矩阵乘，例如各线性层；QKᵀ、注意力概率乘 V 等动态矩阵乘不在该范围内。

## F5：正确性验证与回归

我同时进行了 MatMul 算子输出的数值级对照和模型端到端回归。在相同参数与输入条件下，我比较自研芯片上的预排布 MatMul 与普通布局 MatMul，输出逐元素数值相等。模型端到端比较中，logits 与修改前逐元素数值相等，输出 token 一致。这些是本次共建补充的项目口述结果。

| 验证层级 | 已确认的比较内容与结果 | 保留的边界 |
|---|---|---|
| MatMul 算子 | 预排布与普通布局两条路径均在自研芯片上运行；相同参数与输入下，输出逐元素数值相等 | 具体版本、比较函数、实际 Shape／dtype 与覆盖范围待核 |
| 模型端到端 | logits 与修改前逐元素数值相等，输出 token 一致 | 输入样本、采样配置与回归范围待核 |

这组逐元素相等的对照没有使用 CPU 结果作为参考。跨 CPU 的结果比较采用容差标准；具体 CPU 验证记录与容差尚未列出，不能将两种比较口径混写。

这次布局调整保持 Tile 大小不变，逐元素相等记录的是同一自研芯片新旧布局的实际对照结果。该结论限定在已执行的测试范围内，具体实现与原始覆盖记录仍待核验，不外推到不同计算路径或所有输入。

## F6：结果、数字冲突与限制

| 阶段 | 当前确认的端到端时延 | 可以支持的结论 |
