# 自我准备：简历取材与面试事实入口

> 整理日期：2026-11-09。用户确认本次只整理本地已有材料，先盘点事实，再制作针对性简历。
> 本目录按“事实与证据 → 工作项目 → 学习设计 → 简历与口述成稿”区分用途。三张工作 Case Card 已合入对应项目，原文件已删除；两份 Change Card 单独存入 `学习设计/`。项目内保留原案例锚点，现行链接指向合并后的位置。

## 1. 从哪里开始

1. **了解目前有哪些经历和能力**：读[能力与经历总表](能力与经历总表.md)。覆盖教育、任职、六项工作项目、横向贡献、个人实践与学习设计，并列出材料冲突及尚未闭合的字段。
2. **为一个岗位选择项目**：读[工作项目索引](projects/README.md)，再按[目标岗位分类](../目标岗位/简历与面试准备分类.md)决定展开哪些经历。
3. **核对个人职责、数字和验证条件**：回到对应项目文件的“核心案例、验证证据与边界”章节；每个项目只维护一份主要事实文档，总表用于导航与汇总。
4. **查看针对性简历**：A–G 已完成共 10 个版本，其中 D 分为 D1/D2/D3，E 分为 E1/E2；Markdown、HTML、PDF 入口见下表。全部于 2026-11-09 实际导出为 2 页 A4，沿用 A 类版式，打印正文为 10.5 pt；工作经历概括职责，项目分别展开对应证据。姓名、手机与邮箱保留待填写。

5. **选择对应自我介绍**：保留[默认版本](自我介绍/默认版本.md)，另有与 10 份针对性简历一一对应的岗位版本，入口见下表各简历行。每份都包含 HR 面、技术一面、技术二面的完整说法、轮次对照和追问补充。

求职范围与核心／扩展层级见[目标岗位入口](../目标岗位/README.md)。岗位选择不决定个人已经具备哪些能力，学习计划也不自动构成项目经历。

## 4. 以后怎样维护

1. 工作项目新增或有事实变化，先更新该项目唯一的主要事实文档，再同步项目索引与事实总表中的摘要；案例证据在项目文件内维护，不再拆出平行事实文件。
2. 数字必须保留模型、配置、计时／统计边界和验证方式；负结果、未覆盖项和协作归属一起记录。
3. 简历、口述稿、年度总结是不同用途或时期的表达材料。出现冲突时，依据具体的本人确认、实验记录和校准说明判断，不仅比较文件修改时间。
4. 学习完成与项目实施分开。代码存在、测试文件存在、导师材料或计划中的任务，均不自动证明本人实现、执行或掌握。
5. 保留历史审计与口述锚点；更新当前概览时明确日期与依据，避免让历史内容继续承担“唯一真源”的角色。
6. 内部机制、未公开实现和实验数字的取材范围沿用原项目约定。整理本地材料不自动扩大对外披露范围。
7. 原始对话归档和已生成记忆卡中的来源路径／指纹保留其历史含义，不冒充当前重新生成的结果。日常导航使用本入口与项目／学习设计的新路径。
8. 针对性简历篇幅以 HTML 导出后的 A4 PDF 为准：目标约 1.5 页，最多 2 页。优先保证阅读字号、行距和项目分页，再决定内容取舍，不按字数或压缩比例单独判定长度。
9. 每份 Markdown 维护正文，HTML 和 PDF 为同步产物。D2/D3/F/G 的相邻经历不代表已实施完整集群、训练数据或云成本管理平台；E2 的文档能力不扩展为公开演讲或生态推广成果。后续新增经历先补事实来源，再修改对应版本。
