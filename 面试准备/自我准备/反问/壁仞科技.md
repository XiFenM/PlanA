## 一、最值得问的 8 个问题

**1\. 这个岗位的实际开发边界是什么？**

“想了解一下，目前团队在 vLLM、SGLang 等推理框架上的工作，是只是围绕壁仞 GPU 进行后端适配，还是也会深入到框架内部，比如调度器、KV Cache 管理、执行引擎这些模块做架构级优化？”

**2\. 当前推理性能优化的主要瓶颈在哪里？**

“目前在实际模型部署中，团队遇到的主要性能瓶颈通常集中在哪些方面？比如 GPU 算子性能、CPU 调度开销、Host-Device 数据传输、KV Cache 管理，或者多卡通信？团队现在优先解决的是哪一类问题？”

3\. GPU 软件栈的成熟度，以及软硬件协同方式如何？

“因为推理框架的优化比较依赖底层 GPU 软件栈，我也比较好奇，目前团队在 Profiling、算子开发和性能分析方面有哪些工具支持？如果发现瓶颈涉及 Runtime、编译器或者硬件能力，框架团队通常怎样与其他团队协作？”

4\. 分布式推理方面有哪些技术规划？

“JD 中提到了 GPU 通信和并行策略优化。想了解目前团队主要关注 TP、PP、EP 这些模型并行方式，还是也已经在推进 Prefill-Decode 分离、多机推理或者跨节点 KV Cache 传输等方向？”

5\. 对量化和算子融合的优化深入到什么程度？

“JD 里提到量化压缩和算子融合，我想了解团队目前主要支持哪些低精度格式，比如 FP8、INT8、FP4？这些优化更多是在框架层选择算子和执行策略，还是也需要针对 GPU 的计算特性开发或优化底层 Kernel？”

6\. 团队如何维护与开源推理框架的关系？

“对于 vLLM、SGLang 这些迭代非常快的开源项目，团队目前采用的是独立 Fork 维护，还是通过插件或 Backend 接口尽量跟随上游？如果开发了通用的优化，是否有机会向上游提交贡献？”

7\. 当前团队最关注哪些模型和实际业务场景？

“目前团队主要针对哪些类型的大模型和业务场景做推理优化？比如 Dense、MoE 或多模态模型，以及在线低延迟服务和离线高吞吐场景。在衡量优化效果时，更关注吞吐量、TTFT、TPOT，还是部署成本？”

**8\. 入职后的工作重点和预期是什么？**

“如果有机会加入团队，您希望这个岗位的人在前三到六个月重点解决什么问题？对于一名表现优秀的工程师，团队最看重的是性能优化成果、框架功能交付，还是某个模块的独立负责能力？”
