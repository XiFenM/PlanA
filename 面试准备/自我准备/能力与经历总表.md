### 3.1 GLM-5.3-Flash：模型适配、缓存与性能

- **当前状态**：文本发布范围已完成，由云服务团队生产上线；不再使用索引旧版的“进行中／端到端精度待补”。
- **本人职责**：既有 vLLM 插件内的模型接入、权重映射、混合 KV cache／状态池、Graph 边界、插件性能与正确性排障、验收及回归。融合 Kernel 由算子团队提供，生产部署与 Runtime／驱动归属分别保留。
- **配置与有界结果**：8 卡、TP8、AWQ 4-bit 权重／BF16 激活。修正混合 KV cache 的容量核算与页分配后，34 层 KDA 状态缓存全部分配成功。短 prompt 下 prefill／decode 单步 Host 开销约 179/120 s→5.7/2.6 s。发布回归记录为 161 项通过、10 个 subtests 通过。
- **最终性能记录**：单请求、输入／输出各 128 token、Graph 与 replay cache 开启、预热 0 次、正式 3 次平均：输出 17.12 tokens/s，TTFT p50 243.89 ms，TPOT p50 58.39 ms/token。Host 单步耗时和服务指标是不同测量对象，不能混算提升倍数。
- **精度证据**：云服务团队反馈 OpenCompass 的单轮 AIME26 30/30，与同模型 8 卡 H100 参考结果相同；这不是逐 Token／logits 对齐证明。
- **边界**：MTP、多模态、FP8、V2 runner 等不在本次文本发布范围。本人不掌握首次上线日期与业务场景，不将这两项重新当作必须补答的已知事实。模型／量化 revision、发布标识及评测配置细项仍可补录。
- **来源**：[项目档案](projects/GLM5-3-flash-project.md)。档案早期引用的独立 summary 文件未随本地目录提供；不能伪造该来源，本表使用档案中已有的明确补充与结果。

### 3.2 vLLM V1 异步 H2D：低概率精度异常修复

- **当前状态**：已定位并修复，在现场请求集范围完成回归，不再沿用早期总结中的“根因闭环中”。
- **本人职责**：通过请求重放、阻塞／异步对照与数值分叉定位，识别 CPU Padding → H2D 提交 → 设备完成 → 消费之间的依赖缺口；在框架／后端层补齐异步标记与等待，复用既有 Runtime 能力，Runtime 无需修改。

- **本人职责**：padded pinned 输出、对 compat／layout 算子的框架侧调用、异步 DMA 提交、设备与 Host 分配生命周期保护、开关与回退策略，以及实际 vLLM 插件 D2H 点位和调度依赖分析。compat／layout Kernel 由算子团队实现；生产接入与生产验收属于其他团队。
- **正确性与生命周期**：目标构建 A/B/C 回归、补充测试和微基准无失败；同步路径跳过不适用的 deferred-event 断言。A/B 设备与 Host 生命周期压力测试各 32 轮通过。
