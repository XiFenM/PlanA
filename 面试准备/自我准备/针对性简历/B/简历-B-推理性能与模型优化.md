## 代表项目

### GLM-5.3-Flash 推理性能与缓存容量优化

负责模型在既有 vLLM 插件中的接入及插件侧优化，交付 8 卡 TP8、AWQ 4-bit 权重／BF16 激活的文本推理版本，由云服务团队生产上线。

- 通过框架 Profile 和隔离微基准，定位非连续状态页引发的 Host 逐元素搬运，将卷积与递推状态拆为连续池。同一短 prompt 的插桩对照中，**decode 单步 Host 耗时由约 120 s 降至 2.6 s**。
- 修正混合缓存分组、页容量核算及 Padding，解决启动 OOM；相同部署配置与显存预算下，**KV cache 容量由 45,409 提升至 148,762 tokens**。
- 针对 Host 下发与数据往返开销，合并 metadata H2D、复用持久 buffer、减少阻塞 D2H，并接入算子团队的融合实现；完成 decode Graph 的 metadata 与补齐适配，插件发布定向回归 **161 项通过**。

### 多模态视觉 Encoder 的 Conv3D 布局优化

- 从视频输入 OOM 追踪到 Conv3D 通道末置处理：小通道在大量空间位置重复补齐，造成临时存储膨胀。通过真实 shape 单例与显存变化分析定位问题，负责模型侧调用重构及初始化权重布局调整。
- 保留二维展平输入和权重，向专用 Conv3D 传递原始维度信息，与算子团队共同完成接口和计算路径调整；专用算子由算子同事实现，联合方案消除了已观察到的 OOM。
- 在 **Qwen2.5-VL-32B 的 10 个图片测例**中，单请求平均 TTFT 从分钟级降至 **5 秒以内**，模型输出 Token 与 CPU Conv3D 路径一致；该结果限定于图片测试组，不外推视频模型级验证。

### ECG 多模态模型部署与权重预排布

- 负责基于 Transformers 的客户模型部署与性能优化。通过 Profile 分析 Host 准备、小 shape 计算及矩阵乘开销，调整执行路径、接入融合算子，并以 Roofline 初步估算辅助判断权重访存瓶颈。
