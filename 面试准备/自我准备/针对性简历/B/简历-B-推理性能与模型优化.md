## 代表项目

### GLM-5.3-Flash 混合缓存适配与推理性能优化

负责模型在既有 vLLM 插件中的接入及插件侧优化，交付单机 8 卡 TP8、AWQ 4-bit 权重／BF16 激活的文本推理版本，由云服务团队生产上线。

- 通过 Profile 和隔离微基准定位非连续状态页触发的 Host 逐元素搬运，将 KDA 卷积与递推状态拆为两个连续池。适配初期，同一短 prompt 的插桩对照中，**decode 单步 Host 耗时降低约 97.9%**。
- 按 KDA 逐层分配的方式修正混合 KV cache 容量核算，移除多余的页尾填充，解决模型启动时的 OOM。
- 合并元数据 H2D 拷贝、复用持久缓冲区并消除阻塞读回，配合算子团队的融合实现减少 Kernel 下发。按 decode Graph 的输入尺寸补齐序列边界和状态槽。
- 发布后接入模型自带的 MTP 层，将候选 token 的生成与校验接入 decode Graph。KDA 按接受长度提交状态，KPool 回滚试写的缓存行，仅重放已接受 token 的更新。
- 在分块 prefill 中直接导出 KDA 卷积与递推状态快照，省去为保存前缀而拆段执行、回传和拼接的开销。将异构缓存拆成独立块池，按组计算请求需要的块数并分配。

### 多模态视觉 Encoder 的 Conv3D 布局优化

- 从视频输入 OOM 追踪到 Conv3D 通道末置处理：小通道在大量空间位置重复补齐，造成临时存储膨胀。通过真实 shape 单例与显存变化分析定位问题，负责模型侧调用重构及初始化权重布局调整。
- 保留二维展平输入和权重，向专用 Conv3D 传递原始维度信息，与算子团队共同完成接口和计算路径调整；专用算子由算子同事实现，联合方案消除了已观察到的 OOM。
- 在 **Qwen2.5-VL-32B 的 10 个图片测例**中，单请求平均 TTFT 从分钟级降至 **5 秒以内**，模型输出 Token 与 CPU Conv3D 路径一致；该结果限定于图片测试组，不外推视频模型级验证。

### ECG 多模态模型部署与权重预排布

- 负责基于 Transformers 的客户模型部署与性能优化。通过 Profile 分析 Host 准备、小 shape 计算及矩阵乘开销，调整执行路径、接入融合算子，并以 Roofline 初步估算辅助判断权重访存瓶颈。
- 在 PyTorch 框架侧实现 Tensor 扩展，于加载阶段完成静态权重的 blocked Col-major 预排布，供 prefill／decode 复用；同芯片新旧布局对照中，MatMul 与模型 logits 逐元素数值相等，输出 Token 一致。
- 联合优化后，单请求端到端时延从 **30–40 s 降至 20 s 以内**，达到客户验收目标。前后均取 **10 次平均**，包含图像预处理及完整输出，平均生成约 700–800 token；整体收益包含 Host、小 shape、融合与布局改动。
