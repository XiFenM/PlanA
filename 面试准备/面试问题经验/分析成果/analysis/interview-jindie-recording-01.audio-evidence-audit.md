## 1. 证据等级与媒体事实

本文件区分三类证据：A 为本地工具直接验证的文件与媒体事实；B 为单模型对音频的内容概述，尚需原音频核实；C 为含混术语、数字、角色边界或底稿未充分展开的内容。技术知识的正确性可以借官方来源核查，但它不能反向证明某句话确实出现在录音中。

A级事实：原件 23,843,226 bytes，时长 2773.909333 秒，一条 AAC-LC 48 kHz 单声道音轨，无视频。源 SHA-256 为 `3c8c3c36d31593f579b0d89186aa932331ccee3ea49040997423b4cdddb9af24`；处理后原件哈希一致。双遍动态响度归一化、16 kHz 单声道 MP3 副本为 16,643,925 bytes，时长 2773.944 秒；整段解码通过。

源综合响度 −24.37 LUFS，真峰值 +0.87 dBTP；编码后副本实测 −18.49 LUFS、−1.16 dBTP，LRA 8.20 LU。滤波器编码前输出 −18.03 LUFS、−2.00 dBTP，不应当作最终 MP3 的实测值。超过 0 dBTP 的源瞬态不等于已经证明存在可听见的削波。响度处理不能恢复录音丢失的信息，也不能证明每句话可懂。

原始源流起点约 0.044 秒，MP3 起点约 0.069 秒，容器总时长相差约 35 ms。模型秒级锚点未做样本对齐，不能用这些数字宣称逐字级定位准确。

## 3. 必须收窄或纠正的底稿表述

### 3.1 个人姓名、听感和主观描述

不在面向阅读的报告中重复模型识别的个人姓名；它与本次技术复盘无关且没有独立核验。底稿所称“信噪比较高”“气氛轻松”“未施压”等不作为本地实测或面试官心理判断。回听 Q7 的目的应是确认问题和回答范围，不是根据语调、停顿推定能力或人格。

### 3.2 Conv3D：混合了 byte、元素与整体内存倍率

Q2 的主旨可以保留：小通道输入在某种物理布局与对齐约束下导致严重填充浪费，候选人从模型侧调整布局，并与算子团队协作。

但 `512 bytes`、`256`、`C=3`、`1100 多 → 1280` 不是已经统一口径的一组数字。举例说明：若元素为 2 bytes，3 个元素占 6 bytes，每行补到 512 bytes，则该行约放大 `512/6≈85.3` 倍；若是 256 个元素，则也为 `256/3≈85.3` 倍。此算例仅用于展示单位的重要性，不是在还原现场 shape。仅凭这些数字不能证明“整体显存扩大数百倍”。

物理布局变换还必须说明卷积索引映射、kernel 输入约定、padding 是否被计算忽略，以及是否发生真实数据拷贝。任意合并维度不是卷积等价性证明。模型“技术成立”的结论应改为“机制可能合理，具体实现与收益未验证”。型号、TP=2、2×64GB 和各模型参数规模暂为 C 级自述。

### 3.3 NZ：格式可类比，瓶颈不能由格式名直接证明

Ascend 文档确实将 NZ 描述为块间列优先、块内行优先，并给出了 padding、reshape、transpose 的转换关系。它支持 Q3 的布局类比，但不证明录音中自研芯片使用同一地址映射，也不证明收益一定来自 bank conflict 下降。[Ascend 数据格式说明](https://www.hiascend.com/document/detail/en/canncommercial/850/opdevg/Ascendcopdevg/atlas_ascendc_10_0099.html)

最终报告保留“小 batch、权重读取压力、加载时预排布”这条分析线，把“ECG”作为待回听专名。HBM 通道利用率、DMA 搬运粒度、片上 bank conflict、计算单元消费格式是不同因素，应通过计数器或受控实验区分。缺少 shape、dtype、带宽和时延数据时，不评价已达到峰值带宽。

### 3.4 异步拷贝：调试现象支持方向，尚未验证具体根因

Q4 有可复用的排障线索：高负载下偶发输出异常；逐层或逐步比对；增加打印/同步后复现概率改变；最终把问题归因于 Host 预处理和设备异步拷贝的完成顺序。

这些线索支持优先检查竞态、生命周期与同步边界，但不是某一种实现根因的充分证明。底稿的“未知项：无”应撤回。需要补：Host 任务由谁执行、什么时候入队、Event 代表哪一阶段完成、缓冲区何时复用，以及修复前后同负载下的复现率。

CUDA 文档说明同流操作按入队顺序执行、stream synchronize 等待相应流中的工作；据此可理解为什么“等待设备流”不能自动证明尚未建立依赖的 Host 任务已完成。这里是通用机制类比，不能把 CUDA API 当作该自研 Runtime 的真实实现。[CUDA 异步执行](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)

底稿建议回答加入了“Host 锁页内存双缓冲机制彻底消除竞争”，该实现不在 Q4 的材料证据中，最终报告删除。也不能从目前未附简历的材料认定简历全部存在偏差，只能记录底稿所述的这一处现场术语修正。

### 3.5 PrivateUse1：区分机制、辅助命名与工程覆盖

底稿把 PrivateUse1 说成 PyTorch 2.0+ 才引入并不准确；官方教程说明 2.0 以前就有保留 dispatch key，2.1 加强了相关集成支持。设备模块注册或改名不等于完成后端接入。标准接入路径包括算子注册、必要的 fallback、设备/流/Event 的 guard 等；具体覆盖取决于后端范围。[PyTorch PrivateUse1 教程](https://docs.pytorch.org/tutorials/advanced/privateuseone.html)

底稿建议中的 `c10::RegisterDeviceKey` 未在本地固定的 PyTorch `c10` 与 `aten/src/ATen` 源码搜索到，不把它作为已核验学习 API。算子注册应从官方实际使用的 `TORCH_LIBRARY_IMPL` 路径学习；这不意味着所有示例在用户当前旧版本上无需适配。

Q7–Q9 的合理结论是“本轮底稿未展示这些机制的清晰解释；插件化项目完成范围还不明确”，而不是“完全没有框架能力”。Q1–Q4、Q10 的框架层工作证据仍应保留。

### 3.6 Tensor 与 Allocator：不要用不准确示范回答补课

本地固定 PyTorch commit：`460948b96a67002b7257ac4f3d6a192f70d61d27`。源码显示通常的稠密 Tensor 路径中，TensorImpl 保存 Storage、sizes/strides 和 storage offset；StorageImpl 持有 DataPtr；Allocator 的基础虚接口是返回 DataPtr 的 `allocate(size_t)`。`raw_allocate` 是有前提的辅助接口，不能概括成所有 Tensor 都通过它获得“物理地址”。DataPtr 也不等于用户可以直接解引用的设备物理地址。

可复查源码：[TensorImpl.h](https://github.com/pytorch/pytorch/blob/460948b96a67002b7257ac4f3d6a192f70d61d27/c10/core/TensorImpl.h)、[StorageImpl.h](https://github.com/pytorch/pytorch/blob/460948b96a67002b7257ac4f3d6a192f70d61d27/c10/core/StorageImpl.h)、[Allocator.h](https://github.com/pytorch/pytorch/blob/460948b96a67002b7257ac4f3d6a192f70d61d27/c10/core/Allocator.h)。该链路是学习用的常见情况，不涵盖 meta、稀疏等全部 Tensor 表示。

面试官“描述符”具体指 TensorImpl 还是后端 descriptor 也仍需确认，不应把一个含混的提问替换为助手自拟的完整考题。

### 3.7 AI Coding：底稿内部存在评价收窄过度

总览写成候选人“仅依赖端到端跑通”，但 Q15 又列出规划、单元测试、集成测试与较粗粒度的代码检查。最终报告采用后一种较完整的转述，并明确单元测试的实际范围仍未知。提到测试不足以证明采用了严格的 TDD。

应指出的缺口是：没有展示测试 oracle 是否独立于生成实现、如何测试未覆盖的内存/流语义、谁审核核心改动、是否能主动构造反例。这比泛化地批评使用 AI 工具有帮助，也不否定已经进行的规划和测试。

### 3.8 KV Cache、Chunked Prefill 与 FlashAttention

- Q11 对因果解码下历史 K/V 可复用的主旨可以保留。复杂度应分清上下文长度 n、head dimension d、单步解码与全序列。标准 dense attention 在已有 cache 的单步仍需读取/处理历史 K/V，attention 工作量随 n 增长；不能把底稿“投影从 O(N²) 降到 O(N)”直接当作严谨描述。
- Q5 的核心是限制长 prefill 对 decode 的阻塞；不能承诺所有延迟、吞吐一起改善。vLLM 文档明确讨论 token budget 对 ITL 与 TTFT 的权衡，参数还需按模型、硬件和负载测量。[vLLM Chunked Prefill 调优](https://docs.vllm.ai/en/stable/configuration/optimization/#performance-tuning-with-chunked-prefill)
- Q12 对 tiling、online softmax、避免完整 attention 矩阵物化的解释方向正确。底稿“HBM 访问复杂度从 O(N²) 降到 O(N)”过度简化。原论文给出的 HBM 访问复杂度依赖序列长度 N、head dimension d、SRAM 容量 M，为 Θ(N²d²/M)，并带相应容量假设；dense attention 的算术复杂度没有因此变成线性。这一错误来自模型的技术解释，现有材料不足以把它归为候选人口误。[FlashAttention 原论文，定理 2](https://arxiv.org/html/2205.14135v2#S3.SS2)

### 3.9 其余需要保留的未知项

Q6 的多模态流程具有模型依赖，不能把所有架构归为同一种 LLaVA/Qwen-VL 流程；模型版本、patch size、视觉 token 数、位置编码和多轮图像复用仍未核实。Q10 的具体数值误差指标来自模型展开，不能保证候选人逐项提及。Q14 的硬件建议是对本人接触负载的观察，不是已经验证的通用芯片设计结论。Q16 的客户支持占比为自述。Q17 的技术栈与工作范围来自面试官口述，不能替代正式 JD。
