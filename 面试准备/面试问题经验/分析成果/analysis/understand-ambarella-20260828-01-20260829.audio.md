### 3. AI 框架研发定位与 vLLM 适配难点（KV Cache 对齐）

### 5. 算子融合案例：Fused RoPE 与片外访存优化
- **问题/追问**（`约 11:10 - 13:10`）：简历中提到的 Fused RoPE 是什么东西？为什么要做？
- **候选人回答思路**：
  - 背景：某些视觉语言模型（VLM）中 RoPE 的旋转位置编码维度排布特殊（如奇偶交错索引排布）。
  - 瓶颈：直接用原生索引操作（Index/Slice）会导致频繁调用底层 Index 算子，在 TPU 上引起大量片外 HBM 读写（Load/Store），由于 TPU 的 Index 算子较慢，造成极大性能损耗。
  - 方案：将交错索引、Reshape 与前后关联算子（如 MatMul/Attention）融合为单个 Fused RoPE 算子，所有操作在片上 SRAM/寄存器完成，避免回写 HBM。
- **面试官提示**：无。
- **直接证据**：明确指出“索引算子在硬件上慢”、“频繁进出 HBM”是融合的核心动力。
- **可取之处**：深刻理解算子融合减少 Memory-Bound 的本质原理。
- **缺失/风险**：未提及该融合算子是由候选人独立编写 C/Kernel 代码，还是由算子团队编写、候选人在框架层做调用封装（后续问题澄清了分工）。
- **置信度**：高。

### 7. 架构分层分工与 Conv3D 显存优化案例
- **问题/追问**（`约 15:05 - 19:10`）：
  - 架构分层体系是怎样的？你主要在哪一层？
  - 简历中的 Conv3D 优化是怎么做的？
- **候选人回答思路**：
  - 分层：硬件层 -> 算子层 (C/自研编译器) -> PyTorch 适配层 -> 框架层 (vLLM / 训练框架) -> 应用层。候选人主要负责 **框架层（PyTorch/vLLM 交互与调度）**。
  - Conv3D 案例：在 Qwen-VL（视觉编码器）中，输入通常为 3 通道（RGB）。由于硬件要求内存按 128 对齐，若通道维度排在末尾（Channel-last），通道数 3 会被强制 Pad 到 128，导致显存占用暴增数十倍。
  - 优化解法：通过 Reshape/Transpose 将空间或 Batch 维度与 Channel 维度拼成大维度（如 200~300），规避小维度 Padding 带来的内存膨胀。

- **直接证据**：准确指出专用芯片内存对齐机制在面对小 Channel（3通道）卷积时的 Padding 显存爆炸问题。
- **可取之处**：软硬件结合意识强，能用框架层 Tensor 变换绕过底层硬件缺陷。
- **缺失/风险**：明确了自己不直接写底层算子 Kernel，主要做上层图与调度。

### 10. 量化优化：AWQ (W4A16) 机制与访存收益
- **问题/追问**（`约 23:45 - 25:30`）：
  - AWQ 量化是怎么做的？

- **候选人回答思路**：
  - 格式：W4A16（权重量化为 INT4 存储，激活保持 16 位，计算时实时反量化成 16 位浮点计算）。

- **面试官提示**：无。
- **直接证据**：准确给出了 AWQ 的权重量化机制及 Memory-Bound 下反量化提速的理论解释。
- **可取之处**：技术解释非常标准且具说服力，展现了优秀的性能分析功底。
- **缺失/风险**：无。
- **置信度**：高。

| :--- | :--- | :--- | :--- |
| **KV Cache 对齐与 Prefix Caching** | 自研芯片要求 256 Block 强对齐，导致通用前缀缓存命中困难，在框架层做细粒度拆分。 | vLLM 默认块大小为 16 或 32，小 Block 适应性强；专用 NPU 常因 SIMD/SRAM 向量宽度限制要求大对齐。 | **真实有效**。体现了深度框架定制经验。 |
| **AWQ (W4A16) 提速机制** | 权重 INT4，计算转 BF16，解决 Memory Bound，实测提速 20-30%。 | 准确。LLM Decode 阶段 Arithmetic Intensity 低，核心瓶颈在权重读取带宽。 | **理论与数据准确**。高质量回答。 |
| **DeepSeek-V3 规格与卡数** | DeepSeek-V3 约 671B，单卡 64GB，部署使用 32 张卡（4台机器×8卡）。 | DeepSeek-V3 总参数量为 671B（激活约 37B）。671B 若在 FP8/INT8 下权重约 671GB+，32卡×64GB=2048GB，容量足够容纳权重与 KV Cache。 | **数据匹配合理**。现场承认简历措辞夸大，但工程拓扑真实。 |
| **Conv3D 显存优化** | Qwen-VL 中 3 通道 Conv3D 因 128 对齐导致显存爆炸，通过维度拼接/Reshape 优化。 | 专用 NPU 常见 Channel-last 对齐机制（要求 $C \pmod{128} == 0$），$C=3$ 时 Padding 浪费率达 $125/128$。 | **软硬件协同理解深刻**。极具代表性的硬件缺陷绕行方案。 |
| **Transformer / Attention 架构** | 否认 Attention 内部包含 Conv/FFN，指出 FFN 为后续独立模块。 | 标准 Multi-Head Attention: $\text{Softmax}(QK^T/\sqrt{d})V$。FFN 为独立的 2 层 MLP。 | **概念完全正确**，成功纠正诱导性问题。 |
