## 2. 结论先行：主要考察方向、表现证据与最大改进机会

### 考察方向
1. **底层硬件与编译/运行架构理解**：自研芯片计算/存储单元抽象、内存层级（HBM/On-chip Buffer）、对齐要求及与 GPU 架构的映射对比。
2. **大模型分布式推理与通信机制**：DeepSeek 等大模型在多卡（TP/EP）环境下的通信算子（AllReduce, All-to-All, AllGather）调用链及机间/机内差异。
3. **性能瓶颈定位与算子协同优化**：Roofline 模型理解、MatMul 访存优化（Block-level Column Major）、Profiling 气泡与算子开销分析。
4. **工程排障与鲁棒性验证**：精度异常（Token 0/感叹号、乱码）、概率性并发 Bug（异步 Padding 与 Stream 同步不同步引发的数据竞争）的定位方法。
5. **现代工程工具流与职业动机**：Coding Agent（AI 辅助编程）落地与防幻觉机制、换槽动机与职业定位。

### 表现证据
- **强项**：具备扎实的一线国产芯片适配与调试经验，能清晰讲出具体的工程踩坑实例（如异步 Padding 导致未完成对齐数据被提前拷入 Device 的 Race Condition、1024 字节硬件强制对齐带来的 Bank Conflict 等）。
- **弱项**：在理论推演（如纯理论 Roofline 算力上限测算）和部分分布式切分细节（如 MOE 层的 FFN 与 TP 混合切分时的通信行为）上，存在概念混淆或临场反应迟疑；部分回答依赖实际 Profile 观测结果而非自顶向下的架构推导。

### 最大改进机会
1. **理论推导的结构化表达**：提升由“架构公式/硬件规格”直接推导“理论极限”的能力，减少过度依赖“Profile 出来再看”的答题习惯。
2. **分布式切分原理精准化**：清晰厘清 TP（张量并行）与 EP（专家并行）在 MOE 架构下各个投影层与 Router 处的通信算子触发逻辑，避免被追问时出现表达反复。

### Q8. 具体算子优化案例：Block-level Column-Major MatMul
- **问题/追问**：`约 23:05` “还做过哪些对模型的优化？”
- **候选人回答思路**：
  - 痛点：大模型中 MatMul 占比高，硬件脉动阵列计算速度快，但片外到片上的搬运访存较慢；传统按行（Row-Major）分块读取时，跨行跳跃读取（Strided Access）容易导致不同行落在相同的 Bank/维度上，产生访存冲突（Bank Conflict）或未对齐惩罚。
  - 方案：设计 Block-level Column-Major 的内存重排优化。在权重加载/预处理阶段，将权重以 1024 字节 Block 为粒度，重排为列主序存储。
  - 收益：运行时可全带宽连续读取所有 Bank，提升访存效率，消除运行时的 Layout 转换开销。
- **面试官提示**：无。
- **直接证据**：详述了 1024 Bytes 硬件粒度、分块跳步读取缺陷、权重离线预转置排布的完整闭环。
- **可取之处**：具备极强的硬件协同设计意识，清晰解释了“离线预处理重排代替在线动态开销”的经典优化范式。
- **缺失/风险**：面试官追问是否修改算子时，候选人澄清主要参与方案讨论与协同优化，未完全独立编写底层汇编/核心算子代码。
- **置信度**：高。

### Q12. 概率性/并发 Bug（随机报错）定位案例
- **问题/追问**：`约 37:35` “有没有遇到过随机出错、单拎出来对但整网跑出错的问题？”
- **候选人回答思路**：
  - 实际故障案例：在客户现场交付时，同一请求输入，单次跑正常，但大批量并发时出现概率性乱码（统计测试 125 次出现约 30 次异常）。
  - 定位手段：
    1. 开启调试打印，将并发/异步调用强行改为同步执行，逐步下发算子。
    2. 改为同步后，报错消失，判定为异步流水线或多线程 Race Condition。
  - 根本原因（Root Cause）：
    - 专用芯片在 Input Prepare 阶段需要进行 1024 字节的强制 Padding。
    - 流程设计为：CPU 内存 Padding -> 异步拷贝到 Device（H2D）。
    - 故障点在于 CPU 侧的 Padding 操作本身也是异步的，且未挂载在 Device Stream 的同步控制体系中，导致数据尚未 Padding 完毕就被提前发往硬件执行，造成脏数据输入。
- **面试官提示**：无。
- **直接证据**：完整的“复现概率（125 次错 30 次）-> 同步二分定位 -> 根因分析（CPU 异步 Padding 乱序与 Device Stream 缺失同步）”工程案例。
- **可取之处**：极高价值的实战案例，充分体现候选人解决复杂异步并发/系统级 Race Condition 的实操能力。
- **置信度**：极高。

## 6. 面试官的关注信号与追问模式

1. **追问深度的渐进性（Probe for Depth）**：
   - 当候选人提到 DeepSeek 适配时，面试官不满足于宏观概括，连续追问：*“哪一代？多少卡？模型结构怎样？通信算子有哪些？MOE 层和 FFN 层通信是否冲突？”*
   - 面试官非常关注候选人是“实际动手调优过”还是“仅仅跑过开源脚本”。
2. **架构类比考核（Cross-platform Mapping）**：
   - 关注候选人能否将自研小众芯片的专用概念（2 大核、Vector/Scalar Buffer）精准映射到行业标准（NVIDIA GPU Shared Memory/SM 体系），考察知识迁移能力。
3. **理论与工程结合度**：
   - 询问 Roofline 模型时，面试官试图引导候选人给出定量的数学评估逻辑，见候选人侧重工程 Profile 后适时切换，展现出对实际工程落地能力的认可，但理论维度扣分。
4. **对真实排障细节的浓厚兴趣**：
   - 针对随机 Bug（Flaky Bug）主动探寻候选人的第一反应与排查路径，对候选人给出的异步 Padding 案例给予了明确正向反馈（“OK”）。

## 8. 面向下一轮准备的行动建议（P0 / P1 / P2）

### P0：极高优先级（核心技术短板加固）
1. **重构分布式并行通信推导能力**：
   - 彻底理清并能脱稿白板推导：在标准 Megatron / vLLM 架构下，**TP（Tensor Parallelism）**在 Attention（QKV 与 O 投影）和 MLP（Gate/Up 与 Down 投影）中的 AllReduce / AllGather 插入点；
   - 针对 **MOE 架构（如 DeepSeek）**，清晰阐明在 TP、EP、TP+EP 组合下，Router 之后 **Dispatch（All-to-All）**、Expert 计算、**Combine（All-to-All）** 以及残差连接的具体通信时序，避免在概念交叉追问时出现迟疑。
2. **强化 Roofline 理论算力推导话术**：
   - 准备好标准算子（如 MatMul $M, N, K$）的理论计算量公式（$2MNK$ FLOPs）与最小访存量公式（$2(MK + KN + MN)$ Bytes），计算计算强度（Arithmetic Intensity $I$），并推导其在特定芯片算力上限与带宽拐点下的理论耗时极限。将“工程排查法”与“理论推导法”结合表达。

### P1：高优先级（结合奕行技术栈对齐）
1. **针对性复习 SGLang 与 FlashInfer 机制**：
   - 面试官明确透露其技术栈涉及 **SGLang** 与 **类似 FlashInfer 的高性能算子库**。
   - 需准备：SGLang 的 RadixAttention 机制、多 Token 预测（MTP）支持，以及 FlashInfer 在非均匀长文本（Ragged Tensors）、Page KV Cache 上的算子级优化原理。

### P2：中优先级（表达与面试策略优化）
