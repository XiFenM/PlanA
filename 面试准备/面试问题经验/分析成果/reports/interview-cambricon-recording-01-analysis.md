## 项目案例：把处理思路补成可检查的证据

### 前缀缓存案例：先说清楚缓存了什么

Q2 的价值在于把物理访问约束和逻辑缓存粒度联系起来。下次展开时，先区分 token 数、元素数与 byte，再用同一组请求说明改造前后哪些块可命中。

例如，**作为机制示例而非现场实测**，block 为 256 token、两个请求前 300 token 相同且此前的完整块仍可用时，前 256 token 仍可能复用；不能只因剩余 44 token 未满块就说全部失效。更小逻辑块能否提高收益，要同时核对 hash 条件、映射、共享写入与回收。[vLLM Prefix Caching 设计](https://docs.vllm.ai/en/latest/design/prefix_caching/)

准备一张“请求 token → 逻辑块 → 物理块和 offset”的图，配一个相同前缀、一个中间 token 改变、一个取消后回收的例子。讲明你实际改了哪个模块、算子侧如何配合、命中率与 TTFT 怎样测量。没有测过的指标保留为空，不用理论收益替代真实结果。

### Conv3D 案例：用一张 shape 与字节数表消除歧义

Q3、Q4 已有“视觉入口、小通道、硬件填充、OOM、跨团队处理”的叙事，但数值混乱会削弱解释。下一次先列原 shape、逻辑轴顺序、物理 layout、dtype、对齐规则、填充后 shape、所需 bytes，再说明重排如何保持输入与权重的对应关系。

底稿中的 `14×14×2` 是 392，若再乘三通道才是 1176；256 bytes 与 256 个 FP16 元素也不同。固定版本官方实现确实可见三通道时空 patch 的 Conv3d，但它只提供背景，不能替代你的部署配置。[Qwen2.5-VL patch embedding 参考源码](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py#L68)

最后给出小输入数值等价性检查、峰值显存和视觉阶段耗时。继续说明本人负责模型/框架修改、定位与协作中的哪部分，避免把整个底层算子实现一并归到自己名下。

### 异步异常案例：画出完成顺序，再说明修复

Q5 应整理成“复现条件 → 缩小范围 → 哪段数据尚未就绪 → 建立什么完成依赖 → 如何复测”。重点不是增加同步术语，而是说清谁写哪个缓冲区、谁何时读取、何时可以复用或释放。

建议的示意路径是：`Host 原数据 → Padding 后缓冲区 → H2D → Device 使用`。这只是待你根据真实代码补齐的分析框架。DeviceGuard 的设备选择职责不能替代拷贝完成；CPU fence 也不能单独解决所有跨线程或设备完成条件。[PyTorch DeviceGuard](https://github.com/pytorch/pytorch/blob/main/c10/core/DeviceGuard.h)、[CUDA stream/event 语义参考](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html)

实际自研 Runtime 语义、修复代码和测量未提供，所以报告不采用底稿中已经彻底消除竞争的判断。固定 seed、单并发能通过、高并发会变化，都应作为需要进一步验证的线索。

### Dispatcher 与通信后端：用一个调用把分层连接起来

Q6 的插件化动机比较具体；机制解释则建议从一次 `aten::add` 或项目中真实算子出发，说明输入 key set、线程局部状态、注册的后端实现以及必要的 redispatch。再区分进入后端之后的 dtype/shape 选择。这样可以把 Autograd、Device 等概念与源码位置对应起来。[PyTorch Dispatcher 后端扩展](https://docs.pytorch.org/tutorials/advanced/extend_dispatcher.html)、[key 提取逻辑](https://github.com/pytorch/pytorch/blob/main/aten/src/ATen/core/dispatch/DispatchKeyExtractor.h)

Q7 则应展示在特定设备和工作负载下，为什么独立通信流的成本超过收益。单流是否更快要看测量；通信 API 的完成、等待、缓冲区有效期与错误处理仍需保持正确。当前官方扩展示例区分了 Backend 和 Work，阅读时应同时对照你实际维护的版本。[PyTorch 通信后端扩展](https://docs.pytorch.org/tutorials/intermediate/process_group_cpp_extension_tutorial.html)

| 主题                | 建议的回答结构                                                                                  | 避免的简化                                                                        |

这些问题可以从实际框架工作中寻找对应物：对象与缓冲区的生命周期、导入时的替换、后台 worker 间传输、异步任务何时完成。用小程序验证后再组织口述，会比只增加术语更容易应对追问。
